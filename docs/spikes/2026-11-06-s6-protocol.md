# Spike S6: can someone else implement the protocol?

**Story:** SPK-019, with the phase 0 protocol stories PRO-001, PRO-002, PRO-003, PRO-091 and PRO-092. **Date:** 2026-11-06. **Status:** done. The `core` smoke suite has run against the reference service since 2026-11-15 (section 7). Brought up to date with the spec revision of 2026-11-06 and with the protocol findings of spike S12 (section 1.1).

## 1. Answer

Partly.

- **The real-time plane and the core ports can be implemented from the artifacts.** A second implementation of the ports, `backend-mock`, passes 36 contract cases and 5 smoke scenarios that use only the port typings and a harness interface. The definitions were enough to write it; where they were not, the gap is listed below and the choice made is recorded as a decision.
- **The control plane cannot yet be implemented without guessing.** 05 §6.2 names 50 routes with their methods, but almost none of their bodies. No HTTP status is given for any error code, nor any success status except `202` for exports. The OpenAPI document is complete as a list of routes, parameters, conventions and credentials; most bodies in it are placeholders that say which gap they wait for.
- **The mock does not prove independence from the document semantics.** It runs the project's own authority (`Room` from `@docedit/authority`), as 05 §8.3 says of the local backend. It proves that the port contract and the wire shapes are sufficient around that authority.

The list of gaps in section 4 is the input for the spec: 103 found, of which 4 were resolved by the revision of the spec that landed while the spike ran, so 99 remain open. Ten of the open ones change wire behaviour that the conformance kit will pin (G14, G16, G20, G24, G27, G32, G44, G50, G101, G103) and should be settled before phase 1a.

### 1.1 What changed while the spike ran

- **The spec was revised at about 09:15** (all of 00 to 13 except 08), after the definitions were first written. The revision resolves G19 (`auth.ok` is now in the session table), G37 (a base older than a snapshot commit gets `stale_base` with action `rebase`), G39 (a spent CPU budget in a room is `rate_limited`) and G40 (`read_only` is checked before P6). The definitions follow the revision: D05 is confirmed by it, D09 (action `reload`) is withdrawn, and the mock and the contract suite now expect action `rebase`. The resolved gaps keep their identifiers, and the consistency check refuses any element that still points at a resolved gap or a withdrawn decision.
- **Spike S12 (read restrictions, ADR 0019, proposed)** reported four protocol changes. They are folded in as far as the artifacts can carry them without deciding ADR 0019: `ch.opened` and `resume` gain an optional opaque `view` (D28); the docs of `sync.ack` and `sync.commit` say that a read-restricted reader's acknowledgement is always rebased and that a commit may reach it with no steps; `ch.closed` says that a change of access closes the channel with `unavailable`. Three interactions with 05 are new gaps: the joining flow of 05 §5.2 cannot stream under projections because REST content carries no token (G101), the empty class steps and filtered scopes are not in 05 (G102), and a change of access is indistinguishable from a room that moved (G103). The mock serves the full view, so it sets no token and passes one through only if the room gives it; the contract suite echoes `opened.view` whenever it resumes after a channel.
- **The control plane of the reference service (PLAN-1a packet A2, later the same day)** could not be built from placeholders, so its bodies and statuses were defined in the definition and recorded as decisions D60 to D74, proposals like the others. Fourteen gaps are marked resolved by them (G03, G04, G05, G07, G09, G50, G54, G56, G60, G61, G64, G65, G73, G97); D61 overtakes D13. G10, G55, G80 and G101 are answered in part and stay open. Packet A1 records its decisions as D40 to D59.

## 5. Decisions taken

These are proposals, not settled design: each answers the gap it names, so that the artifacts and the mock could be built. The main session and the second review (SPK-027) decide whether they stand; a change to one is a change to the definition data and a regeneration. A decision marked confirmed says what a revision of the spec now says; one marked withdrawn was overtaken by a revision, and the artifacts follow the spec.

An identifier the caller may not read, or that is not ready, is left out rather than refused, so the answer does not reveal whether an asset exists elsewhere in the tenant. `url` is a signed URL valid until `expiresAt`. The order of the entries is not defined. The upload descriptor, the responses of `complete` and the URL lifetime remain open under G72. Proposed by the stabiliser of packages/protocol to match the reference service (services/document-service); the owner confirms or changes it. |

Two choices belong to the mock and the contract suite rather than to the protocol:

- The mock treats the content a document is created with as the content at `seq` 0, under grants revision 0, so creation records no control commit (G97). The contract suite does not depend on it.
- The harness's token source mints a new token on every call, as a host's `getToken` does. A revocation therefore closes the user's channels and a reconnect succeeds with a newer token; that the old token is refused is a wire-level check for the kit (PRO-016), not a port contract.

## 6. Where the authority's message shapes differ from 05

The room (`packages/authority/src/room/room.ts`, `types.ts`) uses DEP names in a compact in-process form. `backend-mock` translates them (`packages/backend-mock/src/translate.ts`, `document.ts`); the main session decides which side changes.

| Message or behaviour | The room today | 05 (and the decisions above) | Bridged in the mock by |
|---|---|---|---|
| `sync.ack` time | `time`, Unix milliseconds | `serverTime`, RFC 3339 | formatting the time |
| `sync.commit` | one commit per message: `{ commit: StoredCommit }` | `commits`: an array in ascending `seq` | coalescing consecutive commits for one channel |
| Commit element | `user`, `session` (`system` for server commits), `time`; no `control`; internal members `scopes`, `revision`, `cdm`, `engine`, `retired`, `claimed` | `author: { user, session, agent }` with `session` null for server commits; `control`; `serverTime` (D10) | building the element; `control: { type: "grants", rev }` from `revision` |
| `sync.reject` | `reason`; no `rule`, no `retryAfterMs` | `message`, optional `rule` and `retryAfterMs` | renaming |
| Rejection scopes | per definition node: `defs:style_def/Normal` (07 §5.1) | one `defs` scope (05 §5.3; G41) | collapsing `defs:*` into `defs` |
| `ch.opened.catchUp` | `stream` or `reload` | also `page` | nothing (the room never pages) |
| `ch.opened.inflight` | `null` when not asked and on `reload`; `accepted` only for the caller's own commit | present exactly when `resume.inflight` was sent (D08); 05 does not say "own commit only" | answering from the service's log of stored commits, with the same own-commit rule |
| `ch.opened.content` | content inline on `reload` | content over REST (`GET …/content?seq=head`) | dropping it |
| `access` | `Access` with Sets and Maps, the grants `revision`, a server time `at`, `docRole` as a set of capabilities, `structureScopes`, `newRegion`, `fill: { roles, active, allowed }` | `{ rev, asOfSeq, docRole (a role name), caps, scopes, leases, fill, restrictions }` (05 §5.5; D11) | `toAccess()` |
| `rev` and `asOfSeq` | the grants revision; no seq | `rev` per connection, `asOfSeq` the seq whose regions are listed (D12) | a counter per channel; the control commit's or the head's seq |
| Region list for access | computed from the tentative document, which can include commits not yet stored | `asOfSeq` refers to commits the client can have | setting `asOfSeq` from stored commits only |
| `perm.changed` payload | `{ revision, access }` | the access object itself | unwrapping |
| `perm.changed` order | sent at once; the control commit is stored afterwards | the control commit first, then `perm.changed` with `asOfSeq` set to it (05 §5.9; PRO-033; D12) | holding `perm.changed` until its control commit is delivered |
| Region list changes | no `perm.changed` after a commit that adds or removes a region | 07 §4 recomputes access then (G46; D12) | recomputing access with the authority's `computeAccess` after such a commit |
| `sync.caughtUp` | `head` | `seq` | renaming |
| `ch.closed` | `code: "unavailable"` only | `code`, `reason`, optional `retryInMs` | adding a reason |
| `resume.inflight` | `string \| null` | an optional string (D08) | mapping absent to null |
| Snapshot commits | none: `kind` is `steps` or `control`; no `sync.reset`; no check for a base older than a snapshot | snapshot commits with `sync.reset`; a base older than one gets `stale_base` with action `rebase` (04 §3.2 as revised) | a new room per snapshot, external seq = room seq + offset; the base check in the service |
| View tokens | `ch.opened.view` and `Resume.view` exist in the types (S12); the room itself neither sets nor checks them, the projection gateway does | optional `view` on `ch.opened` and `resume` (ADR 0019, proposed; D28); not in 05 yet (G101) | passing a room's token through, and the client's to the room |
| Leases in access | `holder`, `expiresAt` in Unix milliseconds | `expiresAt` as RFC 3339 | formatting |
| Not in the room | `ch.rejected`, `event`, `sync.check`, presence, `auth.*`, `goaway` | — | the mock's service and backend (gateway duties, not authority duties) |

During the spike the room gained `RoomInit.initialRevision`. Before it, a room created under a grants revision other than 0 appended an unrequested control commit after its first write, which the mock first had to work around; the mock now passes the revision instead.

## 7. What is left

- **Run the smoke suite against the reference service.** The suite targets any implementation of the ports. It needs `backend-dep` (PRO-093 to PRO-095) and the service (BE-001) to exist; then the same `coreSmoke(factory, opts)` runs with a harness that calls the control plane with a service credential. **Done on 2026-11-15:** `packages/backend-dep/test/service.test.ts` starts `services/document-service` in process on a port the system chooses, with its in-memory parts, creates a tenant and a service credential, and runs the five scenarios through `backend-dep` over a real WebSocket and `fetch`. All five pass. Three of them had been listed as pending on 2026-11-06 for reasons in the service that no longer hold. The "unknown" half of the reconnect scenario needs a write to be held: the harness wraps the service's in-memory log so that `append` waits for the test, and nothing else is replaced. What this run does not show: the service on PostgreSQL (its own suites cover that storage), and a deployed service behind a proxy.
- **Settle the gaps** in the spec, starting with the ten listed in section 1, then regenerate (`pnpm --filter @docedit/protocol generate`). Decisions that are confirmed move from the decision register into the prose.
- **Decide ADR 0019 and write the view token into 05**, with an answer to G101: either `GET /documents/{id}/content` returns the `view`, or the full view is exempt from "a missing token forces a reload". Until then `view` is optional in the artifacts and no feature announces it.
- **Behavioural contract cases for the optional ports** other than presence (PRO-098, phase 1b): today they only check that each member exists, and they are skipped against the mock, which does not offer those ports.
- **PRO-117 scenarios.** `test/prose.test.ts` is a first version of the artifact half of PRO-117: it reads the tables of 05 §5 to §7 and 12 §10 and compares them with the definition both ways. The scenario half (every message, field and resource exercised by the kit) remains.
- **PRO-038.** The error registry in `src/definition/errors.ts` is a first version: every code with its surfaces, retry rule, client action and the close code inferred for fatal codes (D25). The HTTP status per code (G50) is still missing.
- **PRO-110.** The completed conversation of 05 §5.9 in the codec test is the first golden fixture; the step-semantics and canonical-hash fixtures are SYN-002 and CDM-011.
