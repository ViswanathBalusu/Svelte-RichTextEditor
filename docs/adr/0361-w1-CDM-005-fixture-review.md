# ADR 0361: Review record for the semantics fixtures (CDM-005, criterion 4)

**Status:** proposed, 2026-11-15. A record for review, not a decision. Prepared by lane w1 (epics FE, CDM, WASM) from the code and the tests. Brought up to date by lane w6 on 2026-11-20, in two passes. The first followed owner decisions 9, 10, 11, 77 and 78 of [docs/owner-decisions-2026-11-15.md](../owner-decisions-2026-11-15.md) and the compiles of CDM-043. The second followed the rosters that the two engines keep in their own packages (FE-077 and EXP-115). The first pass had missed them, so the LaTeX column called five files "not run" that EXP-115 runs. No person has confirmed the record, so CDM-005 criterion 4 stays unticked.

## Context

CDM-005 criterion 4 asks the owners of the layout engine (FE) and of the LaTeX class (EXP) to review the fixtures in `packages/model/fixtures/semantics/` and to confirm, rule by rule, that their engine can implement the rule, or to list the gap. ADR 0032 holds the rules, and 03 §6 and §7 state them since 2026-11-20.

Each engine keeps a roster of the fixture files in its own package, written by the lane that owns it:

- the layout engine: `packages/layout/src/fe-077-fixtures.test.ts`, "every shared fixture has a consumer or a reason" (FE-077 criterion 6);
- the LaTeX writer and class: `packages/export-latex/src/exp-115-registry.test.ts`, "every shared fixture file has a registered LaTeX runner" (EXP-115), with the results in the Evidence and Notes of EXP-115.

The table below is drawn from those two rosters and from the tests they name. "Run" means that a test file of the package reads the fixture file. It does not mean that every case is checked: the cell says what is left out. The compile runners of the LaTeX side need `lualatex`, the local font copy and `pdftotext`. They skip where one of these is missing, which includes the CI jobs.

## What the record shows

- No rule has been found that either engine cannot implement. Every fixture file is run in each engine, or has a reason in that engine's roster.
- The per-line `multiple` rule, which the criterion gives as its example, needs the callback in the class. The callback exists, and the ten cases compile to the fixture's heights.
- Gaps of the layout engine: the hanging-indent stop (below); a date field with no cached text shows a stand-in; `whitespace.json` is not run; leaders are not checked.
- Gaps of the LaTeX side: the four gaps of `paragraph-spacing.json` named in the table (cell edges and footnotes); no runner for projections or for spaces; leaders are not read. The gap between consecutive footnotes depends on which notes share a page, which only TeX knows.

## Differences found by reading the engines (lane w6, 2026-11-20)

The fixtures did not show these. The first has a fixture case now. The others have none, because the rule itself is not settled. Nothing was changed in either engine.

1. **The hanging-indent stop in the layout.** By 03 §7.4 a hanging indent gives a left stop at the left indent. In `tabs.json` every hanging indent lay on a multiple of the default tab stop, so an engine without the rule passed. The new case `hanging-indent-off-the-default-stops` (a left indent of 500 twips) passes in the model and in the LaTeX class and fails in the layout's breaker, which goes to 720 (`nextStop` in `packages/layout/src/lines.ts`). The conversion does add the left indent to the paragraph's own stops for the tab after a numbering label (`items.ts`). Read from the code and not run: as one of the paragraph's own stops it clears the default stops before it, which the rule says the stop of a hanging indent does not do (the case `hanging-indent-does-not-clear-default-stops` passes in the breaker because the test gives it no label).
2. **The style of a footnote's paragraph.** By 03 §6 a paragraph whose `style` is null has the default paragraph style, and the model's own walks read a footnote's paragraph that way (`computeLabels`, `flowGaps`). The LaTeX converter gives such a paragraph the style `FootnoteText` when the document defines it (`footnoteText` in `packages/export-latex/src/inline.ts`; EXP-029 criterion 4). The layout sets every footnote paragraph in `FootnoteText`, or in the default paragraph style when the document does not define it, and reads neither the paragraph's own style nor its direct formatting (`footnote` in `packages/layout/src/flow.ts`). The editor creates a footnote's paragraph with a null style (`insertFootnote` in `packages/engine/src/footnote.ts`), so this is the common case. Every footnote paragraph of the fixtures names its style, so no case shows it.
3. **The table style of a table without a `style`.** The model's walk (`computeLabels`), the LaTeX converter and the DOCX writer apply none. The layout applies the built-in `TableNormal` when the document defines it (`tableStyle ?? 'TableNormal'` in `flow.ts`), as Word applies its default table style. 03 §6 does not say which is right. No fixture has such a table in a document whose `TableNormal` sets a paragraph or run property.

## Not decided here

- Whether the two rosters and the stories behind them count as the review that criterion 4 asks for. They are the statements of the lanes that own the two engines: each fixture file is run in the engine or has a reason, and the gaps are listed. Agents wrote them. In this backlog a review by a maintainer is left to a person (SEC-001 criterion 5, FE-112 criterion 4; `docs/owner-blockers-2026-11-17.md`, part D, names CDM-005 among them). Default applied: the criterion stays unticked until a person confirms the record, or the owner says that the rosters are the review.
- The second and third differences above: which style a footnote's paragraph has when it names none, and which table style a table without one has. The model follows 03 §6 as written; each engine does what its own story asked. A rule in 03 and a fixture case should follow the answer.
- Whether the layout gets a hanging-indent stop of its own. The rule is decided (ADR 0032 section 5, accepted); the change is FE's.
- Settled since this record was first written: the two open questions of ADR 0032 (owner decision 9: the numbering level's indent overrides the paragraph style's; owner decision 11: a projection shows the full document's numbers) and the page with no room for the body (owner decision 77). Still with the owner: whether `spaceBefore` is dropped at the top of a page (ADR 0353; ADR 0032, open question 7).
