# ADR 0334: Blockers left after the second round of BE-029 to BE-042 (lane V-BE-029-042)

Status: proposed (lane V-BE-029-042, 2026-11-13). Owner review needed. Nothing here is decided;
each item names the spec default where the spec gives one.

## Context

Round 2 of the lane was asked to close the criteria in BE-029 to BE-042 that earlier lanes left
blocked on PostgreSQL, object storage, a browser or another package. Most of them are already
ticked with evidence (BE-029, BE-031, BE-033, BE-034, BE-035). The criteria still open in this range
are blocked by a decision, by a feature that is not built, or by a measurement. None of them can be
closed by a test alone, so this round ticks nothing new.

## Open items and the default that applies

1. **BE-039 criterion 1: the outbox row and the control-plane state in one transaction, with a
   deterministic commit identifier.** Spec 04 §10 and 06 §3 require both. Two things block it.
   - The prefill enqueue (`src/control-plane/field-routes.ts`) takes `commitId: uuid7(d.now())`.
     That identifier depends on the time, so a retried prefill gets a new identifier and the
     "a retry cannot apply it twice" rule does not hold for it.
   - That route writes no control-plane state in the same transaction as the outbox row. It reads
     the head and the grants and writes nothing.
   Spec default: none. The spec says the identifier is deterministic but not how it is derived.
   Proposal for the owner: derive it from the tenant, document, incarnation, operation kind and the
   request's `Idempotency-Key` (or, without a key, from the operation's own inputs). Then test it
   against PostgreSQL in Podman: a crash between the two writes must leave either both or neither.

2. **BE-037 criterion 5: `Idempotency-Key` on `PUT /documents/{id}/content`.** Spec 05 §6.1 says
   only that `POST` requests that create something accept the key. `PUT` is outside that rule, and
   the protocol definition (`packages/protocol/src/definition/resources.ts`) does not set
   `idempotencyKey` on `replaceContent`. Spec default: the key applies to `POST` only, so the
   criterion stays open until the owner extends the spec. Changing the protocol is the protocol
   owner's call (ADR 0104, Q9), not this lane's.

3. **BE-032 criterion 6: bare-identifier routes.** `/threads/{tid}`, `/comments/{cid}`,
   `/imports/{jid}` and `/workflow/participants/{pid}` have no registered handler, so they answer
   `not_found`. Each handler belongs to the story that owns its resource (FRW, SYN, EXP). The
   bare-identifier check must be added with each one. `/exports` and `/assets` are done.

4. **BE-036 criterion 4: shared caching of pinned reads.** The bytes and the ETag are tested. The
   header is `private` by decision D70 and review SR-C4. Whether documents without hidden scopes may
   be cached at shared edges is the owner's decision (ADR 0019).

5. **BE-038 criterion 3: pages that span cold segments.** No cold segment store (HIS-029) exists in
   the data plane. BE-040 was merged into HIS-029 on 2026-11-06. Blocked on that feature.

6. **BE-030 criteria 3 and 5.** Criterion 3 asks that another tenant's acknowledgement latency does
   not rise. That is a measurement on the reference machine (BE-058). Criterion 5 is the stage 2
   move of the counters to Redis or Valkey (BE-063). Both stay open.

## Consequences

No story in the range is ticked by this lane. The items above need the owner or another story's
handler before a test can prove them. No product code was changed in this round.
