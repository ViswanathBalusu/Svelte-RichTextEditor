# ADR 0245: Decisions of lane BE-079-091 (proposed)

Status: proposed. For the owner to confirm. Each decision below is one the spec leaves open or
silent on. The spec default is used and listed here so that it is not decided silently.

## Context

Lane BE-079-091 (round 6) built the structural dump (BE-089) and the live-use quota decisions
(BE-091). Both need a figure or a shape the spec does not give.

## Decisions

1. **Structural dump filler (BE-089).** A text run is replaced by one filler character repeated to
   the run's length in UTF-16 code units. The character is the first candidate, in the order of
   `FILLER_CANDIDATES` in `services/document-service/src/data-plane/structural-dump.ts`, that
   occurs in no source text. Reason: the steps' positions count code units, so the lengths must
   match, and a filler that occurs in no source text makes it impossible for a source run to survive.
2. **Dump scope (BE-089).** Only CDM nodes of type `text` are replaced, as 06 §11 and the story say.
   Attributes that may hold user text (field values, alt text, titles, link targets, `latex`) are
   not replaced. This stays open; the story's open question applies.
3. **Commit rate window (BE-091).** The commit-rate quota is a count of commits per sliding window
   of `windowMs`. The spec gives no unit or window. The window length is supplied by the caller;
   no figure is set here.
4. **CPU budget window (BE-091).** The room CPU budget is a number of milliseconds per sliding
   window of `windowMs`, the same window as decision 3.
5. **Retry delay of count quotas (BE-091).** For connections and open documents the retry delay is
   supplied by the caller (`countRetryMs`). No default is invented.
6. **CPU refusal code (BE-091).** A spent room CPU budget is `rate_limited` with action `retry`, as
   06 §12 says for the CPU budget. The story's open question notes that 06 §12 also says exceeding
   quotas gives `quota_exceeded`; the more specific sentence of 06 §12 is followed here.
7. **Operator identity and tenant assignment for the dump (BE-089; added in review fix, H group 1
   round 2).** The spec names neither. The operator is the operating-system account that runs
   `structural-dump-cli.ts` (`os.userInfo()`); there is no flag to name another one. The audit
   trail records it as `operator:<account>`. The assignments are a JSON file kept by the operator
   organisation and named by `DOCEDIT_OPERATOR_ASSIGNMENTS`
   (`{ "operators": { "<account>": ["<tenant>", ...] } }`); no file, an unlisted account or an
   unlisted tenant means not assigned, and there are no wildcards. The check runs before anything
   is read, and the read runs under the tenant that was checked. A refused run is logged (identifiers
   only) and is not written to the tenant's audit trail. Alternatives for the owner: a table in
   PostgreSQL (needs a migration), or the operator's single sign-on groups. Only
   `operator-assignments.ts` and the command line change if one is chosen.

## Consequences

- The dump command is built (`structural-dump-tool.ts`, `structural-dump-cli.ts`) over the
  PostgreSQL log, the checkpoint index and the object store, as `recovery-cli.ts` is. The quota
  decisions are module-level; their wiring (the socket and REST answers, the data plane's metrics)
  is not built and is recorded in the stories' Notes.
- If the owner chooses a different window or a different CPU code, only `live-quotas.ts` changes.
