# ADR 0209: Defaults chosen by lane FE-118-130 for character values and lists

Status: proposed (2026-11-13). Owner decisions are not made here: each default below is the
engine's current behaviour and can be changed by the owner.

## Context

FE-128 (character values) and FE-130 (multilevel lists) leave some rules open. The stories and the
spec give no number or no rule for these points, so the engine uses the defaults below and records
them here, as CLAUDE.md asks.

## Decisions taken as defaults

1. Font size range. Sizes are integers in twentieths of a point, from 20 (1 pt) to 32760 (1638 pt),
   the range the web view already accepts (`packages/engine/src/view-support.ts`). 01 §8 gives the
   unit, not the range.
2. Colour. `#RRGGBB` is accepted in either case and stored in upper case, as the rest of the model
   writes it.
3. Font family. The engine checks the family name against the web view's grammar. The manifest
   (FE-062) is not read by the core, so a name outside the manifest is stored. Open for FE-062.
4. Language. A BCP 47 tag is checked for shape only (`[A-Za-z]{2,8}(-[A-Za-z0-9]{1,8})*`). The
   registry of tags is not in the core.
5. Null removes a value. `null` for a value command removes that mark, so one command both sets and
   clears a value.
6. Character style. The command refuses an identifier that the document does not define as a
   character style (`kind: 'character'`).
7. Clear formatting removes the direct marks only: bold, italic, underline, strike, small caps, all
   caps, vertical alignment, font family, size, colour, highlight, language and hidden text. It keeps
   the paragraph style, character styles (a character style is a named style, not direct formatting),
   links, suggestion marks and preserved runs.
8. Lists. Applying a list to a paragraph that already has a list keeps that list instance; applying
   it to a paragraph after a list of the same definition joins that list; otherwise a new list
   instance starts. Levels are kept on a definition change and clamped to the definition's levels
   (at most nine, 0 to 8).
9. Tab at a list item changes its level only with the caret at the start of the item, and only after
   the table-cell move has declined (FE-040). Enter in an empty list item removes its numbering before
   the paragraph split.

## Not decided here

- Suggestion mode for formatting (FE-128 criterion 7, FE-043) is not built.
- Proofing does not read the `lang` mark yet (FE-128 criterion 3).
- Labels against the PDF output (FE-130 criterion 3) are not compared.

## Performance questions (FE-118, FE-119, FE-120; lane round 5, 2026-11-13)

These are proposals for the owner. No default below is measured or enforced in CI, and no number is
invented.

7. "Interactive" (FE-119 criterion 1). Proposed default: the harness's own definition in
   `packages/perf/e2e/harness.spec.ts`, the end of the last long task (over 50 ms) before a quiet
   window after the editor is ready. The spec gives the 2 s target and no definition (13 §9).
8. Cache states (FE-119 criterion 4). Proposed default: cold means a new browser context with no
   HTTP cache; warm means a second load in the same profile. The harness reports cold loads only.
9. Network profile (FE-119 criterion 4). Not defined by the spec or the harness. No default is
   proposed; the report must name the profile it used once the owner picks one.
10. The "usable to 300 pages" threshold (FE-120 criterion 1). FND-007 already sets the metric: the
    typing measurement on `pages-300` against the typing targets of 00 §9. It is recorded in
    `packages/perf/baseline/reference-1.json` as provisional (ADR 0037). Not decided here.

Status of the stories after this round: FE-118, FE-119 and FE-120 keep every criterion unticked; the
reasons are in each story's Notes. FE-127 was already fully ticked. FE-129 carries another lane's
"In progress" line and was not touched.
