# ADR 0325 (lane U-UX-001-015): access-key gesture and built-in keys

Status: proposed. Nothing here is owner-decided. The gesture is the lane's proposal, wired so that its criteria can be tested; the owner may change it.

## 1. Activation gesture for access keys (UX-012)

Proposed: option A of docs/adr/0231-lane-UX-001-013.md. Alt pressed and released with no other key in between enters access-key mode. In the mode a letter or digit runs the command whose access key it is (shown as a tip on its toolbar control). Escape leaves the mode and returns focus to the text. A key pressed with Alt (Alt+Q) is a shortcut and does not start the mode. A pointer press or focus leaving the shell ends the mode.

Code: `packages/ui/src/shell/access-key-mode.ts` (the gesture as a state machine, `resolveShownKey`), `packages/ui/src/components/AccessKeyTips.svelte` (the tips and the `aria-description` text), `packages/ui/src/App.svelte` (the listeners on the shell's root, `startAccessKeys`, `runAccessKey`).

Rules the code follows:

- A key shown for commands in more than one toolbar group is ambiguous and runs nothing; the mode stays on.
- A key no shown control has runs nothing; the mode stays on, and the key is swallowed.
- A command the permissions or the mode disallow runs nothing; its reason goes to the status region (UX-004, UX-012 criterion 5).
- Keys are read only inside the shell's root, so the host page never reaches the mode (UX-012 criterion 6).

Not checked here: whether Windows Chrome, Edge or Firefox move focus to the menu bar on a lone Alt. Playwright does not show the browser's menu bar, so this stays open. If it does, the owner should choose option B of ADR 0231 or a key that no browser reserves.

## 2. Built-in access keys (UX-012 criterion 1)

Not decided. The built-in commands declare no `accessKey`, so the product shows no access key for them. Adding keys to the built-in entries (for example `format.bold`, `b`) breaks the property test in packages/ui/test/access-keys.test.ts, which registers each of the 36 keys on the `format` level and expects a conflict; that test assumes no built-in key on that level. The owner or the lane that owns that test must choose the built-in keys and fix the fixture. Until then the browser run registers an extension command with the key `k` in its own group.

## 3. Shortcut table row for the gesture (UX-012 criterion 3, UX-013)

Not added. The table in packages/ui/src/shortcuts/table.ts feeds generated artifacts in `spec/shortcuts/`, and regenerating them is a repository-level step. The Firefox list in `SOURCES.firefox` is still unread, so the gesture cannot be checked against Firefox's reservations.

## Not decided here

- The gesture itself, and whether it is documented in 13 section 4 or in the user documentation (UX-090).
- The built-in access keys and the level (the toolbar group) they belong to.
- The tip's placement on small screens (the tip sits at the control's top left, fixed in the viewport).
