# 0121. Security backlog batch: open questions from the security packet

**Status:** proposed (2026-11-13). Written by the security developer in the backlog batch, round 1, for the proofs in `tests/security`. Not reviewed by the owner.

## Context

Packet F (`tests/security`) was checked this round for SEC-017 and SEC-026. Criteria whose tests pass are ticked with Evidence. Criteria that need code outside `tests/security`, a browser, a container, CI or a decision stay unticked, and each reason is in the story's Notes. This note lists the points that need a decision, with the default the code takes.

## Open questions and the default taken

1. **What "memory stays bounded" means (SEC-017 criterion 2).** The protocol `Reassembler` holds one message at a time, and it has no byte cap of its own. The byte cap is in the document service session (`maxReassembledBytes`, which is `maxCommitBytes` plus 64 KiB, and the check in `session.ts` `#chunk`). Default taken: the criterion is met by one-message state plus that cap, proved over the wire by the 4413 close. No heap measurement is made. Question: does the owner want a measured heap bound as well?

2. **Chunk byte counter across expiries (found while checking SEC-017; not a story criterion).** `session.ts` `#chunk` resets `#chunkBytes` only on a complete or an error. When the 10-second timeout drops a reassembly inside `Reassembler.push`, the counter is not reset. A client can therefore reach `too_large` after several expired reassemblies that together pass the cap. The failure is closed, not open, so it is not a bypass. Default: left as it is. Question for the document service owner: should an expiry reset the counter?

3. **The engine identifier gate (SEC-050 criterion 4).** The criterion needs a rule that a changed step library or fixture forces a new engine identifier. No such gate exists: `ENGINE` is the constant `pm-steps/1` in `packages/authority/src/room/types.ts` and in `packages/engine/src/core.ts`, and nothing ties it to the fixture digests. Default: the criterion stays unticked. The current test (`supply-chain.test.ts`) checks only that the step library is pinned exactly. Question: owner decision on what fixes the engine identifier, for example a recorded digest of the fixtures checked in CI.

4. **Snapshot branch of the rebase limit (SEC-025 criterion 1).** The `stale_base` test covers a base more than `maxRebaseSteps` behind. The snapshot branch needs the snapshot route (`PUT /content`, BE-037), which this server does not serve. Default: unticked. The authority's own tests cover the branch.

5. **Comments and threads (SEC-019 criterion 2).** The control plane has no thread or comment routes, so "the author is the caller" cannot be tested over the wire. Default: unticked until PRM-037 exists.

6. **Bypass-class review (SEC-021 criterion 3).** The review is a human judgement. The named fixtures are in `tests/security/test/bypass-classes.test.ts`: empty position maps for attr and mark, a crafted `replaceAround`, removing one region boundary, reusing a node identifier, re-creating a deleted region, and a doc or defs change without structure. Default: unticked until a security reviewer signs off the list.

7. **Limits of I7 and I15 (SEC-027 criterion 4).** `tests/security/test/corrupting-limits.test.ts` replays the past-the-limit fixtures over the wire. In round 1 five of its tests failed. The causes were in the test, and the fixer corrected them:
   - the corpus names the column limit `tableColumns`, not `columns` (`i7-columns-64` exists);
   - the `fields` case opened its channel without the `fields` feature the document requires, so the channel was refused and the commit got `error`; the client now declares the document's features;
   - the test expanded `$repeat` into an array, not a string. Even expanded correctly, a 16 MiB commit is larger than `maxCommitBytes` (1 MiB) and is closed with 4413 before the invariant check. The test now grows the document to exactly 16 MiB by commits under that limit, measures the canonical size, and sends the one character past it, which is refused with `invalid_op` (I7). A 4413 close is not counted as the refusal;
   - the `depth` fixture is a stored document that no step can make, so the control plane refused it at creation. The test now creates the document without the deep region and inserts that region by a commit. No valid document is deeper than 12, so that commit also breaks I3.
   Still open: the corpus has no fixture for 500 rules or for a field value over 4 KiB (I15). They are `it.todo`, and the criterion stays unticked. Question: whether the fixture corpus of CDM-014 gets those two cases.

8. **Phase 1a leases (SEC-031 criteria 2 and 4).** The lease criteria need the node lease store in a running room. They stay unticked in this round.

## Round 4 (2026-11-13): SEC-029, SEC-016, SEC-060

13. **A deleted commit reads as a gap, not as an alteration (SEC-029 criterion 1, found while writing the proof).** `verifyBundle` reports a missing record as a `gap` problem with `altered: false`, so the status is `incomplete` (exit 2), not `altered` (exit 1). A deleted tail whose head is also rewritten verifies as `intact` unless an anchor is held. The criterion asks for the first broken seq, which the verifier gives; it does not ask for the status. Default: the verifier is unchanged and the test pins `incomplete`. Question for the owner: should a deletion count as altered for the relying party, given that the operator is trusted (10 §2)? Criterion 1 stays unticked: the test edits the exported bundle, not a stored row.
14. **Refused and missing answers differ (SEC-016 criterion 4, the open question on `forbidden` and `not_found`).** A user token of document A asking for an export of document B gets 403; a missing export gets 404. The difference tells a caller that a job identifier exists in another document. The spec default is not stated in 05 §6.1, so none is taken. `tests/security/test/bare-identifiers.test.ts` pins today's answers and says so in its name; a decision changes that test on purpose. Question for the owner: which answer is the decision.
