# ADR 0256: Open questions raised by lane SEC-027-039

Status: proposed (2026-11-13, lane SEC-027-039). Owner decisions are the owner's; this record lists what the spec leaves open and the default used.

## Context

Lane SEC-027-039 took the stories SEC-027 to SEC-039 of `docs/stories/SEC-security.md`. Three criteria touched a question the spec or the owner decisions do not settle. They are recorded here, not decided.

## Questions

1. **SEC-039 criterion 4 (embedded objects are dropped, with a warning).** Owner decision A2 (ADR 0017, preservation layer; `docs/stories/SEC-security.md` Notes of SEC-039) keeps embedded objects as opaque preserved content and writes them back on export, and 10 §3.5 is edited to match (E22). The criterion as written contradicts that. Default used: the criterion is left unticked and not tested either way. Owner to confirm the reading: "dropped" becomes "preserved opaquely, listed in the import report, and removable by the tenant" (SR-M18).

2. **SEC-028 criterion 2 (CPU budget per connection).** The data plane has a message-count token bucket per connection, user and tenant (`services/document-service/src/data-plane/session.ts`, `#admit`), not a CPU budget. No CPU budget or its unit is given in 10 or 04. Default used: the criterion stays unticked. A value for the budget would be an invented number; the owner or the operator must set it.

3. **SEC-032 criterion 3 (each OpenAPI route that takes a sequence number has a gate test).** `SEQ_INPUTS` in `services/document-service/src/data-plane/gate.ts` lists client-supplied fields, but the OpenAPI definition (`spec/dep/dep-1.openapi.json`) also has many `seq` properties that the server sends. A walker must separate the two before it can fail a build on a new route. Default used: not written; the criterion stays unticked.

4. **SEC-028 criterion 5 (fuzz time limit per input).** No per-input time limit is given in 10 §5 or 04. Default used: not written. The value is a setting to propose, not to invent.

5. **SEC-034 criterion 1 (commit-time I8 for math, round 2).** The room accepts an injected `mathGate` (`RoomInit.mathGate`), but the document service's room host builds its room without one (`services/document-service/src/data-plane/room-host.ts`), so a real commit with a refused equation is not rejected by I8 (validate.ts notes "I8 (no math gate given)"). The room-level and converter-level refusals are tested in `tests/security/test/math-commit-gate.test.ts`. Default used: criterion 1 stays unticked. Question for the document-service owner and the owner: should the service inject the real gate from `@docedit/export-latex` (the gate sits in a universal package, so the service may import it), or should the gate move into `packages/model` so that the service and the converter share one definition? The spec does not say which.

6. **SEC-036 criterion 4 (raw logs only to callers with `edit`).** The route is in `services/document-service/src/control-plane/export-routes.ts` (EXP-066). It is not tested in `tests/security` yet. Default used: unticked; no route test was written in this round.

## Round 3 (2026-11-13)

7. **SEC-039 criterion 7 (importer fuzz, a time bound per input).** SEC-059 names `docx-importer` only as a phase-2 target and wires no run of it in `tests/security`. The run is `tests/security/test/sec-039-importer-fuzz.test.ts`, with the oracles of EXP-110: a non-`ImportError` exception is a crash, and an import over 1 s plus ten times the sample's import time is a hang. The 1 s and the factor ten are a test bound chosen here, not a spec value; the owner should confirm or set them. Default used: criterion ticked on this bound.

8. **SEC-036 criterion 4 (raw logs only to callers with `edit`) answered.** `tests/security/test/sec-036-raw-log.route.test.ts` runs the real export route. The route reads the result's `log` as an object name and signs it, so the test writes the log under the job prefix as a worker does. Item 6 above is answered by this test. Criterion ticked.

9. **SEC-033 criterion 2 (a test for each context in which a user string reaches TeX) not written.** The call sites found in `packages/export-latex/src` are `text`, `pdfString`, `kvValue`, `url`, `dimen`, `color`, `enumLookup` and `generatedId`. Numbering templates, bullet characters and language names have no direct emitter call in that search; they reach TeX through `text` or `lit` in other modules. Which emitter each of those three contexts uses is not settled, so no list was written. Default used: criterion stays unticked.

## Round 4 (2026-11-13)

10. **SEC-036 criterion 5 (result files served from the asset origin, fixed content types, `nosniff`).** Export results are returned as presigned object-store URLs (`services/document-service/src/objects/s3.ts`, `signedUrl`; `services/document-service/src/control-plane/export-routes.ts`). The presigned URL sets no response content type and no `nosniff`. The asset origin (`services/asset-worker/src/origin.ts`) serves assets, not results. The spec (10 §3.5) says assets come from a separate origin; it does not say which origin serves results. Default used: criterion stays unticked. Owner or the document-service owner to decide: serve results through the asset origin (fixed type, `nosniff`), or set the response headers on the object store.

11. **SEC-029 criterion 4 (export manifest carries the current chain head).** The export job calls `buildBundle` with `chainHead: null` (`services/export-worker/src/job.ts`). The job receives no head from the commit log. Default used: criterion stays unticked; no change made, because the export worker is another package's work. The fix needs the head in the job payload, which the document service would set at job creation.

12. **SEC-033 criterion 2 (a hostile test for each context).** `tests/security/test/sec-033-contexts.test.ts` covers body text, alternative text, field labels, PDF metadata, bookmarks, link targets, colours and lengths. Bullet characters (`BULLETS` in `packages/export-latex/src/blocks.ts`) are not exported, so a test cannot reach that table without a change to the converter. Numbering templates have no converter code that reads `numbering_def.levels`. Default used: criterion stays unticked. Owner to confirm where a numbering template reaches TeX, or to export the bullet table.

13. **SEC-033 criterion 3 (the `text` oracle per language).** The emitter `text` takes no language argument, and the class loads babel with shorthands off (`packages/export-latex/src/languages.ts`). The class still loads babel and imports each language's ini file, and that can change hyphenation, spacing and characters, so only a compile per language shows that the text survives. Round 4 correction: an earlier reading ticked the criterion on a token-level run that did not use the tag; review unticked it. Default used: the criterion stays unticked until a compile run per language exists (the sandbox of SEC-035 under Podman, or `typeset.compile.test.ts` with an engine). `tests/security/test/sec-033-contexts.test.ts` now checks the converter half per tag: the `\DEbabel` and `\DEdeflang` lines come from the table, nothing else in `main.tex` depends on the language, and hostile text inside a language switch is the same tokens as without one. Owner to confirm that the compiled oracle of criterion 1 is the oracle for criterion 3 as well.

14. **SEC-030 criterion 3 (approval hash).** A region's canonical content is hashed and compared with the stored approval hash, and a mismatch is reported. The check is a new module, `packages/authority/src/permissions/approval-check.ts` (`checkApprovalHash`, `checkApprovals`), tested in `tests/security/test/sec-030-approval-hash.test.ts`. Default used: the check reports and does not decide. Fix of the round 5 review (2026-11-13): `verifyRoomApprovals` runs the check over a room (`Room.approvedRegions`), is exported from `@docedit/authority`, and the room host of the document service (`room-host.ts`, `#verifyApprovals`) calls it when the room opens, when permission state arrives, and after a stored snapshot commit or `revision_moved`; each mismatch becomes a `region.approval_mismatch` audit row (actor `system`) and an `onError` report (tested in `tests/security/test/sec-030-approval-wiring.test.ts`). A mismatch is still not refused on the commit path: an approved region already refuses every change. Not built: the grant stores do not keep approvals yet (PRM, phase 2), so a room opened from storage has none to check. Owner to decide whether a mismatch should also refuse the commit, reopen the region, or only report.

15. **SEC-039 criterion 6 (entry names that climb out of the package).** `readZip` in `packages/export-docx/src/zip.ts` now refuses a name that is absolute, has a drive letter, a backslash or a `..` segment (`escapesPackage`). This is a change in the importer's own package, which belongs to the export lane, and it is small. The `it.fails` in `tests/security/test/docx-import-abuse.test.ts` is now `it`. Tests: `tests/security/test/sec-039-entry-names.test.ts`. Owner of export-docx to review.

16. **SEC-037 criterion 3 (commits that name an asset not attached).** The asset check exists in the model (`packages/model/src/validate/validate.ts`, `asset_not_attached`), and the room applies it when it holds an attached-asset set (`RoomInit.attachedAssets`). The story's Notes said no check existed in `packages/authority/src`; that was the wrong place. `tests/security/test/sec-037-asset-refs-room.test.ts` proves the room half: a figure on an attached asset is accepted, and a figure on an unattached one is refused with `invalid_op` and the document is unchanged. Default used: criterion stays unticked. The other-document and other-tenant cases need the data plane to fill the set per document, which is not built (BE-044).

17. **SEC-033 criterion 3 (leftover from review).** Not run in this round. A TeX engine is installed on the host (`/e/texlive/2025/bin/windows`, with `pdftotext`), but the compile driver of the export-worker image and its font directory (`docedit.fontpath`, the worker's environment) are not reproduced on the host, so no host compile harness exists. `sandboxReady()` reports "podman info failed" in a test run, although `podman info` answers in the shell; the export-latex compile tests skip. Default used: criterion stays unticked. Owner or infra to choose between fixing the sandbox probe and writing a host compile harness that mirrors the image's driver.

## Round 6 (2026-11-13)

18. **SEC-030 criterion 5 (whole-document restore refused while a region is approved).** Ticked on `tests/security/test/sec-030-restore-approved.test.ts`, which runs the room's `snapshot` with reason `restore` as the owner. The room's own check refuses it, and it is accepted once the state moves out of `approved`. Default used: the room path, not the data plane's `PUT /content`, which is a snapshot with reason `import` and goes through the same room check. Owner to confirm that the room path is the whole-document restore the criterion means.

19. **SEC-030 item 14 (refuse or report a stored approval that no longer matches) still open.** Unchanged this round: the default remains report only, through the audit row and `onError`. Owner decision needed.

20. **Leftover from review, not fixed here (another lane's file).** `services/document-service/src/data-plane/audit.ts`, `Auditor.flush()`: when the queue is empty, the async block reaches its `finally` (`#flushing = null`) before `#flushing ??=` assigns, so `#flushing` keeps a resolved promise and `record()` never writes again (`#arm` returns early). The fix suggested by the reviewer is to return `Promise.resolve()` at the top of `flush()` when nothing is in flight and the queue is empty. Not changed: the file belongs to another lane. Owner of the audit module to apply it.

21. **Leftover from review, not fixed here.** SEC-030 criterion 3 still stops at the room: the grant stores of the document service do not keep approvals (PRM, phase 2). No change this round.

22. **Stories not ticked this round, with reasons.** SEC-028 criteria 1 to 4 need the CPU budget (no value in the spec), worker threads and an exception counter that does not exist. SEC-029 criteria 3 to 5 need a workflow, the export manifest's chain head (another package) and write-once anchors. SEC-032 criteria 1, 3 and 5 need routes and an OpenAPI walk, and a read marker that is not built. SEC-033 criteria 1, 2, 3 and 5 need a compile or converter bullet table. SEC-036 criteria 1, 2 and 5 need a browser run or the asset origin for results. SEC-037 criterion 3 needs the data plane to fill the attached-asset set (BE-044). SEC-038 criterion 4 needs the worker's kill under Podman, which the host cannot run. SEC-039 criterion 4 conflicts with A2; default kept as unticked.

## Consequences

No change to the spec, to a root configuration file or to another lane's package. The stories carry the reasons in their Notes.
