# ADR 0237: Decisions of lane UX-079-091, round 1

Status: proposed (2026-11-13). Written by the lane's developer agent. The owner or the main session accepts or changes each item.

Context: the lane takes the administration, audit, classification, policy and reference-host stories UX-079 to UX-091. Where the spec leaves a choice open, the lane records it here rather than deciding it silently.

## 1. Audit query (UX-081): default page size

`GET /audit` returns a page of 50 events when `limit` is absent; `limit` is at most 200 (the spec's maximum). The spec gives no default. Owner decision: confirm 50 or choose another value.

## 2. Audit query: time format and bounds

`from` and `to` are ISO 8601 date-times with a time zone. `from` is inclusive and `to` exclusive, as in `AuditQuery` (BE-014). The spec does not name the format.

## 3. Audit query: cursor

The cursor is opaque to clients: base64url of `{"at": <ms>, "id": <event id>}` for the last event on the page. The store has no identifier cursor, so a page that needs more than one store read's events (1000) within one millisecond is refused with `unavailable` rather than read wrongly. A change to `AuditStore` (an identifier-based cursor) would remove the limit; that is a BE decision.

## 4. Audit query: projection

A returned event has `id`, `document`, `actor`, `kind`, `scopes` and `at` only. The event's `data` is not returned except its `scopes` list (UX-081 criterion 6). A later event kind that needs more fields must be added to the projection by decision.

## 5. Audit query: routing

The router entry for `GET /audit` is not in this lane (`handlers.ts` and the composition are not owned here). `AuditQuery.query` is the operation it will call.

## 6. Data-loss prevention hook (UX-086): request body

The hook request body is `{document, actor, action, target, classification}`, signed as a webhook delivery (05 section 7). The field names are a proposal; the spec names the content but not its names. The answer is `{"decision":"allow"}` or `{"decision":"deny","reason":"…"}` (reason at most 500 characters); any other shape is read as null.

## 7. Data-loss prevention hook: timeout and failure outcome (open)

The spec leaves open what happens when the hook does not answer in time or cannot be reached (UX-086 criterion 3). No default is chosen in this lane. The owner must choose: refuse (fail closed), allow (fail open), or a documented per-tenant setting. Until then the request is not sent by any code in the repository.

## 8. Hold administration (UX-080): dependency

The hold rule (`applyHold`) is in `@docedit/history`. `services/document-service` does not depend on that package. Adding the dependency edits `services/document-service/package.json`, which this lane may not change; the main session must decide.

## 9. Webhook administration (UX-079): routes, absent store, response headers

Status: proposed (round 4, lane UX-079-091).

The routes `GET` and `POST /webhooks`, and `GET`, `PATCH` and `DELETE /webhooks/{id}`, are offered only when the server composition supplies a subscription store (`ServiceParts.webhooks`); otherwise they answer `not_found`, as `GET /audit` does without an audit store. The spec does not say how an optional administration resource is offered. Owner decision: confirm, or choose a store configured by default.

Every webhook response carries `Cache-Control: no-store`, because a creation or a rotation returns a secret once. The spec gives no header rule for this. Owner decision: confirm.

Not decided here: the test ping and the replay of deliveries (UX-079 criterion 2) have no operation in the protocol, so no route exists. Adding them is a protocol change for the owner of `packages/protocol`.

## 10. Search (UX-084): not started in round 4

`GET /search` is not routed. The result shape is a placeholder (gap G77), the search index is not fed from checkpoints, and no cursor exists. The spec gives no default page size either. Owner decision needed on the result shape and the cursor before the route is built.

## 11. Round 5: integration guide location, audit stream and export stories

Status: proposed (round 5, lane UX-079-091).

Integration guide (UX-090). The guide is `apps/reference-host/docs/integration-guide.md`, not under `docs/`, because this lane may write only in `packages/*`, `services/*`, `apps/*` and `tests/security`. The page glue (`page-glue.ts`) already refers to a guide with these section names. Owner decision: keep the guide beside the reference host (as written), or move it to `docs/` in a change the main session makes.

Audit stream (UX-082). The spec leaves the stream's transport and format to PRO. The lane does not add a poll route, because that would choose a transport. The cursor of `GET /audit` already resumes without a gap in (time, identifier) order. Owner decision: the transport (long-lived connection, or a cursor feed over HTTP) and the stable identifier rule for stream events.

Discovery export (UX-087) and tenant export (UX-088). No bundle format is specified, and no discovery export exists. Owner decision: the bundle format and the manifest, before any code is written.

Administration console (UX-089). Waits for the published administration API (UX-076), which has no machine-readable definition yet.

## 12. Round 4: UX-091 (reference host compose stack)

Status: proposed. Lane UX-079-091, round 4 (2026-11-13). Only UX-091 was left in the lane's range without a handled round. Ran `apps/reference-host/test/stack.test.ts` and `apps/reference-host/test/registration.test.ts` (11 tests passed, Node.js, `pnpm vitest run`). No container was started: Podman is installed here, but the stack was not run, so criteria 1, 3, 5, 6 and 7 stay unticked. No criterion was ticked this round.

Criterion 2 remains an owner decision and is not changed here. `apps/reference-host/compose.json` gives `export-worker` `network_mode: host`, which conflicts with the criterion as written ("cannot reach the network"). The worker needs the database and the store, and a network-less worker would need those reached another way. Options for the owner: a dedicated network for the worker with only the database and store reachable, or a split of the worker so the sandbox alone runs in a network-less container. Spec default until decided: keep the current definition and report the gap (see ADR 0114).
