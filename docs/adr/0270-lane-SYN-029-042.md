# 0270. Open questions from the SYN-029 to SYN-042 lane (round 1)

**Status:** proposed (2026-11-13). Lists questions the spec leaves open, or that a story leaves open, and that round 1 met. It decides nothing; the owner, PRO, BE or UX decide. Default taken where one is named.

**Context.** The lane reviewed the sync stories SYN-029 to SYN-042 in `docs/stories/SYN-sync-engine.md`. One criterion was ticked in this round: SYN-037 criterion 6 (a client that receives `rate_limited` resubmits the same commit with the same `id`), evidenced by the existing engine tests in `packages/engine/test/sync-state.test.ts` and `packages/engine/test/session.test.ts`. No code changed. The other unticked criteria in the range depend on work not built yet, as the Notes of each story say.

## Questions

1. **Threshold for "many subscribers" (SYN-041 criteria 1 to 3).** The story and 04 §12 do not define when a room counts as large. Default taken: none; the coalescing window is not built, so the room keeps sending each commit at once. Owner: the spec (04 §12).
2. **Message form of a coalesced batch (SYN-041 criterion 3).** `types.ts` in `packages/authority/src/room` defines `sync.commit` with one `commit`. The client push in `packages/engine/test/session.test.ts` takes an array. The spec does not say which form a batch takes on the wire. Default taken: none. Owner: PRO (protocol).
3. **Flush before acknowledgement (SYN-041 criteria 2 and 3).** A window that holds commits for a subscriber must flush that subscriber's held commits before any acknowledgement or rejection on the same channel, or the SYN-015 ordering rule breaks. The spec does not say how. Default taken: none. Owner: SYN (lane for SYN-015 to SYN-028) with the authority owner.
4. **Per-step timing (SYN-040 criterion 1).** Steps 2 to 7 are run inside `Room.submit` without a timing hook, so their CPU cannot be reported separately without instrumentation. Default taken: the benchmark is not written in this round and no figure is reported. Owner: authority owner, to name a hook.
5. **Worker pool for checkpoint, replay and conversion (SYN-039 criteria 1 and 2).** `worker-boundary.test.ts` runs the pure functions in a worker, but the room runs no worker. The production pool is BE's. Default taken: unticked. Owner: BE.
6. **Caret inside unconfirmed text (SYN-036 criterion 5).** The receiver's drawn caret is the element's (13 §5). The data the element receives is confirmed positions at the update's `seq`. Default taken: unticked until the element draws the caret. Owner: UX and the element.
7. **Spike SYN-038 without traces.** The spike needs recorded or simulated editing traces, a sweep of the batching window and of `maxRebaseSteps`, and a report. None is produced in this round, so no measurement is recorded. Default taken: unticked. Owner: the maintainer who runs the spike.

## Consequences

Each question above has its own Note in the story file where a story is affected. Nothing else changes until the owners answer.
