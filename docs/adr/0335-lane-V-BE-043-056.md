# ADR 0335 (lane V-BE-043-056): proposed decisions for the unblock round

Status: proposed. Lane V-BE-043-056, 2026-11-13.

## 1. Egress topology for the webhook dispatcher (BE-056 criterion 4)

The spec asks that the dispatcher's only route out is the egress proxy. The repository now defines
that topology in `infra/webhook-egress-policy.ps1`: the dispatcher sits on a Podman network created
with `--internal` (no route out); the proxy sits on that network and on a normal one; nothing else
is shared. The proxy runs the product's `EgressProxy`.

Default taken: the same topology is required of a deployment. The production network is not in
this repository and is not decided here. The owner or the operations lane decides how it is built.

## 2. Redirect bound in the proxy test

`infra/containers/webhook-egress/proxy.mjs` sets `maxRedirects: 3`. The spec gives no number
(`EgressOptions` in `webhook-egress.ts`). This value is a test setting only and is not a default for
the product. The product default remains open.

## 3. Not decided here

- The tenant context and the hold rule for scheduled jobs (BE-052 criterion 4): the level at which a
  legal hold is honoured is open (ADR 0104, Q4). Not changed.
- The `doc_assets` table and the commit-time asset checks (BE-044 criteria 1, 2, 3, 5; BE-046
  criteria 1 and 2): not built in this round. Orphan deletion must not run before the commit path
  writes attachments, because every ready asset would look orphaned.
- The search tables' DDL in a migration (BE-054 criterion 1): the main session sequences it.
- Document purge pipeline (BE-054 criterion 3): HIS-038 is not built.

## 4. Which limit a flood is reported as (BE-043 criterion 6)

`services/asset-worker/src/sandbox-podman.ts` reported a run as a time limit whenever it exited
non-zero after the wall-clock allowance, before it looked at the output overflow. A flood past the
output limit can take longer than the allowance to stop, so it was reported as `resource_limit`,
while the test and the spec name `output_limit`. The runner now reads an output overflow first.

Default taken: an output overflow is reported as `output_limit` whatever the wall time. Both reasons
fail the job and discard the sandbox, so the outcome for the user is the same. The owner may prefer
another name; the spec gives none. Not decided here.

## 5. Readiness probe timeout (BE-043 criterion 1)

`sandboxReady` gave `podman info` and `podman image exists` 30 s. On the loaded shared host
`podman info` took about 42 s, the probe read Podman as unavailable, and every sandbox test was
skipped. The probes now allow 180 s. This is a timeout for a readiness check, not a product limit
on a job; the job limits are unchanged.
