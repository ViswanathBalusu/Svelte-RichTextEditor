# ADR 0235: lane UX-053-065 decisions (extension tier 2, forced colours, theme wiring)

**Status:** proposed. **Date:** 2026-11-13. **Lane:** UX-053-065, round 2.

This record holds the decisions and evidence rules that lane UX-053-065 applied in round 2. Nothing here is accepted, and the owner has not decided any of it. Where the spec leaves a question open, the proposal uses the spec default and says so.

Stories touched: UX-059 (decision, not taken), UX-061 (wiring check), UX-062 (criterion 1), UX-065 (criterion 4 unticked).

## Decision 1. UX-059: build sandboxed third-party extensions (not decided)

13 section 13 asks whether sandboxed extensions are worth their cost before an ecosystem exists. UX-059 needs three kinds of evidence: named partners or authors, tier 1 usage, and the security review cost.

- Named partners or authors: none is recorded in this repository.
- Tier 1 usage: no usage data exists. The tier 1 API (UX-050) has no record of use outside the editor's own tests.
- Security review cost: not estimated. No review of a sandbox has been done.

The story therefore cannot be decided from the evidence it asks for. The lane does not record a decision. Spec default (11 section 7, phase 4, and the story's `cond` note): tier 2 is not built, UX-060 stays `cond` and unbuilt, and the parity profile (UX-001) is not changed by this lane. Recorded for the owner, who decides "yes" or "no" and sets the first read and write levels if "yes".

## Decision 2. Evidence class for forced colours (UX-062, criterion 1)

A criterion about system colours can be checked against the stylesheet the shell ships, without a browser. packages/ui/test/forced-colors.test.ts reads the `@media (forced-colors: active)` block of packages/ui/src/styles/shell.css and checks the colour values against the CSS system colour keywords. This is recorded as source evidence only. The rendered interface under forced colours, and the emulated run in Playwright, are not claimed. The list of system colour keywords is the CSS Color 4 list; a keyword missing from it would be reported as a failure, not ignored.

## Decision 3. Theme wiring is evidence for criteria, not a tick (UX-061, criteria 1 and 6)

packages/ui/test/theme-wiring.test.ts checks that `App.svelte` reads the colour-scheme preference before the state that holds it, derives the theme from it, binds `data-theme` on the `.de-shell` root, and stops the watcher on destroy. The first paint and the browser's own preference are not run. Criteria 1 and 6 stay unticked until a browser run.

## Decision 4. UX-065, criterion 4 is unticked again

The criterion was ticked without an Evidence line. The e2e spec that tests it, packages/ui/e2e/page-direction.spec.ts, was not run in this lane. The tick is removed until a run in Chromium, Firefox and WebKit is recorded.

## Decision 5. Editor-side guards for custom content are not ticks (UX-056, UX-057)

`checkBlockInsert` (UX-056) and `checkInlineInsert` (UX-057) in packages/ui/src/extensions/custom-nodes.ts refuse content without a fallback and an oversized payload. Nothing in the product calls them, and no insertion path creates an `extension_block` or `extension_inline`. Their criteria about creating the node, the atom behaviour, the `requires` commit, editing through the extension and export stay unticked until the core and the writers exist.

## Consequences

- No criterion is ticked on a browser run in this lane. Browsers were not run.
- UX-059 has no decision recorded; the owner decides it with the evidence above.
- Tests added: packages/ui/test/forced-colors.test.ts, packages/ui/test/theme-wiring.test.ts.
