# ADR 0325: decisions of lane V-UX-001-015

Status: proposed. Nothing here is owner-decided. Each item is the spec's default or the smallest choice that lets a criterion be tested, and each is open to the owner's change.

## 1. Opening shortcut for command search (UX-011 criterion 1)

Spec 13 names command search but no shortcut. Proposed: `Alt+Q`, the key Word uses for its "Tell me" box, which is command search's job. It is bound in the registry as `view.commandSearch` and listed in the shortcut table with no conflict in the browser lists read (Chrome, Edge, Safari; Firefox not read). On Apple platforms the key is read from the physical key (`event.code`), so it works with Option. The owner may choose another key; changing it is one entry in `packages/ui/src/commands/builtin.ts` and one row in `packages/ui/src/shortcuts/table.ts`.

## 2. Synonyms for command search (UX-011 criterion 2)

Open, not decided here. The locale tables carry no synonym keys (spec 13 section 8), so `searchCommands` takes an injected `synonyms` source and the shell passes none. The place where synonyms live (a registry entry field or locale keys) is for the owner.

## 3. Activation gesture for access keys (UX-012)

Not decided here. Spec leaves it open; no gesture is wired by this lane.

## 4. Firefox shortcut list (UX-013 criterion 1)

Not decided here. `SOURCES.firefox` in `packages/ui/src/shortcuts/table.ts` stays `null`, so Firefox's column reads "not checked" until its published list is read and its date recorded.

## 5. Host-page shortcut test in Firefox (UX-013 criterion 4)

Decided by test wording only. Firefox takes Ctrl+F6 for its own focus cycle and moves focus out of the page, so `#after` can lose focus. The test asserts that the editor's shadow root holds no focus and that no command ran. The editor's own behaviour is unchanged.

## 6. Keyboard gesture for the mini toolbar (UX-010 criterion 3)

Open, not decided here. The spec names no gesture. The mini toolbar's buttons are not in the tab order and no key reaches them. Options for the owner: a shortcut that focuses the toolbar when a selection exists, or a key tip in the context menu. Nothing is wired by this lane.

## 7. Mini toolbar content (UX-010)

Spec default taken: the `format` group, and within it only commands that change the text (`changesContent`). The painter's arming and the language list are left out, so a view-only user sees none. The change is in `packages/ui/src/commands/mini-toolbar.ts`.

## 8. Unsent input across a layout switch (UX-007 criterion 6)

Spec default taken: the only unsent input the harness holds is the command search query, and the test checks that it survives a switch of `toolbar` between `full` and `compact` without being run. The comment composer draft and the fill bar are not covered by this test. Test: `packages/ui/e2e/ux-007-layout-switch.spec.ts`, Chromium, Firefox and WebKit. Nothing in product code changed.

## 9. Link from a shipped parity row to an automated test (UX-002 criterion 2)

Open, not decided here. A profile row names its stories, not the tests that exercise the capability, so `parityReport` cannot link a shipped row to a test. Proposed default, for the owner or the PRO/FND owners: each row gains a `tests` list of test file paths, and the report refuses a shipped row whose list is empty or names a file that does not exist. This lane did not make the change, because it alters the profile schema and the release report. Criterion 2 stays unticked.
