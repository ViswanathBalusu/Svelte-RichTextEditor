# ADR 0320: decisions of lane V-EXP-049-064 (round 2)

Status: proposed (2026-11-13). Owner decisions are not made here.

## Context

Lane V-EXP-049-064 closed blocked criteria in stories EXP-049 to EXP-064. Where a spec or story
left a choice open, the choice is recorded below with the spec default used.

## Decisions

1. **The manifest records the math gate version (EXP-051 criterion 4).** `manifest.json` gains a
   `mathGate` field `{ version, katex, fingerprint }` taken from `ALLOW_LIST` (the generated
   allow-list). Spec default: 09 §6.3 names the allow-list as versioned, and EXP-051 criterion 4
   compares results "for the same gate version", so the version has to be in the bundle. The field
   is not part of `bundleHash` (the hash covers files and options only), so existing hashes do not change.
   Consumers that check manifests (`services/export-worker/src/verify.ts`) ignore unknown keys.

2. **Line-start checks match in order, not by index (EXP-055 criterion 4).** A new test
   (`packages/export-latex/src/exp-055-line-offsets.v-lane.compile.test.ts`) matches each paragraph
   line start against the PDF lines in order. Spec default: 09 §7 asks for `lineStarts` that equal the
   PDF's, and `pdftotext` splits an inline equation with a superscript over two lines, so PDF line
   index is not paragraph line index. The existing lane-U test
   (`exp-055-057-line-offsets.compile.test.ts`) is not edited by this lane.

## Open for the owner

- **CJK face for the export sandbox (EXP-056 criterion 1, EXP-026).** The TeX tree of the worker image
  has OpenType CJK faces (Fandol, Harano Aji, LXGW). None is in the image's font manifest, none covers
  Hangul, and their licences were not checked. Choosing one is an owner decision (licence and coverage).
- **Cross-process gate comparison (EXP-051 criterion 4).** The manifest now records the version, but
  no run re-applies an older gate to an older bundle. Whether that is needed is open.

## Round 3 (2026-11-13): form field rectangles (EXP-058)

**Status:** proposed.

- **Unit and origin of a field rectangle.** `layout.json` `fields[id].rect` is `[x0, y0, x1, y1]` in
  twentieths of a point, from the top-left corner of the page, with y growing downward. This is the
  unit the schema already declared (`unit: "twip"`) and the origin of the vertical positions in
  `layout.json`. 09 §7.1 gives only a sample and does not state the unit or origin (open question in
  the spec). The spec default is not stated either, so this is a proposal for the owner to confirm.
- **Numbering in the class.** The class reports a field box under a small number, not under its
  identifier (a LuaTeX attribute holds a number). The converter numbers the fields in order of first
  use and writes the list as `SourceMap.fields` (an optional member, present when the document has a
  form field). The worker joins the number with the list. A field in a header is reported at the
  first page on which the header is printed.
- **Class release.** The class changes, so it is released as 0.2.2 (`ProvidesClass`, `\DEclassversion`,
  `CLASS_VERSION`, and an appended entry in `class/releases.json`).
- **Not measured.** The coverage of a blank field's empty box is not checked on its own. Fields placed
  after inline math, after a discretionary break (a soft hyphen) or in a line with a different glue
  setting than the test's are not tested. The horizontal walk adds the widths of glyphs, rules, kerns,
  math nodes and glue, and nothing for a discretionary break, so a field that follows a discretionary
  break on the same line may be placed too far left. This is a known gap, not a proven one.

## Round 4 (2026-11-14): display equations are clipped (EXP-052 criterion 5)

- **Status: proposed.** The clip is a class change (0.2.3). The spec does not name a mechanism for the
  clip (09 §6.3 says "clips every equation to its box", with no method), so the choice below is the
  lane's, for the owner to confirm.
- **Mechanism.** `\DE@clipout` in `class/docedit.cls` measures the math in a box (`\DE@cbox`) and emits
  the box's outline as a PDF clip path (`0 -depth width height+depth re W n`) under a matrix that turns
  scaled points into big points (1 sp = 0.00001520178239 bp), with the matrix undone before the box is
  shipped. The clip is written with LuaTeX's `\pdfextension save`, `literal direct` and `restore`
  (LuaTeX has no `\pdfliteral`). Display equations (`\DEeq`) use it. Verified with
  `packages/export-latex/test/exp-052-clip.compile.test.ts` (Podman).
- **Inline equations are not clipped.** Boxing an inline equation stopped the line breaker from breaking
  inside it, and it moved the line-start offsets that `exp-055-line-offsets.v-lane.compile.test.ts`
  checks (that test then failed in Podman). The inline box was removed. The spec default for
  inline math is unchanged. A clip for inline math that keeps the line breaks is not chosen here: it
  is an open design choice (for example, a clip per line piece, or a node-level clip in Lua).
- **Release.** Class 0.2.3: `ProvidesClass` and `CLASS_VERSION` raised, `class/releases.json` appended.
  The 0.2.3 entry was written and re-hashed within this round, while the release was still a working
  copy (no build shipped it); the owner may prefer a new version number for any release.
- **Not measured.** Whether a bar partly outside a display equation is clipped on the second pass of a
  multi-pass export is not tested; the clip is set in the same compile as the content.
- **Re-hash, fixer round 4 (2026-11-14).** `docedit.cls` was written again at 00:36:16, after the 0.2.3
  entry was hashed at 00:30:04. The writer was lane V-EXP-033-048, round 11 (ADR 0319, V41:
  `\DErowspan` sets `table/multirow`), whose files `tables.ts` and `convert.ts` changed in the same
  minute. Reverting would have removed that lane's EXP-041 work, so the 0.2.3 entry was re-hashed to
  `691850ae...24c8` instead. This is allowed only because 0.2.3 has never left the working tree (the
  repository has no commit, and the base check of `exp-015-class-release.test.ts` is skipped). The
  class compiles in the Podman sandbox with `exp-052-clip.compile.test.ts`,
  `exp-055-line-offsets.v-lane.compile.test.ts` and `tables.spans.tagged.compile.test.ts`
  (`DOCEDIT_REQUIRE_SANDBOX=1`, 3 files, 4 tests passed). `\DEclassversion` in the class still reads
  0.2.2; nothing reads it, and it was left alone so the class bytes stay as hashed.

## Round 9: EXP-053 criterion 2, token-stream half (status: proposed)

- **Reading used.** The trace of an accepted value is compared with the trace of an empty equation in the same document (the class's own wrapper and the kernel's work for every equation are not counted). The strict reading of criterion 2, "no control sequence outside the allow-list", is not met and is not ticked.
- **Why the strict reading fails.** A value with \frac, \sqrt, \sum, or a matrix also runs kernel and expl3 internals (tagging socket, \msg, \tl, \ifx, \Ustack and similar). These are not on the allow-list, and up to about 290 such words appear per value. No fixed expansion list is written, because one would be chosen by reading traces.
- **Check enforced instead.** No I/O, shell, catcode or engine primitive (DANGEROUS in the test: input, openin, openout, write, read, immediate, directlua, catcode and similar) may appear in a value's trace that the baseline does not have. Test: packages/export-latex/test/exp-053-trace.compile.test.ts (Podman, localhost/docedit-export-worker:s4; 15 values, 3 of 3 tests passed).
- **Owner decision needed.** Either (a) the spec says the check is on the value's source tokens and the allow-list only (the lexical check in gate.fuzz.test.ts already holds), or (b) it names the kernel words a value may expand into. The lane does not choose between them. The default used here is the denylist described above.
- **Painting half.** Not checked for inline equations (the class does not clip them; see the "Inline equations are not clipped" bullet above).
