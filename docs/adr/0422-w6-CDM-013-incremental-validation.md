# 0422. Validating a commit from what it changed

**Status:** proposed, 2026-11-21. Written while finishing CDM-013 criterion 7 (lane w6). The spec says the validator should check changed subtrees using indexes (04 section 12) and does not say how. The owner has decided none of these points.

1. **`CommitValidator` (`packages/model/src/validate/incremental.ts`).** It holds the indexes of one document: identifiers, suggestion identifiers, bookmark and equation names, reference targets and their uses, regions, formulas, styles, numbering levels, page setups, stories, sources, asset uses and a bound of the canonical size. For a commit it compares the document before and after by node identity (ProseMirror documents share every node a step did not touch), runs the checks of one node (`node-checks.ts`) on the added nodes, and decides the document-wide checks from the indexes and the removed and added nodes.
2. **It never reports a violation of its own.** When it cannot say "valid" from the changed nodes, it runs `validateDoc()` on the result and returns that, with `how: 'full'` and a `why`. So the result equals `validateDoc()`'s; only the cost differs. Reasons for a full run: a violation was suspected, a definition changed, a registered check reads a changed node type or does not say what it reads, `requires` or the checks changed, the canonical size bound is near 16 MiB, or the document before is not one the validator saw pass.
3. **Shared code.** The per-node checks and the reference checks moved out of `validate.ts` into `node-checks.ts` and `references.ts`, so the full and the incremental path run the same code. `validate.ts` shrank accordingly. The canonical-form helpers `canonicalShellText` and the field invariants gained the small exports the validator needs.
4. **Size bound.** The bytes of the canonical form are tracked as an upper bound that moves with each commit. It is never below the exact size; near the limit the exact measurement of the full path decides.
5. **Not decided.** Whether the authority holds one `CommitValidator` per room, and when a room drops it, is the authority's (SYN-011); this ADR only supplies the class. The criterion asks for a figure "reported by the performance harness" (FND-007); no harness entry runs it yet.
