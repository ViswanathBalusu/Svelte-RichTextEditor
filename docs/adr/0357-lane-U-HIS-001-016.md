# ADR 0357: lane U-HIS-001-016 decisions (round 4)

Status: proposed. Owner decisions are not made here.

## Context

Round 4 of the unblock lane for stories HIS-001 to HIS-016 closed what was blocked on PostgreSQL. This ADR records the choices that the spec leaves open and that the lane took by the spec's default.

## Decisions

1. **Where the stored version rules live (HIS-006, HIS-007).** `PgVersionStore` in `services/document-service/src/storage/version-store.ts` stores the rows of the `versions` table and checks the kind and the `seq` shape. The gate, the head and the `edit` permission stay in the route, which is not built. Default: the spec's own split (08 §4 and 05 §6.2).

2. **A repeated request for the same document, seq and kind (HIS-007 criterion 5; ADR 0118).** The store returns the version already stored and writes nothing. This applies to `named` as well, as ADR 0118 chose. Default taken.

3. **The `scopeHistory` method on the storage port (HIS-016, leftover).** `LogStore` declares `scopeHistory` as optional, the same way `byId` and `state` are declared. `ScopeCommit` moved to `src/storage/types.ts`; `log-store.ts` re-exports it so existing imports keep working. The memory store does not implement it yet.

4. **Source of the agent identity (HIS-017 criterion 1).** Not decided here. ADR 0118 leaves the source open (owner decision), and ADR 0234 (lane UX-040-052, proposed) proposes an `act` claim in the manner of RFC 8693. The token verifier in `services/document-service/src/control-plane/tokens.ts` does not read `act` today, so the criterion stays unticked. No code was written for it.

## Consequences

- HIS-006 criterion 1 stays unticked until the route exists. Its storage part is tested in `services/document-service/test/postgres/u-his-001-016-versions.pg.test.ts`.
- HIS-003 criterion 2 stays unticked until a CI workflow runs the existing PostgreSQL scans (`.github/` is root configuration).
- `document-service` needs a `@docedit/history` dependency before the route can pass `scopeHistory` to `fieldHistory` (a `package.json` change for the main session).

## Round 5 review of the next stories (HIS-014, HIS-015, HIS-011)

No criterion was ticked in this round. The blockers were read and are recorded here so the next round starts from them.

5. **Checkpoint carries the attribution map (HIS-014 criterion 4).** The room's checkpoint effect in `packages/authority/src/room/room.ts` (around `fx.checkpoints`) writes `seq`, `doc`, `reason` and `threads` only. Writing the map needs a change to the room, which other lanes edit, and the room load path from a checkpoint (BE-019) is not built. Default: stays unticked; the package-level round trip is what exists.

6. **Who-wrote answer and attribution route (HIS-015 criteria 1 and 2).** `withRunTimes` in `packages/history/src/who-wrote-times.ts` gives the authors with run times. The route `GET /documents/{id}/attribution` needs `document-service` to depend on `@docedit/history`, which is a `package.json` change for the main session. Default: stays unticked.

7. **Comparison field spans and object shape (HIS-011 criterion 2).** Already recorded in the story Notes: the spec does not give field spans a shape. Owner or spec decision, not taken here.

## Round 6 (HIS-009, HIS-010, HIS-012, HIS-013)

**Status:** proposed, 2026-11-13.

1. **HIS-012, criterion 7 (ticked).** Its Note named the spike HIS-043 as the blocker. HIS-043 is done (ADR 0118, round 6) with the recommendation to report moves as `moved` in both methods. `packages/history/test/compare.test.ts` "reports a moved block once, deterministically, in both methods" checks that exact output in both methods, for a move within a container and into another container. Determinism is shown by the exact expected output on a fixed input, not by a repeated run. Proposed reading, for the owner to confirm: a fixed expected output is enough for "deterministic".
2. **HIS-009, HIS-010, HIS-013 (not built).** Filtering and grouping exist as `listHistory` and the erased-author label as `labelHistoryItems` in `packages/history`. Missing: a `history` port on `CoreApi` (`packages/ui/src/core-api.ts`), the pane component, a loader from the host registry (`packages/ui/test/panes.test.ts` requires `history` to have no built-in loader), and a browser run in the shared UI harness (`packages/ui/e2e/harness`). No criterion of these three is ticked, because each describes what the user sees in the running editor. They need a UI lane with access to those files.
