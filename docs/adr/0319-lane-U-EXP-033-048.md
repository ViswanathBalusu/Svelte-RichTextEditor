# 0319. Lane U-EXP-033-048: sandbox route and the flatten seq test

Status: proposed

## Context

Lane U-EXP-033-048 (round 2) was asked to close the criteria of EXP-033 to EXP-048 that were blocked on the real environment. Two findings need the owner or the main session.

1. The export sandbox is not ready on this machine. `sandboxReady()` (`services/export-worker/src/sandbox-ready.ts`) reports `Podman's default mounts put /run/secrets into the sandbox`. The image `localhost/docedit-export-worker:s4` exists. On the direct route `podman info` is remote (Windows client), so `--default-mounts-file` is refused and the check fails. On the machine route (`podman-machine-default`, running), the `/usr/share/containers/mounts.conf` of the machine maps `/usr/share/rhel/secrets` to `/run/secrets`, and the readiness probe still reports host mounts. The lane did not change the Podman machine or its configuration. Every sandbox compile test in packages/export-latex and services/export-worker therefore skips on this machine. All criteria whose Evidence is a Podman compile (for example EXP-036 criterion 2 and 3, EXP-038 criterion 3, EXP-042 criterion 5) were not re-run in this lane.

2. The date pattern of a `date` field (EXP-033 criterion 2) uses the stored calendar date anchored at UTC noon, not the export job's time zone. This is the same open question as ADR 0115. The owner decides.

## Decision (proposed)

- Finding 1 goes to the main session: the Podman machine needs an empty default mounts file, or the readiness probe needs a route that passes `--default-mounts-file` on the machine. Root or environment configuration is not changed by this lane.
- EXP-033 criterion 7 is ticked on a Node.js test with a fake compile (`services/export-worker/src/exp-033-seq.job.test.ts`). The spec default is used: the job reads the content at its `seq`.

## Consequences

Compile-based criteria stay unticked until the sandbox route is fixed and the compile tests are run again.

## Round 8 (EXP-043, EXP-046)

Status: proposed.

- EXP-043 bookmark backslash (open question for the class owner). A heading whose text holds `\textbf` loses the backslash and the letter after it in the outline. The likely cause is that hyperref writes the bookmark as a PDF literal string without escaping its backslashes, so `\t` reads as a tab. Doubling each backslash in `\DE@strexp` (`class/docedit.lua`) fixes the outline but also changes the XMP `dc:title`, which is raw text, and breaks `pdfstring.compile.test.ts`. The change was reverted. The spec default is kept: the outline shows the heading as typed, so the test stays `it.fails`. Proposed: give the heading bookmark its own string path (the optional argument of `\DEh` through a macro that doubles backslashes), and keep the document title path unchanged. Not done in this round.
- EXP-046 trace level (open question for the owner). The other emitters now have a level-1 token trace in the sandbox (`exp-046-others.trace.compile.test.ts`). Whether level 1 meets criterion 2 ("a trace of the token stream") is the owner's decision. The criterion stays unticked until the owner decides. `generatedId` takes a counter, so it has no string batch.
