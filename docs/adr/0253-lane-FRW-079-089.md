# ADR 0253: lane FRW-079-089 (fields, rules and workflow, round 1)

**Status:** proposed. **Date:** 2026-11-13. **Lane:** FRW-079-089, round 1.

## Context

The lane was asked to take three to five stories from FRW-079 to FRW-089 that still have unticked criteria. Most of them are owner decisions (FRW-083 to FRW-087) or need node views, a browser run or a server that is not built. This round took FRW-080 and FRW-088 to the point where a test can say something, and recorded why the rest stay unticked. No root configuration was changed, and no install was run.

## Findings

1. **No default width for a field without `width` (FRW-080 criterion 3).** The schema (`packages/model/src/definition/fields.ts`) declares `width` as `null` with no default. The layout (`packages/layout/src/flow.ts`, `form_field`) lays a width-less field out as text, so its value reflows the surrounding line. The story asks for a fixed default declared with the schema. The value is an open question in the spec (12 §15, "the default width value"). No value is proposed here: the spec default is "none given", and a number is an owner choice. Needs the owner: the value, and what shows when a value is longer than the box (the same open question).

2. **Width-less fields still reflow (FRW-080 criteria 1 and 2 for fields without `width`).** Once finding 1 is decided, `flow.ts` must draw a width-less field with the default box as well. The current test `packages/layout/src/frw-080.fill-breaks.test.ts` pins the reflow only as a control, so it will need a new expectation when the default is set.

3. **The authority property for criterion 3 excludes null and object attributes (FRW-088).** `packages/authority/test/frw-088.unreadable-changes.test.ts` changes every string, boolean and number attribute of the sensitive field, and refuses each. Attributes stored as null or as an object (`default`, `validation`, `ext`, `format`) are not in the property, because a generic value does not satisfy their schema, so the step does not apply. The example test in `outcome.fields.test.ts` covers `default` and `assignee`. This is a test-side gap, not a product gap, and it closes when a typed value generator for the schema exists.

4. **The editor half of FRW-088 criterion 3 is FE-141.** The authority refuses changes; the editor must show the field as redacted. Not built here.

5. **FRW-079 needs node views (not built).** `packages/engine/src/schema.ts` declares `form_field`, but no node view, native control or keyboard handling exists in `packages/engine/src` or `packages/element/src`. Criteria 1 to 6 need those and a browser run for screen reader and axe. Nothing was ticked and no test was written that would stand in for them.

6. **FRW-089 criteria 2 and 3 are owner decisions.** Criterion 1 needs the authority's redaction and the editor's display. Nothing was changed.

7. **FRW-083 to FRW-087 are owner decisions.** The criteria begin "Given the owner decides". No decision was taken or drafted here; the spec defaults stay as they are in the stories.

## Decisions taken

- FRW-080: the breaks property test is added (`packages/layout/src/frw-080.fill-breaks.test.ts`); no criterion ticked, because the box width itself is not asserted and criteria 1 and 2 must say so.
- FRW-088: the authority property test is added (`packages/authority/test/frw-088.unreadable-changes.test.ts`); criterion 3 stays unticked for the editor half.
- No decision was made for any open question.

## Open questions for the owner or the main session

- The default width of a field without `width`, and what shows when a value is longer than its box (FRW-080 criterion 3; 12 §15, question 4).
- Whether the typed-value generator for the authority property should be added to `packages/model` or stay in the test (finding 3).

## Round 3 (2026-11-13)

- **FRW-089 criterion 1, rules part.** Added `packages/authority/test/frw-089.derived-hidden.test.ts`. A rule's `set` target computed from a sensitive value is redacted in a reader's projection once the closure from `derivedFromHidden` is in the hidden set; without the closure the derived value leaks. Criterion 1 stays unticked: mirrors, computed labels, `cached` text and the server evaluation are not covered.
- **Export needed (rules owner).** `derivedFromHidden` is not re-exported from `packages/rules/src/index.ts`; the test imports it by a relative path. Proposed: export it from the package index.
- **Owner decisions unchanged.** FRW-083 to FRW-087 remain owner decisions; no default was chosen here. FRW-079, FRW-080 and FRW-088 were handled in earlier rounds and are not repeated.
- **Story In progress line.** Added and removed on FRW-089 in `docs/stories/FRW-fields-rules-workflow.md`; the Evidence and Notes lines were extended there.
- **FRW-080, round 3 (box part of criterion 1).** Added `packages/layout/src/frw-080.box-width.test.ts`: at flow level a field with a `width` is one preserved inline box of that width (144 pt for 2880 twips) for every value, and the inlines do not depend on the value. The layout tree does not expose inline box widths, so the drawn box is not measured; criterion 1 and 2 stay unticked.
- **Not done this round.** FRW-079 criteria still need node views and a browser run (no `form_field` node view in `packages/engine` or `packages/element`). FRW-083 to FRW-087 are owner decisions. FRW-088 criterion 3 editor half is FE-141. FRW-089 criteria 2 and 3 are owner decisions. No root configuration changed, no install run, and the story-check and progress scripts were not run, as the lane rules require.
