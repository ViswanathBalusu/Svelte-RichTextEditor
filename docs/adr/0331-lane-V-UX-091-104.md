# ADR 0331: decisions of lane V-UX-091-104

Status: proposed (lane V-UX-091-104, round 1, 2026-11-13). Owner decisions are not made here.

## 1. Event name for an access request (UX-104 criterion 2)

Context. The shell calls `onAccessRequest({ scope })` when a reader asks for access to hidden content
(`packages/ui/src/App.svelte`). The element did not pass that callback on, so `<doc-editor>` never
raised an event for the host. The spec (05 section 8.1) lists no event for this, so the name is open.

Decision (spec default for an open name: the existing `de-*` pattern, identifiers only).
The element raises `de-access-request` with `{ docId, scope }`, through `emit`, bubbling and composed,
like `de-share-request`. It is raised only by the current session, as the share request is. The
editor sends nothing itself; the host decides who answers.

Consequence. The element now always gives the shell an `onAccessRequest`, so the "Ask for access"
control appears in the status notice for hidden content in every mounted element. Whether it should
appear only when a host listens is open; the spec default (show the control) is used here.

Files: `packages/element/src/events.ts`, `packages/element/src/editor.ts`,
`packages/element/src/doc-editor.ts`, `packages/element/test/access-request-events.test.ts`.

## 2. What is not decided here

- The element event is not in the catalogue of 05 section 8.1. 05 needs an amendment if the owner accepts
  the name.
- Whether a reader's request should carry a reason or a recipient: not asked, not added.

## 3. UX-097 criterion 1: the audit entry for an accepted commit (round 1, 2026-11-14)

Context. UX-097 criterion 1 asks that the commit and the audit entry of a prefill with `DEP-Actor`
name the person's surrogate, with the commit's origin. The commit half now holds on the running demo
stack: `apps/reference-host/test/v-ux-097-attribution.stack.test.ts` (PostgreSQL in Podman, the
document service on the lane's ports) reads the prefill's row in `doc_commits` with the surrogate and
origin `prefill`, and a prefill without `DEP-Actor` with `system`. The audit half does not hold: the
audit store records only rejections (07 section 14; `services/document-service/src/data-plane/audit.ts`),
and the `audit_events` table has no row for an accepted commit.

Open. Whether accepted content-changing commits belong in the audit trail, or only in the history (08
section 2), is not decided by 07 section 14. Adding an audit event per accepted commit would be a new
product decision, and it would write document activity to a table that is append-only and tenant
scoped.

Decision taken here: none. The criterion stays unticked. Spec default for the question: no change to
the audit store in this lane. The owner (or the spec owner for 07 and 08) decides whether accepted
commits are audited, and with what fields.
