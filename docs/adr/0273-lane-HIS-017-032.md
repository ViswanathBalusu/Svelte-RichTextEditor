# ADR 0273: Open points of the HIS-017 to HIS-032 lane (round 2)

**Status:** proposed (2026-11-13, lane HIS-017-032). Nothing here is decided by the lane; each point
keeps the spec default or stays unticked until the owner or the maintainer decides.

## Context

Round 2 of lane HIS-017-032 ticked HIS-024 criterion 4 (a walk of the protocol definition against
`SEQ_INPUTS`, `services/document-service/src/data-plane/his-024-seq-walk.test.ts`). While reading the
remaining criteria, these points were found that the spec leaves open or that need a decision.

## Points

1. **Weekly thinning boundary (HIS-030 criterion 1).** 08 §11 says checkpoints are kept for 30 days,
   then thinned daily, then weekly. It does not say when daily becomes weekly. `thinningPlan` takes
   `weeklyAfterMs` with no default. The spec default is not given, so no value is chosen here. The
   criterion stays unticked until the owner names the age.

2. **Attribution runs from below the gate (HIS-026 criterion 3).** At a visible version,
   `attributionFor` (`packages/history/src/reader.ts`) still returns runs whose author and `seq` belong
   to commits below the gate (probe in `gate-negative.test.ts`). The criterion says the response
   "contains nothing from below it", which allows at least two readings: drop such runs, or report
   them under an unknown person. The code is not changed by this lane. Choosing one changes the
   attribution API, so it is for the maintainer.

3. **`since_access` boundary (HIS-025 criterion 4).** Already recorded in HIS-025 Notes and ADR 0145
   §8: the gate admits the last commit at or before `access_since`, the criterion says the first at or
   after it. Unchanged here.

4. **Route `attribution` takes no `atSeq` (gap G68).** `SEQ_INPUTS` lists `GET /documents/{id}/attribution`
   `query.atSeq`, but the definition (`packages/protocol/src/definition/resources.ts`) has no such member.
   The walk test names this one exception (`NOT_IN_DEFINITION`) and fails on any other listed input the
   definition lacks. The protocol owner must add the member or remove the entry.

5. **Stale note in HIS-024.** Its Notes say `visibleFrom` in the control plane holds its own copy of the
   rule. A search of `services/document-service/src/control-plane` in this round found no `visibleFrom`;
   the control plane calls `minVisibleSeqOf` (`gate.ts`). The note has been left as it was, to be checked
   by the owner of HIS-024. Criterion 1 is not ticked on this lane.

## Consequences

- HIS-030 criterion 1 and HIS-026 criterion 3 stay unticked.
- HIS-025 criterion 4 stays unticked.
- No code changes follow from this ADR until it is accepted.
