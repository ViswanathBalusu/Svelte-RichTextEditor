# ADR 0216: Webhook retry schedule and open points of lane PRO-071-084

Status: proposed (2026-11-13). Owner decision pending.

## Context

PRO-071 criterion 1 asks for retries "with exponential delay for up to 24 hours (a target; the kit
uses test-mode timers, PRO-109) and then abandoned". 05 §7 and 10 §3.2 give the window and the
word "exponential", but no base delay and no growth factor.

## Decision taken in the code (proposed)

- `services/document-service/src/control-plane/webhook-dispatcher.ts` takes an optional
  `RetryPolicy` with three inputs: `baseMs`, `factor` and `maxAgeMs`. The window is exported as
  `RETRY_WINDOW_MS` (24 hours, the stated figure).
- The delay before send `k + 1` is `baseMs * factor^(k - 1)`. A send is only scheduled when it
  would fall no later than `maxAgeMs` after the row was created; otherwise the row stays `failed`.
- Retried failures: a timeout, a transport error, an unresolved name, or a non-2xx answer. A
  refusal by the egress policy is not retried.
- Every send of a row carries the row's `webhook-id` (PRO-071 criterion 2).
- No default base delay or factor is chosen. A composition that wants retries must pass them. The
  running service passes none, so it does not retry. This leaves the owner's choice open.

## Open points for the owner

1. The base delay and the growth factor. Options: a base of one minute with a factor of two (about
   fifteen retries inside 24 hours), or values taken from the reconnection backoff in
   docs/spec/05-protocol.md (0.5 seconds doubling to 30 seconds). Neither is stated for webhooks,
   so neither is the default.
2. Whether `retryable` should include a 429 or 503 answer with `Retry-After`. Not done.
3. Whether a replay of an abandoned row resets the window. The code keeps the original creation
   time, so a replay after 24 hours is refused the retry it would otherwise get.

## PRO-080 criterion 2: searchPrincipals forwarding (round 4, proposed)

- packages/element/src/editor.ts passes searchPrincipals to the shell as a wrapper that reads the
  element's current property on each call. With no callback set, the wrapper answers an empty list.
  The spec does not say what the grants pane shows without a directory; an empty list is the
  proposed default, the owner may choose otherwise.
- The element passes docId (the document it was loaded with) as the shell's docId, which the
  pane sends as PrincipalQuery.docId.
- Still open: a browser test of the grants path and the mention path, and a check that the callback
  receives identifiers and a search string only (PRO-080 criterion 4 already holds by construction).
