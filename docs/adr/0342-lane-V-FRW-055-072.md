# ADR 0342 (lane V-FRW-055-072): form field insertion and prefill idempotency

**Status:** proposed, 2026-11-13. Owner decisions are the owner's; the defaults below are the lane's and are listed for confirmation.

## Context

Lane V-FRW-055-072 closes the criteria of FRW-055 to FRW-072 that were blocked on a container, a browser or another package. Two questions in the range were left open by the spec or the backlog and were not decided silently.

## 1. The palette inserts form fields (FRW-072 criterion 1)

The palette's `insert.field.<kind>` commands pass `{ kind }` to `insertField`. The engine's `insertField` took only the page kinds (`page`, `pageCount`, `date`, `title`), so no form field could be inserted.

Decision (default, proposed):

- The form kinds of phase 1b, `text`, `number`, `checkbox` and `choice`, are inserted by `insertField` through `packages/engine/src/frw-072-form-fields.ts`.
- The key is `<kind>_<n>`, for the least `n` that no form field of the document uses. It matches the CDM key grammar (`FIELD_KEY_PATTERN`).
- The label is the kind and the number, such as `Text 1`. The identifier is null and the identifier plugin fills it.
- The document must require `fields`, and the field must not be in a header, footer or footnote (I10).
- The element shell now answers `canInsertField` (through the core) and runs `insertField` with `{ kind }` (`runNamed`, `commandNames`).

## 2. The kind `date` (open, not decided)

`date` is both a page date field (FE-136, body text, needs a server instant) and the palette's form date. The same name cannot name both. This lane keeps `date` as the page date. A palette `date` therefore is refused without a date source. Options for the owner:

- (a) a separate argument for the form kind, for example `{ kind: 'date', form: true }`, changed in the palette and in `CoreApi`;
- (b) a distinct name for the form kind, for example `formDate`;
- (c) defer the form date (phase 1b lists it, so (c) needs the owner's agreement).

## 3. Prefill and `Idempotency-Key` (FRW-061 criterion 6, open)

The prefill route does not accept `Idempotency-Key`: its protocol definition sets no `idempotencyKey` flag (`packages/protocol/src/definition/frw.ts`), and 05 §6.1 names POST requests. A repeat of an applied prefill is refused by its stale If-Match (412), so one commit is written. The criterion names the key, so this stays open.

Options for the owner or the protocol owner:

- (a) keep the current behaviour and reword criterion 6 to say that a repeat is refused by If-Match;
- (b) set `idempotencyKey: true` on the prefill route, then regenerate the protocol artifacts (`pnpm generate`) and the OpenAPI document, and let the replay return the stored answer.

The lane did not change the protocol definition, because the artifacts under `spec/` are generated and the regeneration runs at the root.

## Consequences

- `packages/engine/src/fields-toc.ts`, `packages/engine/src/core.ts`, `packages/engine/src/api.ts` (the field kinds and the query `canInsertField`) and `packages/element/src/editor.ts` (`runNamed`, `commandNames`) changed with small exact edits.
- A browser run of the palette needs a demo page with the full shell and a document that requires `fields`. The element's spike page has neither.

## Round 2: FRW-056 criterion 5 (2026-11-13)

Status: proposed. Lane V-FRW-055-072, round 2.

Decisions taken, none of them an owner decision:

1. The renewal handler (`services/document-service/src/control-plane/jobs/workflow-renewal.ts`) runs the pure rules of `@docedit/authority` as a `workflow.renewal` job. The lead time has no default: it is a parameter, as the spec gives no value.
2. "One time-stamp per expiry" rests on two guarantees: the queue's `ifAbsent` job per document and expiry, and a compare and set on the expiry in the store. The test store is a PostgreSQL table made in the test database only. The production store and its migration belong to the workflow service and are not built.
3. A race between two runs can call the signing service twice. Only one renewal is recorded; the second time-stamp is not added to the chain. Whether the signer should be asked at all once a renewal is in flight is open, and is proposed for the signing owner to decide.
4. `packages/authority/src/index.ts` now exports `planRenewal` and `applyRenewalResult`, a small exact edit so that the service can import them.

Not decided here: the operator alert channel for a failed renewal. The failed job and its recorded error are the only visible signal.
