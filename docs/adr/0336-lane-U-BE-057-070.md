# ADR 0336: Lane U-BE-057-070 decisions (proposed)

Status: proposed. Owner decisions are not made here.

## Shared rate-limit store falls back to local buckets (BE-063 criterion 4)

The spec (06 §4.3, §8) says losing Redis or Valkey degrades presence and forwarding, and never data.
It does not say what rate limits do. This lane chose the following, as a proposal:

- Each take goes to Valkey as one Lua script over a hash per bucket (`valkey-buckets.ts`).
- When Valkey cannot be reached within the timeout, the take answers from a local token bucket with
  the same settings, and counts itself as `degraded`.
- The alternatives are to fail open (admit everything) or to fail closed (refuse). Failing open lets
  a noisy client through; failing closed refuses honest editors because of an infrastructure fault.
  The local fallback keeps each node's own limit in force, so the owner should confirm it.

Owner decision needed: confirm the local fallback, or choose fail-open or fail-closed.

## Clock source of shared buckets

The caller passes its own clock to the script. Nodes whose clocks differ see slightly different
refill. A server-side `TIME` inside the script would remove the skew but ties the script to a
Valkey version; this lane did not take that step. Owner or operator decision if skew matters.

## Test environment note (Podman on WSL)

On the WSL Podman machine a published port is a DNAT rule that Windows loopback cannot reach. A
test container that must be reached from the host runs with `--network host` and binds
`127.0.0.1`, as `infra/test-env.ps1` does. `--cgroups=disabled` was needed because the pids
controller is not delegated to the container. This is an observation for the infrastructure owner,
not a change to `infra/`.
