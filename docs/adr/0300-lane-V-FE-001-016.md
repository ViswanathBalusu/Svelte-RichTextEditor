# ADR 0300: Lane V-FE-001-016 decisions (proposed)

Status: proposed. Date: 2026-11-13.

## Context

Lane V-FE-001-016 closes the criteria of FE-001 to FE-016 that earlier lanes left open for a browser run.

## Decision 1: read violations before the screenshot in the FE-015 nonce test

FE-015 criterion 2 asks that the nonce fallback reports no violation. In WebKit, one
`style-src-elem` inline report appeared under the nonce-only policy. A probe with the same policy
showed no report while the editor was mounted and before any screenshot, on either path. The report
appeared after Playwright's `element.screenshot()`, which injects its own inline style in WebKit.
The test now reads the violations before the screenshot and keeps the pixel comparison.

Consequence: violations raised by the screenshot step itself are not checked. The editor's own
rendering is checked before and after the comparison only through the pixel result. The owner may
prefer a screenshot method that does not inject styles; that is a test-harness choice, not a product
one. Spec default kept: no violation from the editor.

## Open for others

- FE-016 criterion 5 second half: the paste parser's `innerHTML` runs under ProseMirror's own
  `ProseMirrorClipboard` policy name. A project-owned policy needs the paste handler of FE-054.
- FE-012 criterion 4 and FE-005 criteria: need a reconnecting channel. Not built in this lane.

## Decision 2 (round 2): FE-011 hides the page in the test, not in the browser

Playwright keeps every page visible: a second page brought to the front leaves the first one
isible (measured on Chromium, the test failed on that check). The FE-011 e2e test therefore
overrides document.visibilityState and document.hidden in an init script and dispatches a real
isibilitychange event. The element's listener and the flush run as in a real hide; the hidden
state itself is simulated. Criterion 3 is ticked on this run; criterion 1 stays open because no
browser test makes a journal write pending when the page is hidden.

## Decision 3 (round 2): FE-009 browser test is marked fixme

The sync session never reads the journal when a document opens, so a commit journalled before a
kill is not resubmitted (FE-009 is not built). packages/element/e2e/fe-009-resubmit-reopen.spec.ts
runs the scenario and is marked 	est.fixme with the reason, so that the element suite stays green
until the resubmission is built. Criteria 1 to 6 of FE-009 stay open.

## Open for others

- FE-009 criterion 2 (a commit stored before the kill, acknowledgement lost): the embed's backend
  keeps each page's service in memory, so a second tab does not see the first tab's stored commits.
  A test needs a service shared between tabs (a backend fixture with storage), not built here.
- FE-009 criterion 6 (an entry journalled for another document is not submitted): engine-level
  test possible; not written in this round.

## Round 3 (2026-11-13): FE-005 criterion 1 and FE-008 criterion 4

Status: proposed.

- Focus on a same-task move (FE-005 criterion 1). The browser blurs the focused editor while the
  element is still connected and drops the selection with the removed subtree. The element keeps
  a flag that focus is inside its shadow root. The flag clears when focus goes to another element
  (a focus-out with a related target) or on a press outside the element. On connect, focus goes
  back to the editor only when the flag is set and nothing in the shadow root has focus. This is
  a proposed decision: the spec does not say what should happen to focus on a move.
- Scroll on a same-task move. The editor has no scroll container of its own (shell.css); the page
  scrolls, and a same-task move keeps the page scroll. No element code restores scroll.
- Save state, connection down (FE-008 criterion 4). The engine reads unsaved while the channel
  reports resuming and a commit is unconfirmed (existing engine rule, now tested in
  packages/engine/test/fe-008-unsaved.test.ts). Not decided: whether a commit an online channel
  cannot answer should read unsaved before the acknowledgement timeout. The spec says so for
  "database unavailable"; the timeout and the answer that counts as "cannot acknowledge" are
  owner or spec decisions, so the criterion stays open.
