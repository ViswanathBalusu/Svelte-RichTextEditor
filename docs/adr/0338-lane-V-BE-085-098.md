# 0338: Lane V-BE-085-098 decisions (proposed)

Status: proposed. Owner decisions stay with the owner. Each item below uses the spec default, or
records that the spec is silent.

## 1. Fonts manifest is outside the read-restriction sweep (BE-098 criterion 3)

`GET /fonts` (05 section 6.2) answers the tenant font manifest to any caller with a user or service
credential. It is not a read of a document, so it has no document to project and was left out of
`services/document-service/test/control-plane/be-098-read-sweep.test.ts`.

Spec default used: the manifest is tenant-scoped, not per document. Open point for the owner: confirm
that a user of a tenant may read the whole manifest, including font families licensed for the tenant
only. If not, the route needs a visibility check and the sweep should include it.

## 2. Bare identifiers in the read sweep

`/threads/{tid}`, `/exports/{jid}` and `/imports/{jid}` are sent with a random identifier by the sweep.
The stranger is refused as not found. Refusal of a real thread or job for a stranger is covered by the
route tests of EXP and PRO, not by the sweep. Spec silent on whether a not-found answer and a
forbidden answer must be indistinguishable; the sweep accepts either as a refusal.

## 3. Windows of the live-use quota gate (BE-091)

The spec gives no figures for the commit-rate window or the retry delay of a count quota (06 section
12). The node composes the gate with `LIVE_QUOTA_WINDOW_MS` (60 000 ms) and `LIVE_QUOTA_COUNT_RETRY_MS`
(1 000 ms) in `services/document-service/src/control-plane/live-quotas.ts`. These are settings of this
lane, not spec values. Spec default used: none invented beyond these two settings; the owner confirms or
replaces them.

## 4. Refusal at hello and at commit (BE-091 criterion 1, socket)

A connection over the `connections` quota is refused at `hello` with `error` `quota_exceeded`,
`retryAfterMs` and `fatal: true`, and the socket closes with the close code the registry maps
`quota_exceeded` to. A commit over the `commitRate` quota is answered `sync.reject` `quota_exceeded`
with `retryAfterMs` and is not submitted; a commit counts against the rate when it is attempted, including
one the room would later reject. Spec silent on whether an attempt counts; the attempt is the default.

## 5. Export concurrency is queued, not refused (BE-092 criterion 3, open)

The code claims export jobs per tenant up to `exportTenantConcurrency` and queues the rest
(`src/control-plane/jobs/queue.ts`, `defaultLimit`). `docs/adr/0246-lane-BE-092-098.md` proposes
`quota_exceeded` instead. The two differ. Not decided here: BE-092 criterion 3 stays open until the owner
chooses one. The queue is the behaviour that runs today.

## Round 3 (BE-086, BE-087, BE-088): status proposed

Decisions made where the spec is silent (for review; the owner decides any that matter):

1. Control-plane series carry the node. `Metrics` takes the node as a base label, set in `src/server.ts`; the tenant read keys of `TenantMeter.read` skip `node`, so quotas keep their keys.
2. A validation or parse error is logged as its path and rule (`violationSummary`, `src/log.ts`). A key the client chose is written as `(key)`, never as the key.
3. A job carries its request's trace in its payload (`traceparent`), so the job row keeps its shape. The worker records a `job.run` span under it. The payload is returned to the tenant, so the trace identifiers are visible to that tenant.
4. A restore passes the request's trace to `replaceContent`, so the outbox item, the room and the checkpoint share the trace.

Left open: BE-088 criterion 1 (data-plane error lines carry no tenant, document or session), which needs the context of each `onError` call in `src/data-plane/`.
