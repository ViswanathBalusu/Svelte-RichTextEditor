# 0250. Lane FRW-040-052, round 1: decisions taken where the spec is silent

Status: proposed (2026-11-13). Written by the developer of lane FRW-040-052. Nothing here is an owner decision; each item uses the default the spec gives or the one stated, and the owner confirms or changes it.

## Decisions in the code

1. **Items that apply to each participant kind (FRW-040 criterion 4).** `packages/authority/src/workflow/participant-evidence.ts` gives a `filler` and a `signer` every evidence item. An `approver` gets no consent acceptance, no adoption and no signing, because 12 §6.1 says an approver "approves or declines without fields" and 12 §8.1 places the consent before the signing ceremony. An approver keeps `completedAt`, since approving is completing (FRW-047 criterion 7). A `cc` gets no completion, because 12 §6.1 says a `cc` "receives the result". Default in code: none of these items is invented for a kind that lacks it. Question: whether an approver accepts the consent text before approving.

2. **Default of `finalisation.certificate` (FRW-049 criterion 5).** The spec gives the option in the workflow definition (12 §6.1) and an example set to true, but no default. `packages/authority/src/workflow/final-export.ts` reads an absent option as false, so no certificate pages are appended unless the workflow asks for them. Question: owner decision on the default.

3. **Approver and consent (FRW-044 Notes, unchanged).** Recorded as item 1 above; the consent endpoint is not built.

## Not decided here

- The instant the retention clock starts from (FRW-043 Notes).
- Whether a changed consent text refuses an earlier acceptance (FRW-044 Notes, ADR 0148 item 1).
- The retry policy when the signing service is down (FRW-052 criterion 5; Open questions 26).
