# ADR 0317: Lane U-EXP-001-016 decisions (EXP-009 compile-minute budget)

Status: proposed. Owner: the export lane. Decided by the lane, to be confirmed by the owner.

## Context

EXP-009 (phase 2) asks for a monthly compile-minute budget per tenant. The spec leaves open whether previews count, whether the refusal covers previews, and what a budget that is not set means. Owner decisions stay with the owner; the lane records the spec-default reading below.

## Decisions

1. Previews count. The worker time of every settled export and preview job counts against the tenant of the job (`CompileBudget.record`, wired from the `metered` hook in `src/server.ts`).
2. The refusal covers previews too, and it is checked before a cached answer is given (`createExport` in `src/control-plane/export-routes.ts`). A refused request gets 429 `quota_exceeded` with `Retry-After` and creates no job.
3. A budget that is not set (`null`) is no limit. The spec gives no figures, so no default is chosen (`CompileBudget.refusal`).
4. The month is the UTC calendar month. `Retry-After` is the number of whole seconds to the first instant of the next UTC month.
5. The ledger is in memory. It is lost on restart. A durable ledger and the administration write path of the budget (UX-076) are not built.

Lane w2, 2026-11-21: where the minutes are counted (items 1 and 5) is replaced by [ADR 0422](0422-w2-EXP-009-compile-minutes-from-the-queue.md), proposed. The job queue now measures the worker time and keeps it with the job. Items 2 to 4 stand.

## Consequences

- EXP-009 criteria 1 and 2 are ticked. Criteria 3 (budget raised through the administration API) and 4 (usage read) stay open until UX-076 exists.
- Owner question: should previews be exempt from the budget, so that the preview path cannot be starved by a spent export budget? The lane follows the reading "every compile counts".

## Round 4 decisions (EXP-005, EXP-015)

1. The options join the bundle hash (EXP-005 criterion 6). The hash is the SHA-256 of the file lines and a `#options <digest>` line, where the digest is the SHA-256 of the canonical JSON of `manifest.options` (`packages/export-latex/src/bundle-hash.ts`). The converter and the worker's `verifyBundle` use the same function. Spec default: the criterion states that the options are part of the hash. This changes the bundle hash of every existing bundle. It is the step ADR 0221, item 1 asked a joint decision for; the owner should confirm it.
2. The defaults of `locale` and `timeZone` (EXP-005 criterion 4) are not chosen. `spec/dep/dep-1.openapi.json` gives `locale` a pattern and `timeZone` no default, so "the defaults of the published schema" name no value. The manifest records `timeZone` as `''` when unset and no `locale` at all. Owner or spec decision.
3. The class release rule is checkable (EXP-015 criterion 4). `packages/export-latex/src/exp-015-class-release.test.ts` pins `CLASS_VERSION` and the SHA-256 of `docedit.cls` and `docedit.lua`. A class edit now fails until the version and the pin are changed together. This is deliberate friction, and the pin must move in the same change as the version.
4. The kitchen-sink compile (EXP-015 criterion 1) uses the worker image's TeX Live. This lane did not check that image against the "pinned" TeX Live 2026 named in the criterion.
5. Environment note, not a decision: on this host `sandboxReady()` did not select the machine route (`podman-machine-default`) by itself, and the sandbox tests skipped with the host-mounts reason. They ran with `DOCEDIT_PODMAN_MACHINE=podman-machine-default` set. The main session should check the automatic detection in `services/export-worker/src/sandbox-ready.ts`.

## Round 4 review: EXP-003, EXP-012, EXP-013, EXP-014 (no criterion ticked)

The lane checked the open criteria of these four stories. None of them is blocked on PostgreSQL, object storage, a container or a browser, and none could be closed with a test this round. Each open point needs a decision or a product change that is not the lane's to make.

1. EXP-003 criterion 1 (a table row taller than a page). The spec does not say how the preflight learns a row's height before anything is typeset (`src/preflight.ts` header). The detection rule is open. Spec or owner decision.
2. EXP-003 criterion 2 (the editor runs the shared preflight). The editor call would sit in `packages/element` or `packages/ui`, which this lane does not own. Criterion 1 is also open. Stays open.
3. EXP-012 criterion 2 (footnote, header and footer text, split-table rows). `footnoteText` in `src/inline.ts` puts the footnote body inside the host paragraph's lines, and `line()` in `src/context.ts` owns every line by its paragraph. A fix needs a per-segment owner in the converter. It changes `map.json` and must be checked by a compile (the class sets `\DEfntext` in the paragraph body, `class/docedit.cls`). No compile was run this round. Spec default: footnote text owned by its footnote.
4. EXP-013 criterion 5 (a flattened style equals the cascade of 03 §6). The macro carries eleven setters. Spacing before and after, keep with next, page break before and contextual spacing are not in it. Whether a flattened style must carry them is open (ADR 0221).
5. EXP-014 criterion 2 (an SVG asset converted to PDF on upload). `services/asset-worker/package.json` names only raster codecs (jpeg-js, omggif, pngjs). Nothing in `services/asset-worker/src` writes PDF. Choosing the SVG-to-PDF converter and adding its dependency is an owner decision and needs the main session for the root `package.json` and `scripts/pnpm-locked.ps1`.
