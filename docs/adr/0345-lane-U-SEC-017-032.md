# ADR 0345: Open questions decided by lane U-SEC-017-032

Status: proposed. Owner decisions are not made here; each item uses the spec default or the reading
the story Notes give, and the owner may change it.

## 1. A deleted record is named at the record after the gap (SEC-029 criterion 1)

The spec does not say which `seq` is "the first broken seq" when a record is deleted. The chain
verifier (`PgLogStore.verify`) sees the gap at the record after the deleted one and returns that
`seq`. The test sec-029-db-tamper.test.ts asserts that value. An owner who wants the deleted `seq`
named instead should change the verifier and the test together.

## 2. The memory grant store writes no audit rows (SEC-030 criterion 2)

The PostgreSQL grant store writes a `grants.changed` audit row in the change's transaction
(storage/grant-store.ts). The memory grant store does not (storage/memory.ts). The SEC-030 test
checks the audit row on PostgreSQL only. Whether the memory deployment must audit grant changes is
open; the default here is that the audit trail is a PostgreSQL property (BE-014).

## 3. The "owner" of a region state change is the service credential (SEC-030 criterion 2)

The region state route is guarded by `manage`, and the test makes the change with the tenant's
service credential, which holds `manage`. A user-level owner token is not used.

## 4. Workflow changes are not in the control-commit test (SEC-029 criterion 3)

No workflow is built. The test proves permission changes (grants and the document state
`locked`) as control commits. The workflow half of criterion 3 stays open until workflow exists.

## Round 2 (lane U-SEC-017-032, 2026-11-13)

Status: proposed. Decisions the spec leaves open, recorded here and not decided silently.

1. SEC-028 criterion 5. The authority fuzzer (packages/authority/test/fuzz.test.ts) keeps its existing per-input limit of 2000 ms (`FUZZ_INPUT_MS`). It is a proposed default. The spec gives no value (see ADR 0256, item 4). An over-limit input now fails the property and is stored as JSON under packages/authority/test/slow-inputs/. The owner should confirm or change the value.
2. SEC-020 criterion 6 (logs). The logs half is proved; the metrics half is not, because the dispatcher writes no webhook metric. Whether a webhook metric is wanted is open.
3. SEC-019 criterion 4 (thread author over the wire) is blocked: the thread and comment routes of PRM-037 are listed in data-plane/gate.ts but no handler is served. Building them is product work and is not done in this lane.
4. SEC-018 criterion 1 (per-address limit before authentication) is blocked: no per-address admission exists in services/document-service. The loopback test host cannot show that other addresses connect normally. Recording the spec default here: none is given by the spec.
