# ADR 0353: lane V-CDM-028-053, local LaTeX compile and open placement questions

**Status:** proposed. Owner decisions stay the owner's; the spec default is used where one exists.

**Context.** Lane V-CDM-028-053 closes the CDM-028 to CDM-053 criteria that earlier lanes left open because they needed a real environment. Round 1 covers CDM-044 and CDM-045 on the LaTeX side.

## 1. Local LaTeX compile instead of the export worker's sandbox (for tests only)

The export worker's compile sandbox (EXP-070; `services/export-worker/src/sandbox-ready.ts`) cannot start on this host. The Podman machine of this Windows host fails for every container that uses cgroup limits (`crun: controller pids is not available under /sys/fs/cgroup/...`), and a plain `podman run` fails with the same controller error. `sandboxReady()` therefore reports `ok: false`, and every sandboxed compile test skips.

Round 1 adds `packages/export-latex/test/cdm-local-tex.ts`: it converts with the local font copy (`services/export-worker/out/fonts-local/`, each face checked against its SHA-256, as `imageFonts()` does) and runs TeX Live's `lualatex` in a fresh temporary directory, two passes, `--no-shell-escape`, with `DOCEDIT_FONT_PATH` set to the font directory. It is used only by tests on bundles that the converter wrote from fixture documents. It is not a product path and does not replace the sandbox. The binary comes from `DOCEDIT_LUALATEX` (default `lualatex` on the PATH); the tests skip when it does not start. `pdftotext` comes from `DOCEDIT_PDFTOTEXT`.

Proposed: keep the sandbox as the only compile path in the product. The owner or the infrastructure lane should fix the Podman machine (cgroup controllers) so that `sandboxReady()` passes here and in CI, after which the sandboxed variants of these tests can replace the local harness.

## 2. Twip convention (checked, no change)

The class (`packages/export-latex/class/docedit.lua`, `SP_PER_TWIP = 65781.76 / 20`) and the model define a twip as 1/20 bigpoint, that is 1/1440 inch, which matches Word's twip. TeX's point (1/72.27 inch) is not used for model lengths. A test that converted twips with 1/20 TeX point measured a 0.375 % error that grew with the header height; that was the test's error and is fixed.

## 3. Degenerate body: no room left (CDM-045, `nothing-left-for-the-body`)

The fixture `packages/model/fixtures/semantics/header-growth.json` gives, for a header of 9000 twips and a footer of 9000 twips, a body start at 9708 on page 1 with a body height of 0. TeX sets the first body line on page 2 at the same top. The LaTeX test accepts that placement. The layout engine's test (`packages/layout/src/cdm-045-header-growth.test.ts`) does not run frames with no room.

Open for the owner: whether a page with no room for the body should carry an empty body on page 1 (the fixture) or move the first line to the next page (the LaTeX class). The spec default is not stated in 03 §7; ADR 0032 §6 leaves the rest to pagination. Until the owner decides, CDM-045 criterion 3 stays unticked.

## 4. Leaders on the LaTeX side (CDM-044)

The LaTeX tab test (`packages/export-latex/src/cdm-044-tabs.test.ts`) uses `leader: none` for every case, because a leader's dots would merge into the words that `pdftotext -bbox` reads. Leaders are therefore not measured on the LaTeX side. Stop positions (left, right, centre, decimal and default or hanging stops) are measured, and CDM-044 criterion 4 is ticked on that basis. The leader kinds stay a gap to close with a raw-text or content-stream reader (EXP-032 already reads the rules this way).

## 5. Not measured

- The body's end (`bottom`, `height`) of the header-growth frames: the layout report has no end of the body.
- Decimal stops inside justified text (CDM-046 reports them as approximate).
- CDM-043 (paragraph gaps): the LaTeX side of the six body pairs is still checked only in the source (`\DEgap`, `packages/export-latex/src/cdm-043-fixtures.test.ts`), not in the PDF.

## 6. Owner or infrastructure needs (not decided here)

- Podman cgroup controllers on this host, so `sandboxReady()` can pass (see 1).
- A CI job that compares generated schemas across two releases of one `cdm` major version (CDM-048 criterion 5). Root `.github/` configuration is outside this lane.
- A second `cdm` version before any migration can be written or tested (CDM-049 criteria 1 to 4 and CDM-050 criteria 1, 3, 4 and 6). This depends on the roadmap, not on the environment.
- CDM-050 criterion 2 (commit stamp with the `cdm` version and an engine and package identifier): the room stamps `cdm` and `engine` in `packages/authority` (`room/types.ts`, `room.ts`). Whether the model package or the authority package must expose it is for the owner. Not changed in this lane.

## 7. Round 8 (lane V-CDM-028-053)

- CDM-043 criterion 5, LaTeX side, now run in the PDF: `packages/export-latex/src/cdm-043-gap-compile.test.ts` compiles the six body pairs of `paragraph-spacing.json` with the local `lualatex` and reads the paragraphs' blocks from `main.layout`. The gap is measured against a zero-spacing reference of the same paragraphs. All six pass within one twip. The line-height cases, the container flows, the footnote pair and the table pairs are still not run, so CDM-043 criterion 5 stays unticked.
- CDM-042 criterion 6 (DOCX labels as literal text): the DOCX writer still writes Word's native numbering (`w:numPr`, `w:numFmt`, `w:lvlText`). The spec asks for literal text and no counters of their own, but native lists are what keeps Word lists editable. Open for the owner: literal labels (a writer change that gives up native lists) or native lists (a spec change). Not decided here; criterion 6 stays unticked.
- CDM-050 criterion 2: the room stamps `cdm: 1` and `engine: 'pm-steps/1'`; no package version identifier exists in any package. Open for the owner: which package version identifier a commit carries, and where it comes from. Not decided here.
- CDM-041 criterion 5 (shared cascade fixtures in the layout, LaTeX and DOCX): not started in this round; the writers do not expose resolved values in a form the fixture can compare.
