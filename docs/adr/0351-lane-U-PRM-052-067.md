# ADR 0351: Lane U-PRM-052-067 (PRM-permissions, unblock round 1)

Status: proposed (2026-11-13). Written by the developer of lane `U-PRM-052-067` in round 1. The owner decides whether the recommendations below become the rules. Until then, the spec's text stands.

## Context

The lane closes blocked criteria in `docs/stories/PRM-permissions.md` (PRM-052 to PRM-067) with tests against the real PostgreSQL in the integration environment (`infra/test-env.ps1`). This round it took three stories: PRM-052, PRM-057 and PRM-058.

## Decisions taken by the lane (spec default, to be confirmed)

1. **Actor of a revocation.** A `POST /v1/sessions/revoke` made with the tenant's API key has no `DEP-Actor`, so its actor is `system` (`Caller.actor`, 08 §13). A revocation with a `DEP-Actor` header records that surrogate. The spec does not name the actor of a host call; this is the default.
2. **Subject of a revocation.** The entry names the revoked user by the per-tenant surrogate in `data.subject`, never by the host's identifier (ADR 0102, identifiers only). `GET /audit` does not project `data`, so the subject is visible to the store and not to the route. Whether the route should show it is open (07 §14 does not say).
3. **Where the revocation test lives.** The asset read test (PRM-057 row 7) sits in `services/document-service/test/control-plane/`, not in `tests/security`, because `tests/security` does not depend on `@docedit/asset-worker`. Adding that devDependency needs `scripts/pnpm-locked.ps1` and the main session's go-ahead. Needs from others: add `@docedit/asset-worker` to `tests/security/package.json` if the security suite should run row 7 itself.
4. **Refusal code for the gate.** For PRM-058 row 2 the outsider is refused `403 forbidden` (the `view` check). A viewer hitting the history gate is refused with a 4xx; the test does not pin the code. The spec's code for a gated read is not named (07 §12); the owner decides whether it is `forbidden` or `not_found`.

## Round 4 (lane U-PRM-052-067, developer of round 3)

This round it closed PRM-053 (criteria 1, 2, 3 and 5) and PRM-056 (criterion 3; criterion 5 partly). Recommendations, all with the spec default or the least change, for the owner to confirm:

5. **Event data carries `seq`.** `dep.grants.changed` and `dep.region.state_changed` now carry `data.seq` (05 §7 says the event data includes the `seq`). The CloudEvent envelope refuses an event without it, so before this change both events were dropped silently. The routes test that pinned `data` to `{ rev }` now accepts `seq` as well.
6. **Rejection throttle values are test values.** The tests use a window of 60 s and a maximum of 5. The spec gives no figure; the owner sets them (the ADR 0146 open item). Nothing in the code has a default.
7. **Refused policy change over HTTP stays `forbidden`.** PRM-066 criterion 2 says `permission_denied` for a grant request. The control plane answers 403 `forbidden`, as `lease-routes.ts` maps `permission_denied` to `forbidden`. Recommendation: keep `forbidden` and amend the criterion's wording, or make the spec name one code for both. The owner decides.
8. **Guards with a `somewhere` or `region` requirement use `requireRow`.** `guard()` passes no regions, so it can only decide document-level rows. Any future route with a region-scoped row must load the regions and the grants first, as `asset-routes.ts` does.
9. **Found, not changed:** the dispatcher's `#track` drops a failed send without a log line (`services/document-service/src/control-plane/webhook-dispatcher.ts`); the event sinks of `dep.document.state_changed` and the other events have not been checked against the envelope's `seq` and `chainHead` rules.

Needs from others: BE-055 (the dispatcher's failed-send log line); the owner's decisions above; a real HTTP egress receiver is not tested here (BE-056).
