# ADR 0345 (lane V-SEC-017-032): decisions taken while closing SEC-017 to SEC-032 blockers

Status: proposed. Every item is a reading the spec leaves open, or a default this lane chose so a test could run. The owner decides the items marked "owner".

## 1. Read marker: a lower update is "refused" (SEC-032 criterion 5)

The criterion says that an update which would lower a read marker "is refused". The spec (05 §6.2) says the route "can only move forward", and 07 §8 says "read markers only move forward". Neither names an error for a lower value.

Default taken: a lower or equal `seq` is not applied, and the route answers 200 with the marker in force (`PUT /v1/documents/{id}/read-marker`, `services/document-service/src/control-plane/history-routes.ts`). The test is `tests/security/test/sec-032-read-marker.route.test.ts`.

Open (owner): should a lower value answer with an error (for example `409 conflict`) rather than the marker in force? That is a change to the API surface, so it is not made here.

## 2. Anchor signing and retention in the S3 test (SEC-029 criterion 5)

HIS-036 does not name a signature scheme or a retention period. Defaults taken for the test in `tests/security/test/sec-029-anchors.s3.test.ts`:

- Ed25519 over the canonical JSON of `{at, chainHead, doc, seq}`, a key generated per run (test key only).
- Object Lock in COMPLIANCE mode with a 15 minute retention, on a bucket with a unique `docedit-v-sec-017-032-*` name. COMPLIANCE objects cannot be removed before retention ends, so the bucket stays until `infra/test-env.ps1 down` removes the tmpfs data.

Open (owner): the signing key custody, the retention period, and whether anchors use COMPLIANCE or GOVERNANCE mode (the owner decides; see also SEC-062 on key management).

## 3. A commit whose processing throws (SEC-028 criterion 4)

The spec says the commit is rejected and the exception counted, and that the room keeps serving. It does not name the rejection code. Default taken: `invalid_op` (the default action `drop`), counted in `Room.validationExceptions` (`packages/authority/src/room/room.ts`). The test is `packages/authority/test/sec-028-throwing-commit.test.ts`.

Open (spec gap): a throw part-way through applying a commit leaves the room's in-memory state as far as the throw reached. No rollback is made. A reviewer should decide whether the room must reload from storage after such a throw. The counter is not yet exported to the Prometheus registry (`services/document-service/src/data-plane/metrics.ts`).

## 4. CPU budget per connection (SEC-028 criterion 2, SEC-018)

The spec gives no CPU budget value and the data plane has only a message-count bucket. No default is invented here. Owner: choose the budget and the measurement harness.

## 5. The oracle for the rebase fuzz target (SEC-025 criterion 6, round 3)

The criterion says the step validation and rebase fuzz target runs "with the oracle of SEC-021". The SEC-021 oracle of PRM-017 (`packages/authority/test/harness/oracle.ts`) is in the authority's own test folder, and the security tests import only public exports. Default taken: the outcome check with the standard rules (the gate the room uses) decides acceptance, and an independent comparison of the serialised content of the protected region R decides whether an accepted commit changed it. The test is `tests/security/test/sec-025-rebase-oracle.test.ts`. It does not run the full PRM-017 oracle over every scope.

Open (reviewer): whether an accepted commit must also pass `oracleViolations` of PRM-017. Owner or reviewer to decide whether importing that harness into `tests/security` is allowed.

## 6. Thread author in the wire tests (SEC-019 criterion 4, round 3)

The spec says the stored author "is the caller". The service stores the connection's surrogate (`user.surrogate`), not the token subject, as the commits do. Default taken: the test asserts that the stored author is not the claimed name, that the first comment carries the thread's author, and that another user's reply carries a different surrogate. The test is `tests/security/test/sec-019-thread-author.route.test.ts`.

Open (owner): whether the thread's author in the API should be the surrogate or the subject. Not changed here.

## 7. Webhook metrics (SEC-020 criterion 6, round 3)

Not changed. The dispatcher (`services/document-service/src/control-plane/webhook-dispatcher.ts`) takes no metrics sink, so there is no webhook metric to read. Adding one is a change to a service package outside this lane's test scope, and it needs a decision on metric names. The logs half stays covered by `tests/security/test/sec-020-webhook-logs.test.ts`.

## 8. Round 4 decisions (2026-11-14)

Status: proposed. Items 8.1 to 8.3 record a default taken for a test. Item 8.4 is an open question left unchanged.

### 8.1 Webhook metrics read as the service exposes them (SEC-020 criterion 6, metrics half)

Item 7 is superseded in part. The service has no webhook metric, but `/metrics` (`services/document-service/src/control-plane/metrics.ts`, served in `server.ts`) is served after deliveries. Default taken: the criterion is read as "the metrics the service exposes after deliveries carry no secret or signature". The test is `tests/security/test/sec-020-metrics-logs.test.ts` (memory and PostgreSQL). Open (owner or reviewer): whether a webhook-specific metric must exist. Not added here.

### 8.2 Lease expiry in tests (SEC-026 criterion 3)

The control plane's region lease has a five-minute default with no duration option on the acquire route. Default taken: the test stores the lease in the grants store with a short expiry (`putLeases`) before the room opens. The test is `tests/security/test/sec-026-lease-expiry.test.ts` (memory and PostgreSQL). Open: whether the acquire route should take a duration for tests. Not changed.

### 8.3 Envelope answers (SEC-017 criterion 3)

Default taken: a frame counts as answered when the connection closes with 4400 or an `error` message arrives, which is what the criterion names. A duplicate-key envelope is answered by the codec with an error or 4400 (no silent acceptance was observed). The test is `tests/security/test/sec-017-envelope-hostile.test.ts` (memory and PostgreSQL).

### 8.4 Open, not decided here

- SEC-023 criterion 5 (block-level suggestions beyond paragraphs and table rows) is a spec question for 07 §17, already recorded in the story Notes. Default in the spec is refusal, but the authority accepts block marks on any node that carries them, and tables are in the suggestion code path. Owner or spec decision; no behaviour changed.
- SEC-027 criteria 2 and 3 (each invariant with each step type over the wire, and each schema attribute's grammar over the wire) are not closed. The invariant fixtures under `packages/model/fixtures/invariants/cases` are documents, not commits, so they would need conversion. Left for a later round.
- SEC-018 criteria 1 (verification count), 2 (tenant quota, phase 2, and latency on the reference machine), 3 (room memory) and 5 (connection CPU budget, not built) stay unticked. Item 4 above still applies to the CPU budget.
