# ADR 0309: Decisions of lane U-PRO-001-017 (PRO protocol, round 2)

**Status:** proposed. Owner decisions stay with the owner; each item below says what the spec
default is and where the choice was made.

**Date:** 2026-11-13. **Lane:** U-PRO-001-017. **Stories:** PRO-015 (criteria 2 to 4).

## Context

PRO-015 carries optional claims. Its Notes recorded a conflict: the token check refused an unknown
`restrict` value, where criterion 2 says it is ignored. The other two open criteria were a claim
that was minted but not recorded, and a refresh that could not change `restrictions` on the wire.

## Decisions

1. **Unknown `restrict` values are ignored (PRO-015 criterion 2; 05 §1 rule 3; PRO-005).** The
   spec default. A `restrict` that is not an array is still refused as a malformed claim, because
   the criterion is about unknown values and not about shape. Known values are kept once, in the
   token's order. Alternative for the owner: refuse the whole token on any unknown value. That
   would contradict PRO-005 and is not chosen here.
2. **`wfp`, `amr` and `auth_time` are recorded as given, on the verified identity only**
   (`VerifiedIdentity.asserted`, `services/document-service/src/seams.ts`). They are not identity
   proof and feed no permission check (FRW-038, FRW-040). Each is kept only when it has the
   expected type. Nothing persists them yet. `wfp` does not set `Connection.participant`: that
   field drives workflow fill rights, which are FRW's rules (12 §4.1), so wiring it is FRW's
   decision.
3. **`access.restrictions` on the wire come from the connection** (`Connection.restrictions`,
   `packages/authority/src/permissions/model.ts`), in the fixed order no-export, no-copy,
   no-print (`restrictionsOf`, `packages/protocol/src/bridge/translate.ts`).
4. **A change of restrictions alone is a change of access.** `Room.refresh` sends `perm.changed`
   when the restriction set differs, even if the rest of the access is the same (PRO-015
   criterion 4). `sameRestrictions` compares sets, so order and repeats do not count.

## Not decided here

- Whether a malformed `restrict` should be refused or ignored. The spec gives no rule.
- Where `wfp`, `amr` and `auth_time` are stored beyond the connection (history or audit). That
  belongs to HIS and FRW-038 and FRW-040.

## Consequences

- Test files: `services/document-service/test/control-plane/pro-015-claims.test.ts`,
  `services/document-service/test/data-plane/pro-015-restrictions.test.ts`.
- The test helper `Tokens.issue` accepts `restrict` (`services/document-service/test/data-plane/support.ts`).
