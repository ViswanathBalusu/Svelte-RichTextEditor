# ADR 0338: Decisions taken by lane U-BE-085-098

Status: proposed (for the owner to confirm). Date: 2026-11-13.

## Context

Lane U-BE-085-098 closes the criteria of the backend stories BE-085 to BE-098 that earlier lanes left open
for lack of PostgreSQL, object storage, a container or a browser. Some of those criteria need a decision the
spec leaves open. This record lists them so that they are not decided silently (CLAUDE.md, stories).

## Decisions

1. Backup key (BE-096). A backup is sealed under a 256-bit backup key read from base64 text, held apart
   from the tenants' keys in `KeyService`. Spec default used: the key is a secret of its own. Open: where
   the key is stored, how it is rotated, and whether operators hold it in a KMS. Not decided here.
2. Backup format (BE-096). The bundle is held in memory and sealed once (AES-256-GCM with a fresh data key,
   wrapped with the backup key). Open: streaming for large databases.
3. Object bytes in a backup (BE-096). Objects are copied as stored, so they stay sealed under the tenants'
   keys. A backup therefore needs the tenants' keys as well as the backup key to read customer content.
4. Database dump (BE-096). The dump is plain SQL from the PostgreSQL client tools, run by the operator. No
   command line for backups is built yet.
5. Rehearsal (BE-096). A rehearsal restores the dump into a scratch database and checks each sample with the
   BE-081 procedure against the live hash taken before the backup. The result and the sample checks are
   recorded as `backup.rehearsed` audit events. Retention and restore windows have no number in the spec.
6. Audit scope (BE-096). The audit trail is per tenant, so a backup covering several tenants writes one
   event per tenant. Events carry identifiers and counts only.

7. Repair content (BE-090). The repair writes the content the log replays to from the newest checkpoint
   that verifies, as a snapshot commit with origin `repair`. History is not rewritten. A replay across a
   snapshot above the checkpoint is refused and done by hand. Open: the approved-region check for a
   snapshot (BE-090 criterion 2), which is not tested.
8. Repair reason (BE-090). The operator's reason goes in the audit event only. The commit carries the
   registry's origin and nothing else from the operator.

## Consequences

Criteria of BE-096 are ticked on the module level and on PostgreSQL and S3 in the test environment. The
owner confirms or replaces decisions 1 to 6 before a hosted deployment.
