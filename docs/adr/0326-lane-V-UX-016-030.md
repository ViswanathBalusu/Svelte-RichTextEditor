# ADR 0326: decisions of lane V-UX-016-030 (round 2)

Status: proposed (2026-11-13). Lane V-UX-016-030 closed criteria that earlier lanes left blocked on a
browser run or on a missing pane. Each decision below is one the spec leaves open; it uses the spec's
default or the smallest reading, and the owner may change it.

## Decisions

1. **The comments pane reads its threads once, when it opens.** `CommentsPane.svelte` takes
   `core.threads.list()` at mount. Live refresh from `thread.*` and `comment.*` (UX-030 criterion 4) is
   not built. Default: the spec's list is refreshed by notification; this lane did not add the event.
2. **`ThreadsService.list()` is a new port member** (`packages/ui/src/core-api.ts`, `ThreadSummary`). The
   spec (05 section 6.2) gives no list endpoint in the shell's terms; the shape is the one the pane
   needs and is the reader's projection (ADR 0019). The fake port implements it.
3. **Filters are the state (open, resolved, all) and the assignee.** The spec names "open or resolved
   and assigned to a person" (UX-030 criterion 3) and gives no other filter. Default: nothing more.
4. **The pane's text is new `comments.*` keys in `src/i18n/en-GB.ts`.** Plural reply counts use the
   `one` and `other` forms. The thread text (the excerpt) is content, not an interface string.
5. **A thread row is a focusable `role="group"` named by author, state and reply count.** The spec asks
   for each entry to have a text name (UX-030 criterion 6). A group with `tabindex="0"` is the smallest
   reachable, named element while the comment list (the bodies of replies) is not built.
6. **A detached thread shows "The commented text was removed."** Its text is the shell's, not the
   spec's (UX-029 criterion 4 says only that it is shown as detached).
7. **Test runs use a single browser run at a time on port 57261.** Parallel Playwright runs in the
   shared `test-results` folder removed each other's trace files; this is an environment note, not a
   product decision.

## Consequences

- UX-028 criteria 3 and 5 and UX-030 criteria 1 and 3 are ticked on the browser runs named in their
  Evidence lines.
- UX-030 criterion 6 stays open until the comments inside a thread are listed.
- The created thread does not appear in the pane until it is reopened (UX-028 criterion 1 stays open).

## Round 3 (2026-11-14)

8. **UX-023 criterion 2 stays open on "collapsed".** The shell has no collapsed state for a pane (a closed
   pane is skipped and tested). The spec's "collapsed" is read as not yet built, not as a new state.
   Default: leave the criterion open until the owner says whether a pane can be collapsed to a landmark.
9. **The caret in UX-020 criterion 1 is read from the editor's shadow-root selection.** The page's selection
   is held by the host element, whose text is the whole document, so a page-level read proves nothing.
   WebKit did not match that read (not investigated), so the test is skipped there and the criterion is
   claimed for Chromium and Firefox only.
10. **UX-025 criterion 5 treats the welcome frame as the service's own echo.** The service's welcome names the
    signed-in user from the token it was given, so that one `"user"` object is removed before the search for
    directory names. No other frame or request is changed. The directory names are supplied by the host, not by
    `resolveUsers` for that echo.
