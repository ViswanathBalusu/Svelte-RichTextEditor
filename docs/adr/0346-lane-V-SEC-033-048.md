# ADR 0346: lane V-SEC-033-048 (unblock round 1)

Status: proposed. Date: 2026-11-13.

This record covers the stories SEC-033 to SEC-048 that the lane looked at in this round. Each item is a
decision the spec leaves open, or a blocker the lane could not clear. Owner decisions stay the owner's.

## Done in this round

- SEC-047 criterion 5 is ticked. Test: `tests/security/test/sec-047-v-compile-log-route.test.ts`
  (Node.js, memory storage, passed). The file name differs from the name used by another lane's
  `sec-047-compile-log.test.ts`, which was already in the tree; this lane did not touch that file.

## Open items

1. SEC-037 criterion 3 (commits naming another document's or another tenant's asset are refused with
   `invalid_op`). Not built. The room checks asset references only when it holds an `attachedAssets`
   set (`packages/authority/src/room/room.ts`, `packages/model/src/validate/validate.ts`), and the
   room host passes none. The control plane's content route checks references with
   `validation_failed`, not `invalid_op`, which is a different code.

2. SEC-037 criterion 3, the data-plane source. Proposed: the room host gives each room a live source
   of attachable assets (the ready assets of the document plus the references of its current content),
   read before each commit that carries an asset reference. Alternative: a refresh on each asset-ready
   event. The first is simpler and does not refuse assets uploaded after the room opened. Owner or main
   session to choose; the commit path is synchronous today.

3. SEC-045 criterion 4 (a signed URL of tenant A on a key of tenant B does not work in the full
   scenario). The document service has no URL verifier; the stores sign URLs but nothing checks them.
   Proposed: the verifier belongs to the asset origin (`services/asset-worker/src/signing.ts`), and the
   scenario needs uploads and exports, which the current HTTP scenario does not drive.

4. SEC-038 criterion 4 (the decoder kill under the time and memory limits). No run in this lane. A
   `podman run --memory` probe against `localhost/docedit-asset-worker:dev` did not return within the
   probe time while the Podman machine served other lanes. The earlier lane recorded a `memory.max`
   write failure on the same machine. Needs a quiet Podman machine or the infrastructure owner.

5. SEC-048 criterion 1 (secret scan in CI) and SEC-035 criterion 6 (suite in CI): both need
   `.github`, a root configuration. Left to the main session.

6. SEC-034 criterion 6 and SEC-033 criteria 1 and 5 need a compile in the sandbox under Podman (item 4).

7. Round 4 (2026-11-13), SEC-034 criterion 5: the strongest accepted equation, placed in region A, paints
   over neighbouring words of the rendered page (`services/export-worker/src/sec-034-region-equation.e2e.test.ts`,
   `it.fails` case). The text of region B is still extractable. Proposed: the house class keeps an inline
   equation inside its line box, or clips the line as Word does for `exact` spacing. The owner of the
   export class (packages/export-latex/class) decides which; the default used here is no change to the class.
   The cause is not confirmed; the line-height path in `docedit.lua` (`tallest_run`, `docedit.line_height`)
   is the first place to look.
