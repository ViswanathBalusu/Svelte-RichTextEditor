# ADR 0341: decisions of lane U-FRW-037-054 (FRW-037 to FRW-054)

Status: proposed. Owner decisions stay with the owner; each item below names the spec default used.

## Context

Lane U-FRW-037-054 closes the criteria of stories FRW-037 to FRW-054 that were blocked on a database, a container, a browser or another package. This round handled FRW-039 (access code) only. The remaining stories in the range are listed in the lane report.

## Decisions

1. **Stored form of an access code (FRW-039 criterion 3).** A code is stored as the salt and `SHA-256(salt || UTF-8(code))`, both in lower-case hex. The code is hashed as given, without trimming. Spec default: 12 §6.1 and §7 say only "stored as a hash" (FRW-039 criterion 3); the salt and hash function reuse the evidence commitment of ADR 0013 (`packages/authority/src/workflow/evidence.ts`). Proposed; the salt length and any slow hash (for example a password-hashing function) are open.

2. **Accepted `auth` member (FRW-039 criterion 5).** A workflow's `auth` accepts only `require` with entries equal to `access_code`. An empty or absent `require` requires nothing. Any other method, any other member, a non-list `require` or a non-object `auth` is refused. Spec default: 12 §6.1 names `access_code` as the only method in the resource example; no other method is specified, so none is accepted.

3. **Not decided here.** The attempt limit, the lockout policy and the rate-limit window for FRW-039 criterion 4 (open in the story Notes and in the Open questions); how a code is registered and delivered to the participant (open); the instant from which the evidence retention clock runs (FRW-043, open). None is set by this lane. The access-code check stays a pure function until the workflow service exists.

4. **Write-once form of a sealed PDF (FRW-054 criterion 1).** The sealed bytes go under `objectKeys.final` (the tenant's prefix) with S3 Object Lock in COMPLIANCE mode, so no credential can overwrite or delete them before `retainUntil`. The retention end is the caller's: no default is set, and the spec gives none (FRW-084 and the Open questions). Spec default: 12 §8.2 step 4 says "write-once"; COMPLIANCE is the strongest mode the test server supports. Proposed; the retention length and whether an operator may hold a legal hold on sealed PDFs are open.

## Consequences

- `packages/authority/src/workflow/access-code.ts` and `packages/authority/test/frw-039.access-code.test.ts` are the only code added by this lane in this round.
- Criteria 1 to 5 of FRW-039 stay unticked until the verify endpoint, the storage tables and the workflow save exist.
- FRW-054 (decision 4): `services/document-service/src/objects/sealed-pdf.ts` and `services/document-service/test/objects/frw-054-sealed-store.test.ts` (6 tests, Versity S3 Gateway in Podman). No criterion ticked.
