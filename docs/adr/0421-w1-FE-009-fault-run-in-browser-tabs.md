# ADR 0421: The fault run of FE-009 is made in browser tabs

**Status:** proposed, 2026-11-21, lane w1 (story FE-009, criterion 7). Not reviewed by the project owner.

## Context

FE-009's last criterion asks for the outcome of "the fault-injection run of the phase 1b exit criterion": two users with different grants and one fill-only participant work on one document for an hour under fault injection (dropped connections, a killed process, a database outage), and nothing typed is lost across a closed tab (11 §4). The harness of that run is BE-080, which is not built. Its Notes say what it lacks: a package that holds the editing core, the DEP client and the service together, a PDF export step, and a nightly job in the root configuration. Earlier rounds of this lane therefore left the criterion open and offered a property test against the mock room (`packages/engine/test/fe-009-fault-injection.test.ts`), which is the client's logic without a browser, a socket or a database.

The client's half of the run needs none of the three missing things. A browser tab already holds the editing core, the DEP client and the IndexedDB journal together, and `tests/V-FE-113-128` already drives `<doc-editor>` against the real document service on PostgreSQL.

## Decisions (proposed)

1. **The run is made in browser tabs, against the real service.** `tests/fe-009-fault-run` starts `services/document-service` as a process of its own on PostgreSQL and the object store of the test environment (`infra/test-env.ps1`), and opens three tabs of the library build with `endpoint` and `getToken`: Ada, an editor who holds the grant on a restricted region; Grace, an editor who does not; and a participant with the role `filler` and one fill role. Each has a browser profile of their own, because the journal is bound to the signed-in user (owner decision 47) and three people do not share a machine. The host signs the tokens itself with a key registered for the tenant (05 §3.1), so a token is there whether or not the service is.
2. **People type with the keyboard.** The two editors type words of the form `A00017` at the end of lines of their own (a click, the End key, the keys), Ada inside the restricted region and in the body, Grace in the body before and after the region, so that each one's changes move the positions of the other's. The participant types values into three fields and leaves each with Tab. About one of Grace's turns in twenty is an attempt on the region she may not change.
3. **The faults are real.** A relay between the tabs and the service destroys every socket with no close handshake (a dropped connection). The service process is ended with SIGKILL and a new one is started on the same database, tenant, keys and object store. PostgreSQL takes the database away (`ALLOW_CONNECTIONS false` and the end of every session on it) and gives it back; the service's own test hook (BE-079) is the other choice, `DOCEDIT_FAULT_RUN_OUTAGE=hook`, and is not what the record run used. A tab is closed while it holds unconfirmed work: the relay cuts the network, the person types two more words, the run waits until the journal holds them, and the tab is closed (in Chromium every other time its renderer is crashed instead, which gives the page no event at all); then the tab is opened again in the same profile. The schedule comes from a seed: one fault of each kind first, then at random, 12 to 35 seconds apart.
4. **What counts as typed.** A word counts once its editor shows it after the keys were sent. A word the editor did not show (the tab was loading, or the caret did not go where the click was) is listed apart and must not be in the document twice; it is not counted as lost, because the person saw at once that it was not there.
5. **What the run compares at the end.** The faults stop, every tab is given three minutes to send what it holds (`flush()`), and then: every word that was typed is in the service's document exactly once, or it is in that person's recovered edits (FE-010), which is where 04 §9 sends work that no longer applies; every field holds the last value the participant gave it; no word of Grace's is inside the restricted region; every tab's confirmed text and field values equal the service's; and no journal holds a commit. A run in which a tab did not come back, or the service could not give its document, fails.
6. **What this run is not.** It is the part of the phase 1b exit test that FE-009 names. It does not judge the rejections with the oracle of SPK-016, does not prove that each kind of catch-up was used, does not rewind a log, exports no PDF and is not scheduled; those are BE-080's criteria and stay open there. BE-080 can use this folder as its browser half.

## Found by the run

- A client that said `hello` while the database was away was answered `unauthenticated` (the token could not be checked) or `forbidden` (the origin list could not be read). Both tell a client to give up (05 §5.8), so it never came back. `services/document-service/src/data-plane/session.ts` now answers `unavailable`, which a client backs off from, for a token or an origin it could not judge, at `hello` and at `auth.refresh`; a token it did judge keeps its code. No session is opened either way. `services/document-service/test/data-plane/w1-fe-009-hello-unavailable.test.ts`.
- A content read over REST answers 500 `internal` while PostgreSQL refuses the database, where 06 §8 and BE-077 say `unavailable`. Seen in the run's probe; BE-077 was tested with the hook, which does not fail reads. Not changed here.

## Consequences

- The run needs PostgreSQL and the object store of the test environment, a built library and about an hour and a quarter. It is not part of `pnpm check`.
- Its report (seed, schedule, counts, result) is written to `tests/fe-009-fault-run/reports/`, which is not kept; the report of a run that is cited as evidence is copied to `tests/fe-009-fault-run/runs/`.
