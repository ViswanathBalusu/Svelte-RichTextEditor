# ADR 0329: Lane U-UX-061-075 decisions on browser measurements

Status: proposed. Owner: the main session, for confirmation.

## Context

Lane U-UX-061-075 closes criteria of stories UX-061 to UX-075 that were blocked on a browser run. Three measurement choices were needed where the stories are silent or leave the method open.

## Decisions (spec default, to confirm)

1. Forced colours (UX-062, criterion 4). Forced colours are emulated with Playwright (`emulateMedia({ forcedColors: 'active' })`). The contrast measure is the WCAG 2.2 relative luminance ratio of each visible text run against the first opaque background above it, at 4.5 to 1. Labels of disabled controls are not measured, because WCAG 2.2 1.4.3 exempts inactive components.
2. Theme page canvas (UX-061, criterion 2, shell side). Only the shell's computed background and the page canvas are read. The stored document and exports are not checked, so criterion 2 stays open.
3. Pointer targets (UX-068, criterion 2). The minimum is 24 by 24 CSS pixels (WCAG 2.2 2.5.8), measured on every tab of the full toolbar. Menus, panes and dialogs are not yet measured.

4. Unknown string keys (UX-063, criterion 2; UX-064, criterion 3; round 2, 2026-11-13). The element's `strings` property passes host replacements to the shell's catalogue. An unknown key is reported to the console as a warning in every build. The product has no development-only build flag for the element, so "reported in development" is read as "reported to the developer who runs the page", and no development-only gate is added. The owner may ask for a gate instead.
5. Memory method (UX-074, criteria 2 and 3; round 2, 2026-11-13). The figure is `Runtime.getHeapUsage().usedSize` after two `HeapProfiler.collectGarbage` calls, read through the Chrome DevTools Protocol, so it is measured in Chromium only. The warm-up is one pass of every pane plus 20 passes. The noise is the spread of five back-to-back readings with no action. Criterion 2 is not ticked on this method; the run is recorded and not asserted.

6. The checker reads footnotes and the stories (UX-066, criterion 3; round 4, 2026-11-13; proposed). The export job's alternative-text report (EXP-113) reads footnote pictures and header and footer pictures, so for the two to agree on which pictures lack alternative text the checker reads footnote text and the stories too (headers and footers, after the body so the body's heading order is kept). A header or footer block takes the DEP scope `body`, because the DEP scope vocabulary (05 section 5.3) names only `body` and `region:<id>`; the owner may prefer another scope for stories. Headers and footers are checked for all five kinds, not for alternative text alone. Spec default: none stated.
7. UX-067 criterion 5 is ticked on the export job alone (round 4, 2026-11-13; proposed). The author's export command is not built, so "when the author exports" is read as the job's conversion with issues present; the checker has no gate on export.
8. Browser-run and reference-machine items left open in round 4 are not decided here: UX-069 (conformance report, needs manual screen-reader logs and a CI setting under `.github/`) and UX-072 (typing latency on the reference machine; the frame publication rule in the story Notes is the owner's call).

## Consequences

Stories UX-061 (criteria 1 and 4) and UX-062 (criterion 4) are ticked on these runs. The harness uses a fake core, so the selection is the core's summary, not the engine's selection.
