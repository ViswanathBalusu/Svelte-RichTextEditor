# 0349. Open questions from the V-PRM-018-034 lane (round 1)

**Status:** proposed (2026-11-13). Records the decisions this lane took where the spec left a question open, and the spec default it used. The owner or the authority owner may choose otherwise.

**Context.** The lane closed criteria in PRM-018 to PRM-034 that were blocked on a missing change in a package rather than on an owner decision. Two stories were touched: PRM-023 (criterion 2) and PRM-033 (criterion 1).

## Decisions

1. **A role placeholder with no active workflow (PRM-023 criterion 2).** Default taken: the spec default of 07 §1, which resolves `role:<id>` to participants bound "in the active workflow". With no active workflow the grant matches nobody. This answers the question in ADR 0260 item 1. Changed: `grantMatches` and `bestGrant` in `packages/authority/src/permissions/access.ts`; the fixture oracle in `packages/authority/scripts/capability-fixtures.ts` (`packages/authority/fixtures/capabilities.json` regenerated from it); the test oracles in `packages/authority/test/harness/oracle.ts` and `packages/authority/test/visibility.test.ts`. Owner: the spec (07 §1) may still prefer the earlier reading that the code had.
2. **Marking blocks as a region (PRM-033 criterion 1).** Default taken: the command wraps whole body blocks, refuses a selection inside a region, and refuses an empty title. The title is required by the story ("enter a title"); the spec does not say what an empty title means, so refusal is the default. Changed: `packages/engine/src/prm-033-mark-region.ts`, wired in `packages/engine/src/core.ts`, and the name in `packages/engine/src/api.ts`.
3. **Nested selection reason (PRM-033 criterion 2).** Not decided. The command refuses a nested selection, but `queryCommand` gives no reason for it yet. Owner: the UX owner (13) for the words of the reason.

## Round 2 (2026-11-13)

4. **Renaming a region (PRM-034 criterion 1).** The rule for who may rename is the spec's (07 §2: `structure` and `edit` in the region, `region.retitle` in `packages/authority/src/permissions/model.ts`). Default taken for the rest, which the spec leaves open: an empty or blank title is refused, and a title equal to the current one is a no-op that queues nothing. Changed: `packages/engine/src/prm-034-rename-region.ts`, wired in `packages/engine/src/core.ts` (the `renameRegion` branch and the block-only set) and the name in `packages/engine/src/api.ts`. Owner: the title rules (length, allowed characters) are not in the spec and are not set here.
5. **Splitting and merging regions (PRM-034 criterion 4).** Not decided here. It waits for the owner's decision on PRM-065 (ADR 0033 item 3), as the story's Notes say.
6. **Two-browser grant scenario (PRM-019 criterion 1, PRM-024 criterion 5).** Not built in this round. The browser side has no client that joins the document service over the network in the shell harness, so the scenario needs a wiring change in `packages/element` and `packages/backend-dep` and a run of the document service in Podman. Recorded in the lane report, not decided here.

## Consequences

No other decision is taken here. Round 2 changed no spec default. The count of queued changes after a region is marked is more than one, because the region plugin's follow-on paragraph and identifier fill are queued too; this is not treated as a defect and is not decided here.
