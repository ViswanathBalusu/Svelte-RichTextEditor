# ADR 0272: Lane HIS-001-016 open choices (proposed)

**Status:** proposed, 2026-11-13. Written by the developer lane HIS-001-016 (round 2). Not decided by the owner.

## Context

Lane HIS-001-016 met some criteria only by deciding a point the spec leaves open. Each choice below uses the spec default or the narrowest reading, and is listed so the owner can confirm or change it.

## Choices

1. **Creation time of seq 0 for "who wrote this" (HIS-015 criterion 1).** The content created at seq 0 has no commit, so no server time is stored for it in the commit list. `withRunTimes` in `packages/history/src/who-wrote-times.ts` takes the creation time from the caller and refuses with `internal` when a run from seq 0 has no time. It never guesses one. Open: where the service stores the creation time (a document row or a seq 0 record). Default used: the caller supplies it.
2. **Time of a run that spans several commits.** A run is summarised with the earliest and latest server time of the commits that wrote its authors' text (`firstTime`, `lastTime`). Open: whether the user-facing answer shows the range or only the latest time. Default used: both are returned; the interface decides what to show.
3. **Assistant and person kept apart in the author summary (HIS-017).** Authors are grouped by user and agent, so one person's own writing and their assistant's writing appear as two authors. This follows 13 §6.2. No change to the rule is proposed.

## Consequences

- HIS-015 criterion 1 stays unticked until the pane and the route exist; the pure answer builder is in place and tested.
- Choice 1 needs a decision before the attribution route is built (HIS-015 criterion 2).

## Not changed

Story criteria that need a container, a browser run, a CI workflow or a root configuration change were not touched (HIS-003 criterion 2, HIS-001 criterion 2 for snapshot commits, HIS-016 criterion 5 which needs the document service and PostgreSQL).

## Round 3 (2026-11-13)

4. **Shape of the comparison result and spans of a field change (HIS-011 criterion 2; HIS-012 criterion 3).** 08 §6 asks for `changes` keyed by block identifier and `field` keyed by field identifier, with spans carrying `op`, `at`, `text`, `user` and `seq`. The code returns `changes` as a flat array, each entry naming its `blockId` or `fieldId`, and a field change has no spans because a field value is one value. Default taken: keep the flat array and the span-less field change, which the tests already pin; a keyed object would break every consumer of `compare`. Question for the owner: whether the spec's keyed object is the contract, and whether a field change should carry one span holding the old and new value.
5. **Attribution map in a checkpoint (HIS-014 criterion 4).** The room's checkpoint effect (`packages/authority/src/room/room.ts`, the `fx.checkpoints` entries) holds `seq`, `doc`, `reason` and `threads`. Default taken: none in this lane; the map is serialised by `packages/history` (tested), and writing it into the checkpoint needs a change to the room, which belongs to another lane. Question: which lane adds the attribution map to the checkpoint record and its storage.
6. **Move form in comparisons (HIS-012 criterion 7).** Already recorded as item 2 of ADR 0118. Default in code: the kind `moved`. Still open for the owner; HIS-012 criterion 7 stays unticked.
7. **Named version head default (HIS-006 criterion 1).** `createVersion` takes an explicit `seq`. Default taken: the service chooses the head when the request gives none, since the rule must not guess. Question: none beyond confirming that the service, not the package, applies the default.

No story criterion was ticked in round 3. The remaining criteria of HIS-006, HIS-009, HIS-010, HIS-013 and HIS-014 need the service, the room or the pane, which are not built in this lane's packages.
