# 0202. Lane FE-027 to FE-039: open questions and the defaults taken

**Status:** proposed (2026-11-13). Written by the developer of lane FE-027-039, round 1, for the stories FE-028, FE-030 and FE-037. Not reviewed by the owner.

## Context

The lane took three stories in round 1 that still had unticked criteria and whose missing part could be built and tested in Node.js: FE-028 (`de-selection` and `de-command-state`), FE-030 (criterion 5, the element's reaction to a refused document) and FE-037 (criterion 6, Cut across protected content). Nothing here changes the spec.

## Open questions and the default taken

1. **Detail of `de-command-state` (FE-028).** 05 §8.1 gives `{ scope, blockId }` for both `de-selection` and `de-command-state`, and says "the commands whose state changed" in words. The code raises `de-selection` with `{ scope, blockId }` and `de-command-state` with `{ commands: [{ name, enabled, active }] }`, listing exactly the commands whose `enabled` or `active` result changed. The list form is the reading of the words; it carries names and booleans only, no content. Decision for the owner: whether the spec's table should give the list shape.

2. **Baseline at mount (FE-028).** The state the reporter starts from is not raised. The spec does not say whether a host gets the initial selection or command state; a host that needs it calls `queryCommand` and reads the selection. Decision for the owner.

3. **Cut across protected content (FE-037 criterion 6).** The spec says that only the editable parts are removed. The code uses the trimmed deletion (FE-037 criterion 1) for a cut whose selection is not wholly editable. When the selection holds no editable text, the cut is refused as before, with the existing `scope` or `read-only` reason, and the clipboard still receives the whole selection. This keeps the existing refusal behaviour of `cutSelection()` (`packages/engine/test/clipboard.test.ts`, 'writes the copy but deletes nothing in a region the user may not change').

4. **Announcement of a trimmed deletion (FE-037 criterion 2).** Not decided here and not built in this lane. The shell's live region in `packages/ui` already announces refusals and recovered edits; the element's announcer is deliberately not fed those, so that the reader does not hear them twice. The notice for a trimmed deletion belongs in that shell path, and needs the ui owner.

## Consequences

- FE-030 criterion 5 is ticked on the core test and the element test together.
- FE-037 criterion 6 is ticked; criterion 2 stays open.
