# ADR 0212: Open decisions found by lane PRO-015-028

Status: proposed. Owner decisions are the owner's; the spec default applies until then.

## Context

Lane PRO-015-028 (round 1) read the stories PRO-015 to PRO-028 of `docs/stories/PRO-protocol.md` against the code. Two points in the stories conflict with the code, or with the spec, and the story text does not decide them.

## Open decisions

1. **Unknown `restrict` values (PRO-015 criterion 2).** The story says an unknown value is ignored. `services/document-service/src/control-plane/tokens.ts` refuses the whole token when `restrict` holds any value other than `no-export`, `no-copy` or `no-print`. The spec default used here: keep the code as it is and leave PRO-015 criterion 2 open. Question for the owner: ignore unknown values (as the story says and as PRO-005 "ignore what is not known" would suggest), or refuse them (as the code does)?

2. **Unknown claims in general (PRO-005 against PRO-015).** If unknown values are ignored, the same rule should cover other optional claims. Not decided here.

3. **Where `wfp`, `amr` and `auth_time` are recorded (PRO-015 criterion 3).** The story says the service records them as given. `verifyUser` keeps only the identity fields. Spec default: not recorded; criterion stays open. Question: which record (audit log, identity object) holds them.

4. **Rejection of an unknown `restrict` value and `access.restrictions` (PRO-015 criteria 2 and 4).** No `access.restrictions` is returned on `ch.opened` and no `perm.changed` carries `restrictions`. Depends on decision 1 and on read restrictions (ADR 0019, proposed).

5. **Binary frames on `pm-steps/1` (PRO-020 criterion 2).** The story asks for a kit assertion that no binary frame is sent. Spec default: no test added, because the client never builds one; the owner or the kit owner decides whether a kit assertion is wanted.

## Consequences

Only the criteria listed above stay open. Ticked criteria carry their Evidence in the story files.
