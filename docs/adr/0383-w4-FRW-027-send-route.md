# 0383. The send route: method and path, refusals, the hash of an empty chain, participant marks

**Status:** proposed, 2026-11-17. Written while building FRW-027 (lane w4). 12 §6.2 defines the `send` action and 12 §10 and gap G95 leave open how it is called. Each item takes the smallest reading that works; the owner may change any of them.

1. **Method and path.** `POST /documents/{id}/workflow/send`, with no body, `requires: manage`, `Idempotency-Key` accepted (the pipeline's generic handling stores and replays the response). The operation is `sendWorkflow` of the FRW extension; its row in the permission matrix is the `manage` row (`workflow.action`). 12 §10 now names `/workflow/send` as an assumed `POST` (G95). `correct`, `resume`, `void` and `remind` are not defined by this decision.
2. **Refusals.** A caller without `manage` is `forbidden`. A workflow that is not `draft` is `conflict` (409), as `transitionProblem` of the authority maps `invalid_state` (ADR 0249 decision 10); `PUT` keeps `workflow_active` for its own refusal. A failed list is `validation_failed` (400), or `pending_suggestions` (409) when that is the only failure. The problem lists each failure as a violation: `/fields/<key>`, `/roles/<id>`, `/suggestions/<id>`, and the path of a rule problem. A document with no workflow is `not_found`.
3. **The hash of a document with no commit.** `sentHash` is `sha256:` and the chain head. A document that has no commit yet has no chain head, so the SHA-256 of the canonical JSON of its content stands for it. The webhook's `chainHead` is that value in the same case.
4. **`sentSeq` and a commit in between.** `sentSeq` is the head read before the lock is stored. A content commit that the room accepts between the read and the control commit lies after `sentSeq`, so the body that is frozen could differ from the body at `sentSeq`. The route does not close the gap. Closing it needs the room to refuse content commits from the moment the lock is requested, or the control commit to be written first and `sentSeq` read from it. Open for the owner of SYN and PRM.
5. **What the checklist reads.** The whole document at the head (`ContentReader.rebuild`), not the caller's projection, so a field in a region the caller may not read is still checked.
6. **Participant marks.** At the send each participant gets `state`: `active` for the lowest incomplete order among those who must act (`activeParticipantIds`), `pending` for the rest (a `cc` participant never acts). 12 §6.1 names no values; these two are proposed.
7. **The `sent` version.** Stored at `sentSeq` with the kind `sent` (08 §4), created by the caller's surrogate. A second creation for the same seq and kind returns the stored version.
8. **Webhooks.** `dep.workflow.sent` and one `dep.workflow.participant_activated` for each activated participant, built by `workflowEvent` (identifiers, `seq`, `chainHead`, and the participant for the participant event). Not built: `wf.changed` (FRW-035).
