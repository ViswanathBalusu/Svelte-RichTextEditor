# ADR 0238: open decisions and blocked criteria of lane UX-092-104 (round 4)

**Status:** proposed. Not decided. Each item below needs the owner, the main session or the named package's owner.

**Date:** 2026-11-13. **Lane:** UX-092-104 (round 4).

## Context

Round 4 found little in this range that can be ticked honestly. Stories UX-092 to UX-100 and UX-103 and UX-104 were handled in earlier rounds, and their remaining criteria depend on things that are not built or that sit in another package. This record lists what was checked, what was decided by default, and what is needed from others.

## Decisions and needs, by story

1. **UX-098 leftover, `verifyDelivery` reuse (not done).** The host keeps its own verifier (`apps/reference-host/src/lib/server/webhook-receiver.ts`). Reusing the service's verifier needs `signDelivery` and `verifyDelivery` exported from `services/document-service/src/index.ts`. That file belongs to the document-service owner, not this lane. The route test shows the two agree. Needed: the document-service owner or the main session adds the export.

2. **UX-098 criterion 3 (e-mail to the mentioned person), stays unticked.** Two gaps:
   - `dep.comment.mentioned.v1` carries only `data.seq` (gap G83). The event names neither the mentioned person nor the comment.
   - The host directory (`apps/reference-host/src/lib/server/directory.ts`) has no e-mail field.
   Options, not chosen here: (a) the host resolves the comment at `seq` through the control plane with its service credential, and reads the person's address from its own directory, which needs an e-mail field and seeded example addresses; (b) the event schema gains the mentioned `sub` and the comment identifier (a change to 05 section 7 and to `spec/`). The spec default is the event as written, so nothing is built until the owner chooses.

3. **UX-098 criterion 5 (development mail sink), stays unticked.** The compose stack and its mail sink belong to UX-091 (another lane). The host's sinks are in memory and a log line.

4. **UX-099 (send for completion), blocked.** The workflow resource (FRW-025) and its `send` (FRW-027) are not built: no route under `services/document-service` serves `/documents/{id}/workflow`. Nothing in the host can be wired to it. Owner decision 10 (who invites and authenticates participants) is still the default (the host).

5. **UX-100 (template gallery), blocked.** `services/document-service/src/control-plane/handlers.ts` refuses templates and imports with `validation_failed` ("not offered yet (D62)"). FRW-062 is not built, so the gallery has no resource to instantiate.

6. **UX-101 (export dialog), criteria 1 to 4 stay unticked.** The dialog (`packages/ui/src/components/ExportDialog.svelte`) takes its job feed from `core.exports`, but `packages/element` never sets `exports` on the core: a search of `packages/element/src` finds `ExportService` nowhere. `packages/element/src/export.ts` says the exports port has no progress stream, and it has no cancel or job-view adapter (PRO-086 left open). So in the product the dialog shows no targets and follows no job. Needed: a decision in PRO-086 on how the element exposes `targets`, `request`, `job` (with `export.progress` or polling) and `cancel`. Criterion 5 (`no-export`) is phase 2 and not built.

7. **UX-102 (rulers), stays unticked.** `CoreApi` (`packages/ui/src/core-api.ts`) has no paragraph indent or tab-stop view, and `CoreCommandName` has no paragraph commands (FE-129). The ruler component is not written. Unchanged from round 3.

8. **Prettier on `webhook-receiver.ts`.** A style issue remains in a file this lane edited but did not format (the rule against reformatting). Left for the owner of the file to run `pnpm format` on it when the batch is quiet.

## Consequences

No criterion was ticked in round 4. The stories' Notes say why each criterion stays open, and this record is the place the decisions above are listed for the owner.
