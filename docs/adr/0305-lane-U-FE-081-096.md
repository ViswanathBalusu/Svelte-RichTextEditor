# ADR 0305: Painter, justification and page window (lane U-FE-081-096)

Status: proposed. Lane U-FE-081-096, 2026-11-13. Owner decisions are not made here; the spec default is used and marked.

## Context

FE-090 (painter), FE-091 (justification) and FE-092 (virtualised pages) were blocked on a painter that did not exist. The layout tree (`packages/layout/src/tree.ts`) holds positions, block identifiers and CDM offsets, but no text and no font. A DOM package is needed, and it is not universal (FND-004 covers the layout package only).

## Decisions

1. **Own package.** The painter is `packages/painter` (01 section 6), a DOM package. It imports the layout's pure modules by relative path (`tree.ts`, `justify.ts`, `page-heights.ts`) and has no runtime dependencies. Proposed: the main session adds the workspace importer to the lockfile and the boundary rule in `.dependency-cruiser.cjs`.
2. **Text and font from the caller.** `PaintSource` gives the text of a CDM range and one family and size. Several fonts per line (FE-062 to FE-064) are not decided here.
3. **Justification.** Word spacing is applied to the line as CSS `word-spacing`, with the value from `justifyLine`. The trailing run of blanks is reset to zero in its own span. Default (spec silent): the last line of a paragraph is not justified.
4. **Page window.** `mountPageWindow` mounts the pages from `visiblePages` with overscan 1 by default, and keeps heights in `pageHeights`. A page is painted from the tree when it is mounted, and not diffed (FE-092 criterion 2 stays open).
5. **Line coordinates.** A line's page position is the paragraph's origin plus the line's offset, as `caret.ts` (`paintedLines`) does.

## Evidence

Chromium, Firefox and WebKit through `pnpm vitest run --project browser`: `packages/painter/src/painter.universal.test.ts` (6 tests) and `packages/painter/src/window.universal.test.ts` (3 tests), all pass in each engine. Skipped in Node.js.

## Not decided

- Whether the painter sets `font-variant-ligatures` and `font-kerning` to match the measurer (FE-090 criterion 4): open.
- Forced-colours caret and selection (FE-096 criterion 5): not built.

## Decisions for FE-093 (overlay, lane U-FE-081-096, 2026-11-13, proposed)

6. **Controls through a caller hook.** PaintOptions.control(box) returns the element for a box fragment; the painter places it in a per-page .de-overlay layer appended after the lines. The layer and the boxes take no pointer events; each control takes them. Default (spec silent): a box with no control paints as before.
7. **Overlay order.** Controls follow document order: body fragments first, then header, footer and footnotes. The spec does not say where header and footer controls sit in tab order; this is the proposed default.
8. **Control size.** A control gets ox-sizing: border-box so that it fills its box exactly, padding and border included.

## Round 4 triage (lane U-FE-081-096, 2026-11-13, proposed)

Scope checked: FE-081 to FE-096 (FE-090, FE-091, FE-092, FE-093, FE-095, FE-096 and FE-087 were handled in earlier rounds and are not redone). No criterion was ticked in this round, and no test was run, because each open criterion checked this round needs one of the following, none of which is a change this lane can finish alone.

1. **Painter caret and selection (FE-096 criterion 5, forced colours).** `packages/painter` draws no caret and no selection (no `caret` or `Highlight` use in `packages/painter/src`). The forced-colours check needs `forced-colors: active`. `@vitest/browser` 5.1.0 and `@vitest/browser-playwright` expose no media emulation (no `emulateMedia` in their typings), so the check needs a standalone Playwright spec that loads a bundled painter page. Not built.
2. **Remote commits to dirty blocks (FE-088 criterion 6).** `packages/engine/src/remote.ts` (`rebuildTransaction`) works on ProseMirror steps. No mapping from those steps to CDM block identifiers exists, so a remote commit cannot mark blocks dirty for `incrementalLayout`. The mapping belongs to the engine and is not built.
3. **Table fragment offsets (FE-083 criterion 5).** A `TableFragment` records its block identifier but no CDM offsets (`tree.ts`, built in `paginate.ts` `placeRow`); its cell paragraphs record theirs. Whether a table fragment should carry a covered range, and what that range is for a table that has no text of its own, is not specified. Proposed default, to be decided by the main session: the table fragment keeps no offsets and the cell paragraphs are the record. Criterion stays open until decided.
4. **Multi-column tables (FE-085 criterion 4).** The rule for a table in a multi-column run is the proposed one of ADR 0206; the criterion as written forbids spanning pages, and a table taller than a page is placed alone and reported. Owner decision needed on which reading applies.
5. **Pagination restart and time slices (FE-088 criterion 2, FE-089 criteria 1 and 4).** `paginate` is one closure-based pass over the whole document (ADR 0120 item 30). A restartable pass is a restructuring, not an added wrapper.
6. **Stored painted widths per browser (FE-094 criteria 1, 2, 5).** The painter takes one font family per line, so a corpus line with several fonts cannot be painted and compared. Per-run fonts (FE-062 to FE-064) are needed first. Measuring the width distribution also needs a run on the reference machine for any target figure.
7. **Read view mounting and history versions (FE-095 criteria 1 and 2).** The element does not mount the painter for `view="read"`, and the history view does not lay out a version's flow. Both are outside this lane's packages.

Needs from others: per-run fonts in the painter (FE-062 to FE-064); the engine mapping of remote steps to block identifiers (FE-088 criterion 6); the element mounting of the painter for the read view (FE-095 criterion 1); a standalone Playwright spec for forced colours (FE-096 criterion 5); owner or main-session decisions for items 3 and 4.
