# ADR 0324 (lane V-EXP-113-123): decisions taken while closing blocked criteria

Status: proposed. Owner decisions stay the owner's; each entry below names the spec default used.

## Decision 1: a cached drawing that is DrawingML XML is not a rendering picture (EXP-117, criterion 3)

EXP-117 criterion 3 says that a rendering in the file (an alternate-content fallback, a cached drawing or a picture) becomes the atom's `fallbackAsset`. The importer makes a `fallbackAsset` only from an internal image relationship (`fragmentAtom` in `packages/export-docx/src/import.ts`). A SmartArt's cached drawing is a DrawingML part (`diagramDrawing`), not an image, and the editor has no renderer to turn it into a picture.

Spec default used: a `fallbackAsset` is an image of the package. A cached drawing that is XML keeps its kind as `fallbackText` (for example "SmartArt"). The test `packages/export-docx/test/exp-117-rendering.test.ts` checks the image half on every corpus file.

Open for the owner or the spec: whether a cached drawing counts as a rendering. If it does, a renderer (or an owner decision to accept a label for SmartArt) is needed before criterion 3 can be ticked.
