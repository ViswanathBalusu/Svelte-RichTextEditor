# 0254. Lane SEC-001 to SEC-013: open questions and the default taken

**Status:** proposed (2026-11-13). Written by the security developer of lane SEC-001-013, round 1, while proving criteria in SEC-006, SEC-007 and SEC-011. Not reviewed by the owner. Each default below is the spec's own position or the code's current behaviour; no owner decision is made here.

## Context

The lane checked criteria in `docs/stories/SEC-security.md` against the code and the tests that already exist, and added one test file. Criteria that need a browser, a container, CI or a decision stay unticked, with the reason in the story's Notes. This note lists the points that need a decision and the default the lane took.

## Open questions and the default taken

1. **Policy for browser extensions (SEC-011, criteria 1 to 3).** Default taken: the position of 10 §6 (the extension item): extensions run with the user's privileges and cannot be prevented; their edits arrive as ordinary input and pass the same checks. The story stays unticked, because the decision is recorded here as proposed, not decided by the owner, and because criterion 2 (a simulated extension that mutates the DOM) needs a browser. Question: does the owner accept this position for the integration guide, and who writes the browser simulation?

2. **LaTeX writer and the CDM grammar for `link.href` (SEC-006, criterion 5).** The scheme decision of `packages/export-latex/src/emit.ts` `url()` is the same as `LINK_HREF_PATTERN` (CDM-002) for every obfuscated scheme in the SEC-006 corpus. The two differ in the body. `url()` percent-encodes a space or a quote in an `https` target and writes the link, while the grammar refuses it. The written output contains no raw space, quote, angle bracket or brace (proved in `packages/export-latex/src/sec-006-link-schemes.test.ts`). Default taken: the writer keeps percent-encoding. Question for the export owner: should the writer refuse what the grammar refuses, so that the two allow-lists are equal and not only equal in scheme?

3. **DOCX side of link checking (SEC-006, criterion 5).** Not checked in this round. `packages/export-docx/src/writer.ts` handles only `#` targets for bookmarks and writes other `href` values; the lane did not read the relationship write path to see whether an allow-list is applied. Default taken: criterion 5 stays unticked. Question for the export owner: confirm the DOCX writer applies the same allow-list, with a test.

4. **Activation criterion of links (SEC-006, criterion 2).** The rendered DOM carries `rel="noopener noreferrer"` (`packages/engine/test/web-view-safety.test.ts`). Default taken: that attribute is the mechanism, and the criterion stays unticked until a browser activates a link.

5. **Token lifetime and audience wording (SEC-007, criteria 4 and 5).** Default taken: "a lifetime above 15 minutes" is tested as `exp` more than 15 minutes after `iat`, and "an audience other than the service's" as the case, prefix and suffix variants of `aud`, both in `tests/security/test/token-confusion.test.ts` (memory run). An expired token is refused by the skew rule. The docs claim check is the forbidden answer of the same file. No new code was needed.

## Not done this round, and why

- SEC-005 criteria 1 to 4 need the corpus through the wire in every attribute and text position of the CDM, and the browsers for criteria 2 and 3. The corpus is not written. Criterion 5 is already ticked.
- SEC-007 criteria 1 to 3 need a full browser session and a scan of storage, network and console.
- SEC-009 has no criterion run in this round. Criterion 5 (the integration guide statement about the open shadow root) is not yet in the guide; the open shadow root is mentioned only in the specification, ADR 0039 and the spike note.
- SEC-001 criterion 5 (second maintainer review) and SEC-003 (threat-model review at phase end) are human process steps.
- SEC-002 criterion 5 (the adversarial client's suite against the compose stack) needs Podman and the BE-005 stack, which were not running.

## Round 2 (2026-11-13): SEC-009 and SEC-010

Written by the security developer of lane SEC-001-013, round 2. Status: proposed. Nothing here is an owner decision.

6. **Font registration in the component (SEC-009, criterion 1).** The FE-061 module `packages/element/src/font-registration.ts` is tested in isolation, but the component does not call `registerFontFiles`. The KaTeX faces in `packages/element/src/features/math.ts` are added under their own family names. Default taken: criterion 1 stays unticked, because the story asks for the component's registration. Question for the element owner: should math.ts register through the hash-alias module, and should the story's criterion be read as the module's contract until then?

7. **Version collision reported as `de-error` (SEC-009, criterion 3).** `packages/element/src/register.ts` reports a second version with `console.warn`. The story says `de-error`. Default taken: stays unticked. Question: can the warning also be raised as `de-error` on the first instance that is mounted, since the registry has no host to dispatch to before that?

8. **Assistant output as suggestions (SEC-010, criterion 3).** The authority stores an assistant commit with its origin and agent, and does not convert it to a suggestion. Default taken: unticked until UX-045 and UX-046 insert the output. Question for the owner of the assistant: is the suggestion mark a shell rule or an authority rule?

9. **Action approval and the port's chunks (SEC-010, criterion 2).** `AssistantChunk` has text, done and error kinds only, so a model response cannot ask for a tool call. That is a structural property, and no test shows it as a control. Default taken: unticked. Question: should the port's type be frozen by a test so that a future action kind forces a review?
