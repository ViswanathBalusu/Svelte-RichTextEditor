# ADR 0303: Decisions taken by lane V-FE-049-064, round 4

Status: proposed. Owner decisions are not made here; each item below is the spec's default or a
default taken where the spec is silent, for the owner to confirm.

## Context

Round 4 of lane V-FE-049-064 closed FE-055 (criteria 2 to 4) and built part of FE-054 and of FE-053
(criterion 3, the engine's part). Where the spec left a choice open, these defaults were taken.

## Decisions

1. Paste order for HTML (FE-054; 02 §5.2). An embedded CDM fragment comes first, then HTML that the view
   reads through the whitelist, then plain text, then picture files. Plain text is therefore used only
   when the HTML yields no text. FE-052 criterion 3 was reworded in its test to match: its HTML now
   yields nothing (a script), so the plain text is pasted.
2. Foreign HTML mapping (FE-054). Block elements become paragraphs. `strong` and `b` become bold, `em`
   and `i` italic. A line break becomes a space. Headings and list items become paragraphs (headings
   are not mapped to the document's heading styles). Tables become paragraphs per cell. `img` is dropped
   and no picture is uploaded from HTML (FE-053 notes). Links keep their target only when it matches the
   model's link pattern (I9).
3. Paste opens the fragment at both ends (`openStart` and `openEnd` of 1), so the first and last
   paragraphs join the text around the caret, as a paste does.
4. Placeholder text (FE-053 criterion 3). The widget reads "Uploading picture" and carries the class
   `de-picture-placeholder`. The text is the engine's default; the shell may restyle it.
5. Print and copy refusals (FE-055). A refused print returns `{ status: 'refused', reason: 'no-print' }`
   and the core raises no error. A refused copy is recorded as a refusal, and the shell explains it.

## Consequences

- Criteria still open are recorded in the story notes: FE-054 criteria 2 (resource loading not measured),
  4, 5 (Trusted Types), 6 (pictures in HTML) and 7 (fuzz corpus); FE-053 criterion 3 (the shell's message).
- `DOMParser.parseFromString` is a sink for Trusted Types. The engine has no named policy yet; the
  element's policy (`packages/element/src/trusted-types.ts`) is not wired into the engine. Needs the
  main session or the element lane.
- Fixer round 4 (2026-11-14), proposed: the view parses clipboard HTML through
  `packages/engine/src/view/paste-policy.ts`, in this order: no policy where the page has no Trusted
  Types; the host's `default` policy where there is one (as ProseMirror does); else a project-owned
  policy named `docedit-paste`, created on the first HTML paste. If none works, the parse yields null
  and the plain text is pasted; the handler never throws. The policy lives in the engine because the
  engine creates it (the element imports the engine, not the reverse). The name is not yet in the
  integration guide or the element's policy list: that needs the guide's owner (FE-017). Until it is
  listed, a host that allows only `ProseMirrorClipboard` gets one `trusted-types` violation per page
  on the first HTML paste and the plain text. Tested by
  `packages/element/e2e/fe-054-paste-trusted-types.spec.ts`.
- The picture placeholder is split (FE-121): the core keeps only the pending ids and positions
  (`picture-placeholder.ts`); the widget is drawn by `view/picture-placeholder-view.ts`, which only
  the web view registers.
- Round 5 (2026-11-14), the name `docedit-paste` is now listed in `apps/reference-host/docs/integration-guide.md`
  (Paste section), `packages/element/docs/policies-and-side-effects.md` (Paste section and the policy
  list), the S2 GUIDE map in `packages/element/e2e/s2-features.spec.ts`, and the published-policy test
  `apps/reference-host/test/integration-guide.policy.test.ts`. This closes the blocker recorded above.
  Item 1 (HTML before plain text) still awaits the owner's confirmation.
- Round 5: keyboard copy and paste (FE-050 criterion 4) run in `packages/element/e2e/fe-050-copy-paste-keyboard.spec.ts`:
  Chromium and Firefox pass; WebKit is skipped there (no readable clipboard under Playwright on Windows).
- The `ux-040-no-print.spec.ts` e2e can fail on a cold WebKit start, because it does not wait for the
  backend's features. This is not changed here (another lane's file).
