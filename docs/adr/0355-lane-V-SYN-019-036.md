# ADR 0355: Open items in SYN-019 to SYN-036 (lane V-SYN-019-036)

Status: proposed. Owner or main-session decisions pending; no spec default was applied silently.

## Context

Round 1 of lane V checked the unticked criteria of SYN-019 to SYN-036. Every other criterion in the range is ticked. The four that remain are blocked by a decision, or by a producer that is not built, not by a missing test environment. The PostgreSQL outbox test (`services/document-service/test/data-plane/syn-030.outbox.pg.test.ts`, 3 tests) and the presence engine tests (`packages/engine/test/presence-*.test.ts`, 11 tests) were re-run and pass on 2026-11-13.

## Open items

1. **SYN-028 criterion 4 (`catchUp: "page"`).** The spec (04 §9) lets the client read `GET /documents/{id}/commits`. ADR 0038 decided that the session reloads the content instead, and no port member reads that resource. Decision needed: keep the ADR 0038 reload (criterion stays unticked, or the criterion is amended), or add the port member and the paging read.

2. **SYN-030 criterion 3 (deterministic commit identifier).** The spec (08 §2) says "derived for server-authored commits" without a formula. The prefill route (`services/document-service/src/control-plane/field-routes.ts`) uses `uuid7(now)` for the commit identifier, persisted in the outbox row at enqueue, so a redelivery after a crash reuses it. A retry of the HTTP request is a new operation and is refused by its preconditions once the head has moved. Options: (a) a derivation from the tenant, document and a client idempotency key, in a UUID version 7 shape; (b) keep the persisted identifier and amend the criterion. Decision needed.

3. **SYN-032 criterion 6 (checkpoint saves comment ranges).** Same open choice as `docs/adr/0355-lane-U-SYN-019-036.md`: anchors at the durable head only, or anchors kept per checkpoint `seq`. Decision needed before the side object (`checkpoints/{seq}.side.json.zst`) can be written and tested on PostgreSQL and the object store.

4. **SYN-036 criterion 5 (the receiver draws the caret).** The shell layer exists (UX-027, `packages/ui/src/shell/carets.ts`), but no code produces a `PeerCaret` from the receiver's placed positions. The engine has no `carets` view and the element does not map positions to rectangles. This is cross-package work (engine, element, ui) and needs a browser test with two sessions when built.

## Consequence

No criterion in SYN-019 to SYN-036 was ticked in this round. The story Notes for SYN-036 were corrected to the present state.
