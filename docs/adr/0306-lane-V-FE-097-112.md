# ADR 0306: Lane V-FE-097-112 decisions (proposed)

Status: proposed (2026-11-13, lane V-FE-097-112). Decisions made while closing the browser and
container gaps of FE-097 to FE-112. None changes the spec; each is a reading or a test choice.

## 1. WebKit and the collapsed caret in a shadow root (FE-111 criterion 2)

WebKit gives the selection of a shadow root retargeted to the document: its anchor is the shadow
host's parent at offset 0, and the collapsed caret range has no client rects. Chromium and Firefox
read the caret inside the root. `packages/element/e2e/fe-111-visual-caret.spec.ts` therefore skips
WebKit and measures the caret in Chromium and Firefox only. Criterion 2 stays open for WebKit. The
options are a WebKit-specific measurement through the editor's own DOM positions, or a visual test
run by a person; neither is chosen here.

## 2. Presence test timing (FE-107 criterion 3)

`packages/element/e2e/fe-107-presence-live.spec.ts` waits 1.5 seconds after the reader mounts before
the peer joins. The reading is from `presence-notices.ts`: the reader's first presence list is its
baseline, so a peer present in that list is not announced. The wait is a test choice, not a product
figure; the product's baseline window (`DEFAULT_PRESENCE_BASELINE_MS`, 500 ms) is a provisional
default from an earlier lane and is not changed here.

## 3. Forced-colours focus indicator (FE-103 criterion 4)

The check accepts an outline of at least 2 CSS pixels as the visible focus indicator under forced
colours, the threshold the earlier test in `packages/ui/e2e/fe-103-keyboard.spec.ts` already used. The
threshold is a test choice; the spec does not give a width.

## 4. Axe scope for ID references (FE-108 criterion 4)

`packages/element/e2e/fe-108-axe-idrefs.spec.ts` runs the axe rules `aria-valid-attr-value` and
`aria-valid-attr` through the shadow root on two states (the default editor and the editor with the
toolbar and the status bar). Overlays, panes and dialogs are not reached and are not claimed.

## 5. Shared Playwright output

The shared `packages/element/test-results/playwright` folder is cleared by each Playwright run, so
concurrent runs in this tree delete each other's traces (`browserContext.close: ENOENT`). Lane runs
use `--output <scratchpad folder>`. The config is not changed (root configuration is not this lane's).

## 6. Stand-in sizes for wide content (FE-106 criterion 2, round 2)

The model gives table cells and images no width, and an image node renders an empty span
(`packages/engine/src/schema.ts`). `packages/element/e2e/fe-106-wide-content.spec.ts` therefore
injects a style into the element's shadow root that sizes a cell or the image span at 600 CSS pixels.
The stand-in is a test choice. The rule added to `packages/element/src/styles/reflow.css` for
`.de-image` (an inline-block with `max-inline-size: 100%`) is a product decision: it holds an image to
its paragraph's width rather than letting it scroll. The image rule was reached only through the
stand-in, so a real sized image is not yet shown in the web view.

## 7. Inline targets are outside the 24 by 24 rule (FE-104 criterion 5, round 2)

`packages/element/e2e/fe-104-target-size.spec.ts` measures the controls of the shell and leaves out
the footnote reference in the document's text. The reading is WCAG 2.2 criterion 2.5.8's inline
exception (a target in a sentence). The spec does not state this exception; the owner or the
accessibility specialist confirms it.

## 8. A list parent for numbered paragraphs (FE-105 criterion 3, round 3)

Axe reports `aria-required-parent` on each numbered paragraph of the editing surface, because a
`listitem` has no `list` ancestor (checked by `packages/element/e2e/fe-105-axe-list-parent.spec.ts`
in Chromium, 2026-11-13: 3 violations). The paragraphs sit in the contenteditable surface, and the
model has no list node, so no wrapper is added. The candidates are an `aria-owns` owner (a `list`
element outside the paragraphs that owns their ids) and a `list` on a wrapper decoration. Neither is
chosen here: each changes the accessibility tree that the FE-126 screen-reader passes will judge.
The spec test is written as an expected failure (`test.fail`), so it stays green while the gap is
open and turns red when a design closes it; the mark must then be removed and criterion 3 ticked.

## 9. Block granularity keeps block-level page starts only (FE-100 criterion 4, round 3)

09 §7 says block-level page starts are the guaranteed minimum. The reading taken: at block
granularity only a page start at offset 0 of its block is adopted; a start inside a block is kept
on the editor's own break (listed in `keptOwnPages`). The earlier code adopted such starts. The
reading is this lane's and is not stated by the spec; the owner may give a different one.

## Open for the owner or the main session

- A default for the presence baseline window and for the live-region politeness is still open (the
  spec's open questions 26 and the baseline entry); not decided here.
- `@axe-core/playwright` is available to the element's tests (used by `fe-019`), so no package change
  was needed for axe.
