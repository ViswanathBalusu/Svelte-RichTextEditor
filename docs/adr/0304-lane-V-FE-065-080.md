# ADR 0304: lane V-FE-065-080 (round 1)

Status: proposed. Date: 2026-11-13. Owner decisions are not made here.

## Context

Lane V closes the criteria of FE-065 to FE-080 that were blocked on a browser, a container or
a decision. Stories were claimed by an "In progress" line while worked on.

## What was done

- FE-066 criterion 5 (paragraphs, headings, tables and images exposed natively) ticked. Proof:
  `packages/element/e2e/fe-066-native-exposure.spec.ts`, the browser accessibility tree of the
  editing surface in Chromium, Firefox and WebKit. This is not a screen reader run.

## Open points, not decided here

1. FE-069 criterion 3 (KaTeX fonts through the FontFace API under hash aliases, FE-061). Not built.
   KaTeX's stylesheet selects a face by family name, weight and style. FE-061 gives each file its
   own family alias (its hash), so the KaTeX rules cannot pick a face by weight. Proposed default
   (spec default: FE-061 aliases per file): generate a stylesheet at build time that maps each
   KaTeX face to its alias with the weight and style of its file, with no `@font-face` in the
   shadow root. The hashes of the 20 KaTeX `woff2` files need a generated table checked by a test.
   Needs a main-session decision on the build step before it is built.
2. FE-080 criteria 1, 2 and 4 (Unicode line breaking). No line-breaking test data exists in the
   repository, and no bundled implementation. A dependency and a download of the test data need
   the owner's approval (the download and the package decision are not made by this lane).
3. FE-066 criteria 1, 3 and 6. Criterion 1 needs the composition matrix to pass in Firefox (earlier
   run: 6 failures of 114 in two groups). Criterion 3 needs a visible check of the spellcheck
   underline. Criterion 6 needs the panels of FE-057.
4. FE-073 print path: the viewer has no print message and no `print()` method on the element.
   Changes in `doc-editor.ts` and the viewer frame are another lane's (PRO-079, PRO-086).

## Round 2 (lane V-FE-065-080, 2026-11-13)

Stories this round: FE-073 (probe and blocker), FE-078 and FE-077 (decisions recorded in Notes).
No criterion was ticked in round 2.

### 1. FE-073 criterion 1: a print from the viewer frame needs a sandbox decision (owner)

Evidence: `packages/element/e2e/fe-073-print-sandbox.spec.ts` (Chromium, Firefox, WebKit, 3 passed).
The viewer frame is `sandbox="allow-scripts allow-same-origin"`. Chromium refuses
`window.print()` in it: "Ignored call to 'print()'. The document is sandboxed, and the
'allow-modals' keyword is not set." Firefox and WebKit log nothing, so a silent return cannot
show whether anything printed.

FE-071 (and `viewer-frame.ts`) rules out `allow-modals`. Options, none decided here:

- (a) a second, print-only frame with `allow-scripts allow-same-origin allow-modals`, created
  for one print and destroyed after it. Smallest change; it widens the policy for that frame
  only, and PDF scripts still do not run (the viewer never enables them).
- (b) print without `window.print()` in the frame, for example a print of the PDF's bytes
  through the browser's own PDF viewer. Not checked here; depends on the browsers.
- (c) keep printing out of the component (the host prints the signed URL). Changes FE-073's
  criterion 1 as written, so it needs the owner.

Spec default for an open choice: none is stated. This lane does not pick one, and it does not
add `print()` to the element, since a `print()` that cannot print would report success falsely.

### 2. FE-078 criterion 2: the offsets a table, row, cell or box covers (spec question)

`tree.ts` records `blockId` on table and box fragments and `rowId` and `cellId` on rows and
cells, but no offsets on them. Paragraph fragments and lines do carry CDM offsets. The flow
blocks of a table and a box (`flow.ts`, `FlowTable`, `FlowBox`) carry no offset range either,
so the criterion has no source to copy from. Options, none decided here:

- (a) the offset range of a table or box is the range of its first and last paragraph in CDM
  order, which is a single value per cell paragraph and not per block;
- (b) a block-level offset range added to `FlowTable` and `FlowBox` in `toFlow` (CDM block
  positions), then carried to the fragments in `tables.ts` and `paginate.ts`.

Option (b) is the one that fits "the document offsets it covers". It changes several layout files
and has to be decided by the layout owner; it is not done in this round.

### 3. FE-077 criterion 1: the cascade is local to `flow.ts`

`packages/model/src/cascade/resolve.ts` exports `resolveParagraph` and `resolveRun`. `flow.ts`
keeps its own `chainValue`, `paraValue` and `runValue`. Replacing the local cascade with the
model's functions changes the output of `toFlow` and of every test that reads it. Not done
here; the change is a planned refactor for the layout owner, and it needs the output change
listed first (see FE-077 criterion 3, docs/adr/0205-lane-FE-066-078.md).

## Round 3 (lane V-FE-065-080, 2026-11-13)

Stories this round: FE-068 (criteria 1 to 3 ticked) and FE-065 (criterion 1 ticked, criterion 3 in part). Evidence is in each story's Evidence line.

### 1. FE-068 open question 28 (guides after an edit since `seq`): proposed default, not decided

Spec 02 §7 says guides are exact only at block starts reported by a compile and drift between compiles. This round draws the starts that the last completed export reported and does not compare its `seq` with the document. Criterion 4 of FE-068 stays unticked until the owner decides. Owner decision needed: keep drawing the reported starts (this round's behaviour), hide the guides after the first edit, or show them as stale.

### 2. FE-068 config key `pageGuides` (new key, working name)

`pageGuides` (boolean, default `false`) is added to `DocEditorConfig`, `NormalConfig` and `config.schema.json`. The name is a placeholder, like the other names of the set (CLAUDE.md). The source of the guides is the `layout` URL of a completed export (`requestExport`, `ExportResult.layout`); the element has no other route to a `layout.json`.

### 3. FE-065 "Web layout" label: the constant, not an overridable string

The label is `VIEW_STRINGS.web` (view-select.ts), a constant. Strings are meant to be replaceable (13 §8, UX), and `setStrings` does not cover it yet. Owner or UX decision: move it into the strings module so that `setStrings` can override it.

### 4. FE-065 `view` change between read and web

A change between web and print keeps the session (the test checks the surface node and the text). A change to or from `read` closes or opens a session through the same reconcile a new document takes, because the read view has no editing core. Criterion 3 says the core is not recreated for any change, so it stays unticked: an owner decision is needed on whether `read` can keep a suspended core, or whether criterion 3 excludes the read view.

### 5. Shared files touched by this round (small exact edits)

- `packages/engine/src/view/web.ts` (`setPageGuides`, one decoration set), new `packages/engine/src/page-guide-decorations.ts`.
- `packages/element/src/config.schema.json` and `packages/element/test/config.test.ts` (the key list of the config test gets `pageGuides`; the schema test requires every config key to be in both).

### 6. Not attempted this round, with the reason

- FE-070 criteria 1, 3, 4, 5, 6, 7: no equation node view in the engine, so no user action reaches the math editor (FE-069 Notes); the math editor UI is not built. Needs the engine node view and the editor's UI.
- FE-072 criterion 4: moving the editor to a diagnostic's block needs an editing core and the user's edit right; the read view has neither.
- FE-073 criterion 1: needs the owner decision on the viewer frame's sandbox (options in item 1 of round 2 above).
- FE-075 criterion 1: needs the S5 result, which is not in the repository.
- FE-076 criterion 6: the S7 recommendation is to fork Docen's layout types; the fork needs the pinned commit, the licence text and a download, which the owner must approve.
- FE-079 criteria 3, 4 and 6: the painter's CSS and the font-file provider are not built; the choice needs S5.
- FE-080 criteria 1, 2 and 4: a bundled UAX #14 implementation and its test data are needed (dependency and download are the owner's).
- FE-067 criterion 3: needs the element's asset URL path (PRO-091); the engine draws no image source.

### 1. FE-076 criterion 6: a spike adapter behind the layout API (owner decision 25)

The criterion applies when S7's recommendation is used. S7 recommends forking Docen (spike section 5.1). The page view is decided at the gate after S5, S7 and S10 (owner decision 25). The engine uses no forked core, and `packages/layout/src/docen.ts` is a spike adapter with a stand-in canvas. Putting it behind `layoutFlow` now would decide the fork early. Proposed default: leave the criterion open until decision 25 is made. Note added to FE-076 Notes.
