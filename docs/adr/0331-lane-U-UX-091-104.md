# ADR 0331: lane U-UX-091-104, round 1 (proposed)

Status: proposed. Written by lane U-UX-091-104 (round 1, 2026-11-13). Owner decisions are not made here.

## Context

The lane closes the criteria of UX-091 to UX-104 that were blocked on a browser, PostgreSQL, object storage or a container. Stories UX-091, UX-092, UX-094, UX-097, UX-098 and UX-104 were handled in earlier rounds and are not repeated.

## What this round did

1. UX-093 criterion 6 and UX-095 criteria 1, 2, 4 and 6 are ticked on a browser run of `apps/reference-host/e2e/u-ux-091-104-share.spec.ts` against the demo stack. Chromium and Firefox passed; WebKit failed at the demo sign-in.
2. The demo stack ran as Podman project `docedit-u-ux-091-104-demo` on ports 56310 to 56313 (`apps/reference-host/scripts/stack.ps1 up -NoExport`). Its containers and volumes belong to this lane and are removed when the lane finishes.
3. `apps/reference-host/src/lib/share/ShareDialog.svelte` gained `trapFocus`, which keeps Tab and Shift+Tab inside the open share dialog. Before it, the browser let focus leave the dialog past its last control. This follows the criterion's wording ("focus is trapped correctly"). It is a choice of mechanism, not an owner decision.

## Decisions taken to finish criteria (for review)

- D1. Focus trap: a `keydown` handler on the native `<dialog>` wraps focus. The spec default (native modal behaviour, with the return of focus on Escape) is kept; the wrap is added on top. Proposed; reviewer to confirm.
- D2. The spec signs in by the person's name rather than with `signIn` from `e2e/support.ts`, because that helper waits for a trailing slash on `/as/<sub>/` which the host does not send. The helper itself is not changed here (shared by the UX-092 spec, not this lane's file).

## Open, not decided here

- O1. WebKit: after the demo sign-in the host shows a 404 page, so no WebKit run of the share spec passes. Not diagnosed. Needs a look at the host's routing in WebKit, owner of `apps/reference-host`.
- O2. `support.ts` `signIn` expects a trailing slash; `host.spec.ts` and the other specs that use it may fail the same way in some browsers. Not checked.
- O3. UX-093 criterion 3 (flush and the return of unconfirmed work to the journal) needs the journal (FE-008) and a flush that can reject. Not built. (Closed in round 6: both are built, and the criterion is ticked on a browser run; see round 6 item 2.)
- O4. UX-095 criterion 2, the "next token" sentence, is tested only at unit level (`share-model.test.ts`), because a browser run needs a person with no role on the document.

- UX-099 (send for completion): needs the workflow resource of the document service (FRW-025, FRW-026, FRW-040). No `workflow` route exists in `services/document-service/src/control-plane`.
- UX-100 (template gallery): needs the templates resource (FRW-061, FRW-062). No `templates` route exists in `services/document-service/src/control-plane`.

## Round 6 (2026-11-14, lane U-UX-091-104)

Status: proposed. Owner decisions are not made here.

1. UX-091 criterion 1 (one command starts the stack from a fresh clone) stays unticked. The start path is proven with `scripts/stack.ps1 up`; the literal reading (a fresh clone, a compose command) is for the owner. Default used: unticked.
2. UX-093 criterion 3 is ticked on the browser run `apps/reference-host/e2e/u-ux-091-104-flush.spec.ts` (Chromium and Firefox; WebKit fails at the demo sign-in, item 3). The first version of the test refused the service with `page.route`, which does not intercept the editing WebSocket, so the work was confirmed and `flush` resolved; that was a test artefact, not an element question, and the element question it raised is withdrawn. The reworked test routes the WebSocket (`context.routeWebSocket`) and drops the page's `sync.submit` frames: `flush` rejects at the guard's 3000 ms timeout, the guard takes its `kept` branch, the work stays in the journal, the service does not have it, and it reappears and is stored when the document is opened again. The evidence is in the story.
3. The reference host's demo sign-in returned a 404 page in WebKit after the person was chosen (seen in the UX-091, UX-092 and UX-093 browser tests). Diagnosed and fixed in round 9 (see the round 9 section below): the sign-in redirected with 303 to `/as/<sub>/`, SvelteKit answered 308 to `/as/<sub>`, and WebKit replayed the sign-in POST to `/as/<sub>` (404). The redirect now goes straight to `/as/<sub>`.
4. The demo stack of this lane ran as project `docedit-u-ux-091-104-demo` on ports 56310 to 56313 (`DOCEDIT_DEMO_PROJECT`, `DOCEDIT_DEMO_PG_PORT`, `DOCEDIT_DEMO_S3_PORT`, `DOCEDIT_DEMO_SERVICE_PORT`, `DOCEDIT_DEMO_HOST_PORT`). `stack.ps1 reset` ran once (UX-091 criterion 7). The stack is stopped and its volumes removed when the lane finishes.

## Round 9 (lane U-UX-091-104, round 9, one developer)

Status: proposed. Owner decisions are not made here.

1. WebKit sign-in fixed (fixes item 3 above). Cause, measured in Playwright WebKit against the reference host's dev server (port 56313, host configuration from environment only, no service): `POST /?/signin` gets 303 to `/as/<sub>/`, which SvelteKit (trailing slash `never`) answers with 308 to `/as/<sub>`; WebKit then re-sent the sign-in form body as `POST /as/<sub>`, which has no action and returns 404. Chromium follows the same chain with a GET. Fix: `apps/reference-host/src/routes/+page.server.ts` redirects to `userPath(sub)` with no trailing slash, so no 308 follows. The test expectation in `apps/reference-host/test/share-routes.test.ts` (`location`) changed to match. `share-routes.test.ts` and `routes.test.ts` pass (11 tests, Node.js). The WebKit probe script is a scratch file, not part of the repository; the same probe after the fix shows `GET /as/<sub>` 200 in both engines.
2. Consequence for the browser tests: the WebKit results of UX-091, UX-092, UX-093 and UX-095 that failed at the sign-in can now reach the editor. No WebKit browser run was made in this round against the demo stack (it needs the stack), so no criterion is ticked from WebKit.
3. No criterion was ticked this round.
