# ADR 0219: Open points of the PRO-113 to PRO-126 lane (round 3)

**Status:** proposed (2026-11-13, lane PRO-113-126). Nothing here is decided by the lane. Each point
keeps the spec default, or stays unticked, until the maintainer or the owner decides.

## Context

Round 3 of lane PRO-113-126 ticked PRO-126 criterion 5: a server without the test hooks skips the
fault-injection profile, and the README states what is then unproven. Reading the other open stories
of the range (PRO-114, PRO-116, PRO-124, PRO-125) raised the points below, which the spec leaves open
or which need something not built yet.

## Points

1. **Feature name for the test hooks (PRO-126).** 05 §11 says the fault-injection profile applies to
   "servers that expose the test hooks", and 06 §8 does not name a feature. The lane added the
   profile with the requirement `features: ["test-hooks"]` (`packages/tck/src/profiles/fault-injection.ts`).
   Spec default: none, so `test-hooks` is the kit's proposal only. DEP has no such feature name, and
   the hook interface (held writes, fencing, rewind, a delayed grants notification) is not specified.
   Criteria 1 to 4 of PRO-126 stay unticked until a server exposes the hooks.

2. **How a relay client learns the head (PRO-124).** A relay serves no content (`packages/authority/src/room/relay.ts`,
   header). The kit's join helper reads content over REST first (`packages/tck/src/profiles/support.ts`,
   `join`), so it cannot start a relay scenario that way. The spec does not say how a relay client
   learns the head (05 §5.2 `ch.opened` `head` is one candidate). No `core-relay` scenario is written
   until the owner or the maintainer chooses. The profile stays `pending`.

3. **Authority service profile (PRO-125).** 05 §10 makes the authority service a network interface, and
   PRO-102 (the wire binding) and PRO-103 to PRO-107 are not built. The profile cannot call
   `open`, `applyCommit` and the others until a binding exists. Spec default: none stated. Nothing is
   written for it in this lane.

4. **Assets and the cross-document refusal (PRO-114 criteria 1 and 3).** The `assets` profile in
   `packages/tck/src/profiles/jobs.ts` has never run, because no target announces `assets`. Whether
   the one-hour fuzz target (PRO-116 criterion 4) is met is a run decision, not code: the kit keeps
   the seed, batch and input in each failure message, and no run of the target length was made here.

## Consequences

None of the points changes code in this lane beyond the fault-injection profile, its README row and
its tests. The owner or the maintainer decides points 1 and 2 before the criteria that depend on them
can be ticked.
