# ADR 0332: Lane V-BE-001-014 decisions (BE-004, BE-005)

**Status:** proposed (2026-11-13). Recorded by lane V-BE-001-014; the owner accepts or changes it.

## Context

Round 3 of the BE-001 to BE-014 range asked for the blocked criteria to be closed against the real
environment where possible. The spec leaves some choices open. This record states the choice made
for each, so that the owner can accept it or change it.

## Decisions

1. **Azure Blob write-once is atomic.** `AzureBlobObjectStore.put` sends `If-None-Match: *` and treats
   409 or 412 as an existing object. Azure applies the condition inside the write, so no separate
   existence check is made (unlike the S3 adapter, ADR 0036).
2. **Azure signed URLs are service SAS URLs, read only, version 2021-08-06.** The expiry is the
   `expiresAt` of the port, written to whole seconds. The default account endpoint is
   `https://{account}.blob.core.windows.net`, and the default container is `docedit`.
3. **The Azure store is selected by `DOCEDIT_AZURE_ACCOUNT`.** Its other settings are
   `DOCEDIT_AZURE_ENDPOINT`, `DOCEDIT_AZURE_KEY` and `DOCEDIT_AZURE_CONTAINER`. Setting both the S3 and
   the Azure settings is refused by `checkConfig`, so an operator chooses one store.
4. **Tests use the Azurite emulator.** The emulator's public account key is a known constant, not a
   secret. The emulator is started by the lane in Podman on a port of the lane's range. Criteria are
   proven against the Blob service API of the emulator, not against a live Azure account.
5. **Criterion 4 of BE-005 (no network in the export worker).** The test inspects a container
   created from the export-worker options of `infra/containers/compose.json`. It is not the demo
   stack in `apps/reference-host/compose.json`, which still gives the worker host networking.
   Choosing the demo worker's network is the owner's (see `docs/adr/0114-reference-host-backlog-batch.md`).

## Not decided here

- Whether the CI workflows run the PostgreSQL, S3 and Azurite suites (FND-010; a root configuration
  change).
- The helm chart of BE-006 and the authority container of BE-007 (not built).
- The acceptance of ADR 0020 (hash-partition count, BE-008), which is the owner's decision.
  Settled: decision 137 (2026-11-17) accepts 64.
- Whether `node_leases` (migration 0033, exempt from tenant rules as a node table) meets BE-011
  criterion 1 ("any table ... has a `tenant_id` column"). The spec default is every table; the
  exemption needs the owner's decision in 06 §4.1. Settled: decision 195 (2026-11-17) allows
  `node_leases` without a tenant column. 06 §4.1, 10 §3.7 and BE-011 criterion 1 now say
  "every table that holds tenant data" (lane w5, BE-011).

## Round 4 (2026-11-14)

6. **BE-014 criterion 1 runs the job, not only the structure.** The `audit.partitions` task moved
   into `src/control-plane/audit-partitions-task.ts` so that a test can run it through the
   scheduler. The task's behaviour is unchanged (daily, `ensurePartitions()`).
7. **BE-012 criterion 3 ("connection or request") is read as satisfied by the request path.** The
   origin change is tested at the next HTTP request. The WebSocket connection check has no test in
   this lane. Owner may ask for that test.
8. **BE-009 and BE-010 criterion 1 are proven by catalogue assertions on a fresh database.** The
   older `schema.pg.test.ts` keeps its stale table list; its author updates it.
9. **Lease ids are kept in `grant_history`** (`src/storage/grant-store.ts`, `toJson`). The PostgreSQL
   store assigns the id; the contract check at `test/contract/checks.ts` line 407 still expects the
   lease without it. Not changed here.
10. **BE-008 criteria 2 and 3 stay open.** The partition count is the owner's decision (ADR 0020).
