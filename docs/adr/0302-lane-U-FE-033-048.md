# ADR 0302: Lane U-FE-033-048, decisions taken while closing FE stories

Status: proposed (2026-11-13). Lane U-FE-033-048, round 3.

## Context

The FE stories 033 to 048 have criteria that a test could not close in earlier rounds. This lane
closed some of them and recorded the rest. Two choices were made that the spec does not settle.

## Decisions (spec default taken, for the owner to confirm)

1. The body view draws the suggestion marks in the `all` markup view by default
   (`packages/engine/src/view/web.ts`). The spec gives the review views' control to UX; until the
   control exists, every suggestion carries its class in the editing surface.
2. A row or table suggestion is marked with an `ins` or `del` node mark. The view currently renders
   such a mark as an element around the block, which puts a wrapper inside `tbody`. The test
   `packages/engine/src/view/suggestion-rows.universal.test.ts` records this as a known defect
   (`it.fails`). Options for the owner: render block marks as decorations only (the view skips the
   mark's element for block nodes), or change the CDM mark's `toDOM` in `@docedit/model`. Not decided.

## Consequences

- FE-043 criterion 4 and FE-048 criterion 2 are ticked on Node.js tests against the real authority room.
- FE-045 criterion 1 stays open until decision 2 is taken.

## Round 6 (lane U-FE-033-048, 2026-11-14)

Status: proposed.

1. Shell mode control (FE-041 criterion 1). Fixed, not a decision: the element's shell adapter did not pass `mode`, `modes` or `setMode` to the shell, so the switcher never rendered for any user. The adapter now passes them, offering `edit`, `review` and `view`. Default taken: `fill` is not offered by the element switcher, because the fill participant's view is FRW's. Owner may decide otherwise.
2. Refusal count (FE-047 criterion 6). Default taken: a suggestion command that skips suggestions reports the count on the `refusal` view (optional `count`) and the shell names it with `notice.suggestions.skipped`. Only the `scope` reason carries a count.
4. Round 8 (2026-11-14). Wording of the suggestion refusal (FE-044 criterion 5). Default taken: the shell string `reason.query.suggestion` in `packages/ui/src/i18n/en-GB.ts` says that suggestion mode cannot record the change, so it is not made. The spec gives no wording; UX owns the final text. Table commands (FE-045 criterion 5) have no shell entry yet (UX-003), so their reason is not shown; this stays open.
3. Block suggestions drawn as wrappers (FE-044 criterion 4, FE-045 criterion 1 and 6, FE-046 criterion 1, block part). Not decided here. prosemirror-view 1.42.9 applies a node's marks to block children in `updateChildren` (`syncToMarks`, `dist/index.js`), so a block-level `ins` or `del` node mark is drawn as an `<ins>` or `<del>` element around the `tr`. A mark's DOM cannot be omitted, so decorations alone do not remove the wrapper. Options for the engine or CDM owner: (a) carry block suggestion state as a node attribute rather than a mark (a CDM and schema change, so an owner-level decision under the CDM); (b) keep the marks and accept the wrapper, which contradicts FE-045 criterion 1. Until one is chosen these criteria stay unticked.
