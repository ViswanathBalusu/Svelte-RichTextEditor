# ADR 0358: Lane U-HIS-017-032 decisions (proposed)

Status: proposed. Owner: the main session, for confirmation.

## Context

Lane U-HIS-017-032 closes the criteria of stories HIS-017 to HIS-032 that earlier rounds left
open for want of PostgreSQL, object storage, a container or a browser. Where a spec default
was needed, the lane took it and recorded it here.

## Decisions

1. Read marker shape (HIS-027 criterion 1; gap G70). `PUT /documents/{id}/read-marker` takes
   `{ "seq": <whole number, 0 or more> }`, as the protocol definition gives it. The response is
   `200` with `{ "seq": <marker in force> }` and `ETag: "r<seq>"`. A lower or equal `seq` returns
   the marker that stands, not an error (08 §10: markers only move forward).
2. Who may set a marker. A user credential with `read.head` on the document. A service credential
   is refused with `forbidden`, because a marker belongs to a user (08 §10).
3. Range of `seq`. Above the head is `not_found`; a value that is not a whole number is
   `validation_failed`.
4. `If-Match` on the marker write is not required. The protocol leaves whether forward-only
   writes need `If-Match` open (gap in `packages/protocol/src/definition/gaps.ts`); the spec default
   for a write that cannot conflict is no precondition.
5. Storage. The `read_markers` table of migration 0050 is used as it is (one row per document and
   user; the trigger refuses a backward move). No new migration was needed.

## Consequences

- `services/document-service/src/storage/read-markers.ts` holds the PostgreSQL and memory stores.
- The route is offered only when `ServiceParts.readMarkers` is set; both the PostgreSQL and the
  memory parts set it.
- Decision 4 must be confirmed or reversed by the owner before the protocol names the write's
  preconditions.

## Round 11 (lane U-HIS-017-032, 2026-11-13), HIS-032 rebuild

Status: proposed.

1. A commit whose payload is not in the log table is answered as \
ot_found\, with the reason that the
   detail is no longer available (\ContentService.rebuild\, \#readCommits\). The spec does not name
   the response for a thinned range (HIS-032 Notes); \
ot_found\ follows \payloadOf\ in
   \packages/history\. Owner may choose another code.
2. A missing payload row is read as absent, whether it was thinned (HIS-032) or moved to a cold segment
   (HIS-029). The service does not read cold segments yet, so both answer the same way. The error is
   \PayloadAbsentError\ (\src/storage/payload-absent.ts\).
3. The commits resource still reads payloads and does not yet answer a thinned range with metadata only.
   Recorded as an open gap in HIS-032 Notes; not decided here.
