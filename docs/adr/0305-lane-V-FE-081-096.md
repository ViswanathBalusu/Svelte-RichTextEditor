# 0305 Lane V-FE-081-096: decisions and measurements

Status: proposed (lane V-FE-081-096, 2026-11-13). Owner decisions stay the owner's; the items below are defaults taken where the spec left the choice open.

## 1. Kerning and ligature pins in the painter (FE-090 criterion 4)

- The painter sets `font-kerning: normal` and `font-variant-ligatures: normal` on each line (`PAINT_TEXT_PINS` in `packages/painter/src/painter.ts`).
- The canvas measurer must set `ctx.fontKerning = 'normal'`. The spec (02 §9.3) says the painter's CSS follows canvas; canvas `auto` is not used, because it does not match any DOM value in Chromium.
- Measurement, taken 2026-11-13 with a probe test in Chromium, Firefox and WebKit (probe deleted after use), at 16 px serif, width of `AVATAR Wave Yes` in px:

| Browser | canvas auto | canvas normal | canvas none | DOM auto | DOM normal | DOM none |
|---|---|---|---|---|---|---|
| Chromium | 126.789 | 125.906 | 136.852 | 125.906 | 125.906 | 136.859 |
| Firefox | 126.800 | 125.917 | 136.817 | 126.800 | 125.917 | 136.817 |
| WebKit | 126.789 | 126.789 | 136.852 | 126.797 | 126.797 | 136.859 |

- Ligature settings made no difference to the widths of the samples in any browser. Ligature-rich samples were `office`, `final fi fl ffi ffl`.
- Verified by `packages/painter/src/fe-090-metrics.universal.test.ts` (6 tests, all three browsers, pass).
- Open: whether the layout's production measurer (FE-079, not built) uses the same pin. Until it does, criterion 4 holds for the painter and its test measurer only.

## 2. Keyed repaint (FE-092 criterion 2)

- `repaintTree` (`packages/painter/src/repaint.ts`) keeps a page element when its painted content is the same, and within a page keeps a line element whose painted `outerHTML` is the same. It moves or inserts only the elements that differ.
- Default: comparison by painted markup, not by a layout diff. A layout diff would need the engine to report changed blocks, which it does not yet do. Cost: each page is painted again into a scratch element on every call, so the CPU cost is not reduced, only the DOM mutations.
- Verified by `packages/painter/src/fe-092-repaint.universal.test.ts` (2 tests, all three browsers, pass).

## 3. Not decided here

- Whether a measurer is required to set `fontKerning`, or the layout engine sets it. Left to FE-079.

## 4. Code state of the kerning pin (FE-090 criterion 4), 2026-11-13

- Section 1 describes the pin as `normal`. The code does not match it: `PAINT_TEXT_PINS.fontKerning` is `'auto'` (`packages/painter/src/painter.ts`), and `canvasTextMeasurer` in `packages/element/src/canvas-measure.ts` leaves `ctx.fontKerning` at `auto`. Section 1 is the probe result; the pin is still `auto`.
- The probe table in section 1 shows canvas `normal` equal to DOM `normal` in all three browsers (Chromium 125.906, Firefox 125.917, WebKit 126.789 and 126.797, a 0.008 px difference). Canvas `auto` equals DOM `auto` in Firefox and WebKit only, not in Chromium.
- Proposal, not applied here: set `ctx.fontKerning = 'normal'` in `canvas-measure.ts` and `PAINT_TEXT_PINS.fontKerning = 'normal'` in the painter together, then rerun `packages/painter/src/fe-090-metrics.universal.test.ts` in all three browsers. The element package and the spec pin are the owner's or the main session's to change, so this lane did not edit them.

## 5. Field text does not reach the painter (FE-087 criterion 3)

- The layout fills `page` and `pageCount` runs with their values (`withFields` in `packages/layout/src/items.ts`), and the story fragments carry the page label.
- The painter takes the text of a line only from `PaintSource.lineText(blockId, from, to)`, by block offset. A `LayoutLine` (`packages/layout/src/tree.ts`) carries no text, so the painted footer reads the block's source text, not `2 of 3`.
- Closing the criterion needs one of: text on the layout line for field runs (a `LayoutTree` schema change, with `layout-json`, the digest and the coverage check), or a source that resolves story field blocks. Either changes a shared contract, so it is left for an owner or main-session decision. Not built in this lane.

## Round 5 (lane V-FE-081-096, 2026-11-13): FE-083 criterion 1, row cut inside a paragraph

Status: proposed. Item 1: when no paragraph boundary of a table row fits the space left (the cells hold one paragraph each), the row is cut between two of its lines (packages/layout/src/row-line-split.ts, splitRowAtLine, used by placeTable after splitRowAt). The spec (03 §10) asks for a row to split across pages unless cantSplit, and does not say where inside a paragraph. The default taken: the same cut index for every cell, a line position counted in reading order, and a shorter cell kept whole in the head. Paragraph boundaries are still tried first. Tests: packages/layout/src/row-line-split.test.ts.

Not decided: the offsets a table fragment covers (FE-083 criterion 5; ADR 0304 item 2 holds this open).

## Round 5 (lane V-FE-081-096, 2026-11-14): FE-096 criterion 5, caret and selection under forced colours

Status: proposed. Item 2: the caret and the selection are drawn by `paintSelection` (packages/painter/src/selection-paint.ts), from the layout geometry. The boxes use the system colour keywords `CanvasText` (caret) and `Highlight` (selection), and set `forced-color-adjust: none`, so that forced colours mode keeps them visible. The spec (FE-019) asks for system colours and does not name the keywords; the default taken is these two. Tests: packages/painter/src/selection-paint.universal.test.ts (normal mode, three browsers) and packages/painter/src/selection-forced.universal.test.ts, run by tests/V-FE-081-096/vitest.forced-colors.config.ts with `forcedColors: 'active'` on the Playwright context (three browsers, passing). Not decided here: whether the element draws the caret with the same rules (it does not mount the painter yet).

## Round 6 (lane V-FE-081-096, 2026-11-14): FE-087 criterion 3, the text of a field line

Status: proposed. Item 1: a page or pageCount field in a header or footer shows its value through the line that holds it. The layout computes the value (`flowStoryResolver`, `withFields`), but the CDM range of the line does not hold it, so `LayoutLine` gets an optional `text` (packages/layout/src/tree.ts). `paragraphItem` sets it only on the lines of a paragraph that has a field inline, from the runs it broke, and the painter draws `line.text` when it is present and the CDM text otherwise (packages/painter/src/painter.ts). Not decided: the spec does not say how a field's value reaches the page. This is the smallest change that keeps every other line as before. Limit: a line of a field paragraph with a tab or a numbering label also carries those characters in `text`, and the painter draws them with `white-space: pre`, which is not checked against the tab stops of the breaker.

Item 2: the re-wrap test (FE-090 criterion 2) and the justify test (FE-091 criteria 1 and 3) run in the browsers and are kept as separate files, so that a failure names the story it belongs to.

## 5. Kerning probe, all three browsers (FE-090 criterion 4), 2026-11-14

- Status: proposed. Decision for the main session, not applied here.
- Probe (throw-away browser test, deleted after use; `pnpm vitest run --project browser`, Chromium, Firefox and WebKit on the development machine, generic `serif` at 16 px, text `AVATAR Wave Yes`, width in px). Canvas `fontKerning` and CSS `font-kerning` were both tried with each `textRendering` value (`auto`, `optimizeSpeed`, `optimizeLegibility`, `geometricPrecision`). The `textRendering` value changed nothing.
- Result: canvas `normal` and CSS `normal` give the same width in each browser (Chromium 125.906; the other two browsers 125.917 or 126.789, matching pairwise). Canvas `none` and CSS `none` agree (136.8 to 136.9). Canvas `auto` (the measurer's current setting) gives 126.789 in Chromium, and no CSS value tried reproduces it there: CSS `auto` gives 125.906, the same as CSS `normal`.
- So the painter cannot follow canvas `auto` in Chromium. The option that makes the painter and the default measurer agree is to set `fontKerning = 'normal'` in `canvasTextMeasurer` (`packages/element/src/canvas-measure.ts`) and in `PAINT_TEXT_PINS` (`packages/painter/src/painter.ts`) together. This changes line breaks in the production layout, so it is the main session's and the owner's decision, and the spec text (02 §9.3, FE-079 criterion 3, "painter follows canvas") needs the same change.
- Until then FE-090 criterion 4 stays unticked, and the criterion 4 Evidence line in FE-090 that says the painter pins `normal` is out of date: the painter pins `auto` (see section 4).
