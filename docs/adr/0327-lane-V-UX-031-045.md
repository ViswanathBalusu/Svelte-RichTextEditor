# ADR 0327: measurements and decisions, lane V-UX-031-045

Status: proposed (lane V-UX-031-045, round 2, 2026-11-13). The owner has not accepted any part of this record. The earlier record for the same ADR number, `0327-lane-U-UX-031-045.md`, holds the en-GB measurement and the UX-031 combobox question.

## Part A: UX-043 criterion 2, licence and size of candidate dictionaries

Measured 2026-11-13 with the npm registry. Metadata by `npm view <name>@3.0.0 license dist.unpackedSize`. Each package packed with `npm pack` into a scratch folder outside the repository, and the tarball size read from the file. Nothing was installed into the repository and no build was made.

Candidates are the Hunspell dictionaries from the `wooorm/dictionaries` project, version 3.0.0 for each. The locales are a proposal of this lane, chosen as the three most common European locales that the interface may need first. The spec does not name the first locales, so the owner sets them.

| Locale | Package | Declared licence | Tarball bytes | Unpacked bytes | Files |
|---|---|---|---|---|---|
| en-GB | `dictionary-en-gb` | `(MIT AND BSD)` | 203,045 | 575,855 | 7 |
| de-DE | `dictionary-de` | `(GPL-2.0 OR GPL-3.0)` | 341,743 | 1,142,963 | 7 |
| fr-FR | `dictionary-fr` | `MPL-2.0` | 342,850 | 1,436,537 | 7 |

Reading against the project licence (Apache-2.0, the recommendation in the spec): this is a reading of the declared licence fields, not a legal opinion. The owner or counsel must confirm each one before any fallback ships.

- en-GB: MIT and BSD-style notices. Permissive; the notices must be kept. Compatible with Apache-2.0.
- de-DE: a choice of GPL-2.0 or GPL-3.0. GPL-2.0 alone is not compatible with Apache-2.0; GPL-3.0 is. The OR allows the recipient to take GPL-3.0, but a distribution under this choice makes the fallback a GPL-3.0 component of the product. This is a blocker to be decided by the owner, not a pass.
- fr-FR: MPL-2.0, a file-level copyleft. It can sit beside Apache-2.0 code if the dictionary files stay under MPL-2.0 and their notices are kept.

Also measured but not tabled, because the packing was not finished in the time box: `dictionary-pt` (declared `(LGPL-3.0 OR MPL-2.0)`, unpacked 5,461,816 bytes). `dictionary-es`, `dictionary-it` and `dictionary-nl` were not measured.

## Part B: UX-043 criterion 3, cost against the 300 KB budget

Round 4 (lane V-UX-031-045, 2026-11-13), estimate without a built bundle. Method: `npm pack dictionary-en-gb@3.0.0` into a scratch folder outside the repository, extract the tarball, then gzip `index.dic` and `index.aff` together with the .NET `GZipStream` at `Optimal` (PowerShell 7 on Windows 11). Result: 552,106 bytes (`index.dic`) plus 3,086 bytes (`index.aff`) raw, 194,899 bytes compressed. The spell-check engine is not included (no engine is chosen), so this is a lower bound for the fallback's chunk. It is about 65 per cent of the 300 KB initial budget (300 KB read as 300,000 bytes; a different reading changes the percentage only slightly), so a fallback in the initial chunk would take most of the budget before any other code.

Load on demand (the recommendation for criterion 3, should the owner choose a fallback): the dictionaries and the engine go in their own chunk, loaded by a dynamic import only when the author has no proofing port and asks for spelling, or the language of a range needs a checker that the port does not provide. The initial chunk carries none of it. A second locale adds its own chunk of the same kind; the de-DE and fr-FR sizes are not measured here. Under C1 of ADR 0234 (proposed, not accepted), no fallback ships in phase 2, so this chunk is not built.

Criterion 3 of UX-043 is ticked on the estimate above, not on a built bundle. The owner may replace the estimate with a measured chunk once one exists.

## Part E: UX-034 entry for a followed link (round 14)

Status: proposed. Lane V-UX-031-045, 2026-11-13. The spec leaves open how the host opens the editor for a comment identifier (UX-034 criterion 2 and the open questions). This lane builds only the shell side, with no owner decision: `openLinkedComment(commentId)` on the shell (packages/ui/src/App.svelte) resolves the id against the thread list the user may view and hands the comments pane a `LinkedTarget` (packages/ui/src/shell/linked-comment.ts) through the shell context. A deleted or hidden comment gets the same unavailable message. Proposed default for the element: a `openComment(commentId)` method on DocEditorElement, a later decision that this lane does not make. Owner question: is a method on the element the host entry, or a URL or event? Criterion 1 (copy the link) waits for the same answer and for the address form the host returns.
