# ADR 0310: Open decisions met by lane V-PRO-018-034

Status: proposed. Owner decisions stay the owner's. Each item uses the spec default where one exists, and says so.

Date: 2026-11-13. Lane: V-PRO-018-034 (unblock round 1). Stories touched: PRO-025, PRO-026, PRO-030, PRO-032.

## 1. Whether the client strips unknown members of `access` (PRO-032 criterion 5)

Context. The criterion says an unknown field in `access` is ignored (PRO-005). The channel reads the known members and hands the object on with the unknown member still present (`packages/protocol/src/client/access-unknown-field.universal.test.ts`).

Options. (a) Keep the object as received; "ignored" means the consumer reads only known members. (b) Strip unknown top-level members before the object is handed on.

Spec default used: none chosen here. The criterion stays unticked until the owner decides. Option (b) would remove members a later server version adds, which is the forward-compatibility case PRO-005 is about, so the owner should confirm the intent.

## 2. Snapshot commit with a base older than the snapshot (PRO-030 criterion 3)

Context. The criterion says `reload`. The second review (SR-K1, 04 §3.2 as edited) says `stale_base` with action `rebase`. The room sends `stale_base` and `rebase` (`packages/authority` snapshot-reset test).

Spec default used: the server follows the review text, as the story's Notes already record. The criterion stays unticked; the owner must amend the wording or confirm the review.

## 3. Concurrency check versus stress run (PRO-025 criterion 3)

Context. The criterion names a stress test with writers. The new test `services/document-service/src/data-plane/resume-attach-multi-writer.test.ts` runs two writers of 25 commits each against an attaching client, in memory, and checks that each commit after `resume.seq` arrives once and in order. It measures no rate.

Decision taken: criterion 3 is ticked as a concurrency check, and the Evidence says it is not a load test. A rate-based stress run, on the reference machine or in the fault-injection profile (PRO-126), remains needed for a stricter reading. The owner may ask for that.

## 4. Page catch-up limit (PRO-026 criterion 1), not done this round

The client's `catchUp: page` read calls `GET /commits` with `after` only (`packages/backend-dep/src/backend.ts`, `page`). It sends no `limit` (at most 200 under PRO-040) and does not follow `nextCursor`. That is a backend-dep change, left for a later round; criterion 1 stays unticked.
