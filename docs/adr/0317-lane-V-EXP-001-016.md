# ADR 0317: Decisions of lane V-EXP-001-016 (proposed)

**Status:** proposed, 2026-11-13. Written by lane V-EXP-001-016 (round 1) for the owner to confirm.

## Context

Stories EXP-001 to EXP-016 left several criteria open where the spec leaves a question open. The lane
took the spec default and recorded it here, so that the owner can change it.

## Decisions

1. **Reference corpus for the veraPDF gate (EXP-016).** The corpus documents kept in git (`pages-1`,
   `form-fields`, `pages-20`, `packages/corpus/README.md`) are the reference set. `pages-100`,
   `pages-300` and `pages-1000` are generated on demand and are not validated on every change, because
   each compile takes long on a shared Podman host. Spec default: "a corpus of CDM documents with
   reference PDFs" (09 §14) does not name the set. Owner to confirm, or to name a larger set for the
   nightly run.
2. **Flavours validated.** A declared `ua-2+a-4f` is validated as `ua2` and `4f` (PDF/UA-2 and
   PDF/A-4f), as in `services/export-worker/src/exp-015-u-exp-001-016.packages.e2e.test.ts`. A declared
   `ua-2` or `a-4f` is validated against that flavour only.
3. **Draft tagging is not validated (EXP-016 criterion 4).** Spec 09 §3.1 says preview compiles may use
   draft tagging; the gate in `services/export-worker/src/exp-016-corpus-report.ts` (`requiresValidation`)
   skips them. The CI step that applies the gate is root configuration.
4. **Result manifest records `seq` (EXP-004 criterion 7).** The bundle manifest and the stored result
   manifest both carry the export `seq`, as the existing job code writes them. No change of behaviour.

## Consequences

- No product behaviour changed in this lane's round 1 for EXP-016. A new pure module and a test file
  name the failure of a PDF by corpus document, rule clause and test number.
- The CI wiring (a pull request job that runs the gate on a Podman runner) is not built; it is listed in
  the lane's needs for the main session.
