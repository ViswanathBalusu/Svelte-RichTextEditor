# ADR 0228: Comment threads in the DOCX writer (lane EXP-092-104)

Status: proposed

Date: 2026-11-13

## Context

EXP-093 criterion 4 says that comment threads at the exported `seq` become Word comments, anchored to
their range or block, with replies. The direct writer (`packages/export-docx/src/writer.ts`) had no
comment part and its export input had no comment threads.

Comment threads are held outside the document (03 §4; 07 §6): a thread targets a text range or a
block by identifier, and the room maps it through commits. The writer receives only the CDM document
and its options.

## Decision (proposed)

1. The writer takes `WriteOptions.comments`, a list of threads: `{ id, block, messages, done? }`, where
   `block` is the identifier of a paragraph and `messages` are `{ author, date?, text }`, the first
   being the root and the rest replies. The caller maps threads to the exported `seq` and gives the
   author label and the server time of each message. The writer never reads a user identity.
2. Each message gets a `w:comment` in `word/comments.xml`. Its paragraphs are split on line breaks.
   The last paragraph carries a `w14:paraId`, derived from the message number, which
   `word/commentsExtended.xml` (`w15:commentEx`) uses for `paraIdParent`, so each reply names its root.
3. A paragraph in the document body that is the block of a thread gets `commentRangeStart`,
   `commentRangeEnd` and a `commentReference` run for each message. A thread whose paragraph is not in
   the exported document, or that has no message, is not written, with a warning.
4. Threads anchored to a text range are not written. The CDM export input has no offsets within a
   paragraph, so a range needs a mapping from character offsets to runs. This is open.

## Consequences

- EXP-093 criterion 4 stays unticked: the block form is built, the range form is not.
- The thread input shape, the paraId derivation and the range-to-run mapping are for the owner to
  confirm. Until then the writer uses the shape above.
- Imported documents (the patching writer in `export.ts`) do not use this path; comments in an
  imported file are kept as the original package holds them (ADR 0017).
