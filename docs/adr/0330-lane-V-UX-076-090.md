**Status:** proposed. Owner decisions are the owner's; these are the working defaults this lane used.

**Scope:** stories UX-076 to UX-090 of `docs/stories/UX-experience.md`, closing criteria that were blocked on a container, a browser or another package.

## 1. Stories touched

- **UX-090** criterion 4 ticked. Section "Strict content security policy" in `apps/reference-host/docs/integration-guide.md`, checked by `apps/reference-host/test/integration-guide.policy.test.ts`. The directives come from spike S2 section 8, which was measured in Chromium, Edge, Firefox and WebKit. The framework notes (plain HTML, React, Angular, Vue, SvelteKit) were not run in a framework project.

- **UX-086** criteria 1 and 2 stay open: no send operation exists in `services/document-service`.

## 2. Proposed names and defaults

- **Audit kind `webhook.changed`** (UX-079). Data holds the subscription identifier and the operation (`created`, `updated`, `deleted`). The secret is never recorded. The record has no document (`doc: null`).
- **Every successful PATCH is audited**, including one that leaves every field as it was. The default is simpler than comparing fields. A later round may compare fields, as UX-085 does for the label.
- **A refused change is not audited.** The audit is written after the operation returns.

## 3. Not decided here

- The transport of the audit stream (UX-082), which the spec leaves open.
- Whether registry writes made by `services/document-service/src/tenant-cli.ts` and `seed.ts` are audited (UX-077 criterion 5). Those writes do not go through the service.

## 6. Round 5 (lane V-UX-076-090, 2026-11-14): tenant quotas (UX-078)

Status: proposed. The spec (06 section 12, 13 section 10) names the quota dimensions and gives no figures, no shape and no entity tag. The following are this lane's defaults, for the owner to confirm; they are not spec values.

- **Route.** `GET|PUT /quotas`, service credential only (the same class as `/retention`), operations `getTenantQuotas` and `setTenantQuotas` in `packages/protocol/src/definition/resources.ts`. Row 13 of the permission matrix names them (`packages/authority/src/permissions/matrix.ts`).
- **Shape.** Seven dimensions (`connections`, `openDocuments`, `commitRate`, `roomCpuBudget`, `storage`, `exportConcurrency`, `exportMinutes`), each a nullable whole number of 0 or more. A `PUT` sets the dimensions it names and keeps the others. The stores accept any finite number of 0 or more; the route is stricter, because the contract has only integers. Whether a fractional quota is wanted is open.
- **Entity tag.** The protocol requires `If-Match` on an update, and the store has no version counter. The tag is a SHA-256 of the settings in dimension order, truncated to 32 hexadecimal digits. A stale or missing `If-Match` is refused with 412 or 428, as on the other routes.
- **Audit.** Kind `quota.changed`, with `previous` and `settings`, written after the change is stored; a `PUT` that leaves the settings as they were writes nothing.
- **Storage.** Memory: `MemoryQuotaStore`. PostgreSQL: `PgQuotaStore` over table `tenant_quotas`, migration `0069_ux_078_quotas.sql` (not listed in `migrations/releases.json`, as 0065 to 0068 are not). The table is not yet under row-level security; the store filters by `tenant`. The tenant check of the PostgreSQL store reads `tenants` in the tenant's own context.
- **Atomicity.** The dimensions of one `PUT` are written one by one after the whole body is checked. A database failure part way leaves some dimensions written. Not decided: a single-statement or transactional write.
- **Open for the main session.** Row-level security for `tenant_quotas`; a decision on fractional quotas; `schema.pg.test.ts` pins the table list and does not yet name `tenant_quotas` (it already failed before this lane, for 13 newer tables).

## 7. Round 5 (lane V-UX-076-090, 2026-11-14): listings of origins and keys (UX-077)

Status: proposed. The paths are proposals: `GET /origins` and `GET /keys`, service credential only, read only. The spec names no path for them (05 section 4 and section 3.2 describe the registration, not a resource). The body of `/origins` is `{ origins: string[] }`, sorted. The body of `/keys` is `{ keys: [...] }`, user keys then service keys, each with `kid`, `use`, `alg`, `thumbprint`, `issuer` and the public `jwk`; a private member is never registered and is not listed. Writes (adding or removing an origin or a key) have no route: they wait for the administration API (UX-076), where the audit of UX-077 criterion 5 belongs.

Needs from the main session or the owner: the CI job for the UX-090 quick start; the G49 event name (UX-085); the administration API contract (UX-076), which gates UX-078, UX-079, UX-081, UX-088 and UX-089; the send-path definition (UX-086); the `/search` resource decision (UX-084); the transport for the audit stream (UX-082).
