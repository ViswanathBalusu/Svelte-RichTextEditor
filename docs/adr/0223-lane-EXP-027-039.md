# ADR 0223: Lane EXP-027-039 decisions (export-latex, round 1)

Status: proposed. The owner decides the open points below.

## Context

Lane EXP-027-039 took the export stories EXP-027 to EXP-039 in `docs/stories/EXP-export.md`. The
converter and class are in `packages/export-latex`. Decisions the spec leaves open are recorded
here, not made silently.

## Decisions taken in this round

1. EXP-028 criterion 4 (alternative text through `pdfString`). `kvValue` is braces around
   `pdfString` (`packages/export-latex/src/emit.ts`), so the `alt` option of `\DEimg` is the
   `pdfString` form. The criterion is ticked on that reading, with a test that decodes the option
   back to the alternative text (`pictures.alt.exp028.test.ts`). The emitter itself is unchanged.
   Spec default followed: `pdfString`. Owner to confirm.

## Findings, not changed in this round

2. EXP-031 criterion 3 (column break). A probe compiled in the Podman sandbox showed that the
   `\DEbrcol` macro (`class/docedit.cls`, `\vadjust{\columnbreak}` after `\penalty-10000`) does not
   start the next column when the break is in the middle of a paragraph, and starts it one line
   low when the break opens a paragraph. The criterion stays unticked. A class change is needed;
   it is not made here because `class/docedit.cls` is shared and the fix is a typesetting choice.

3. EXP-030 criterion 1 (percent-encoding of link targets). The story asks for characters special in
   TeX arguments to be percent-encoded. `url` (`emit.ts`) passes `%`, `#` and `&` through, and the
   output is hex-encoded, so TeX cannot misread it. Encoding `%` again would corrupt a target that is
   already percent-encoded (for example `%20`). The spec default (percent-encode) conflicts with
   correctness for `%`. Not changed; the owner decides between "encode `%` once when it is not
   followed by two hex digits" and the current pass-through.

4. EXP-033 criterion 2 (checkbox glyph through `enumLookup`). The glyph comes from the model's
   `valueText` mapping (`inline.ts`, `formFieldValue`). Not changed: moving it needs a decision on
   the table's owner.

5. EXP-029 criterion 4 (FootnoteText). The style is applied only when the document defines a
   `FootnoteText` style (`inline.ts`, `footnoteParts`). A converter default would be a new decision.

6. EXP-036 criterion 2 (page watermark). `page_setup.watermark` has no converter mapping
   (`attributes.ts`, `null`). Not built.

7. EXP-039 criteria 1 and 3. `splitRow` (`tables.split.ts`) is not called by the converter, because
   no row-height measure exists (ADR 0143 question 2).

## Consequences

Only EXP-028 criterion 4 is ticked in this round. Podman was up during the probe. The compile probe
file was removed after the finding, so no failing test is left in the tree.

## Round 2 (lane EXP-027-039)

8. EXP-033 criterion 6 (glyph branch). The criterion says "a warning" for a value whose glyph the
   fonts lack. EXP-026 makes a missing glyph an error in a final export and a warning in a preview.
   The test follows EXP-026 (`packages/export-latex/src/exp-033-glyph-field.test.ts`). The
   criterion is not ticked (unticked by the round 2 review): the test covers only the glyph input,
   and gives an error in a final export where the criterion names a warning. The width input (a
   value wider than its field) is not built: the converter has no field-width measure and no font
   metrics. Spec default followed: EXP-026. Owner to confirm, or to say that a final export should
   warn for a field and fail for a body paragraph, and to settle the width case (build a measure,
   or reword the criterion). The criterion stays unticked until both are settled.

9. EXP-032 (tab stops) is not ticked. The converter has no `tab` node case, and the class's
   `\DEtab` and `docedit.deftabs` are not tested on a compile. Left open; no decision taken.

10. EXP-030 criterion 1 stays open, as in decision 3. The percent-encoding rule for `#` is a
   trade-off for the owner: `#` in an external link is a fragment delimiter, so encoding it would
   change the link. No change made.

11. Stories checked and left unticked for this round: EXP-029 (`\footnote` branch and layout
   continuation, EXP-055), EXP-034 (signature picture, `dateSigned` format), EXP-035 (block
   fallback goes through `pdfString`, a class argument), EXP-036 (watermark is not mapped; page
   number start and format reach `\DEdefsetupb`, but the PDF check needs a compile), EXP-037 (right to
   left is unsupported), EXP-038 (cell borders and banded rows not drawn), EXP-039 (no row-height
   measure, so `splitRow` is not called and the preflight does not see tall rows).

## Round 3 (lane EXP-027-039)

12. EXP-028 criterion 3 (`align` on a figure caption). `align` reaches the picture line only
    (`blocks.ts`, `figure`, and `DE@figbody` in `docedit.cls`). The caption is set by its own
    style and is not moved by `align`. The spec default is not stated here; the reading that
    `align` is the picture's alignment is what the code does. Owner to say whether `align` should
    also move the caption. Criterion 3 stays unticked.

13. EXP-036 criterion 1 is ticked on a compile (`exp-036-page-numbers.compile.test.ts`). The
    criterion's page numbers come from `\DEdefsetupb` (`pageNumberStart`) and the format macro
    `docedit.pagenumber`. Criteria 2 and 3 (watermark, tagged reading order) stay unticked:
    `page_setup.watermark` has no converter mapping, and the class has no watermark macro.
    Building it needs a converter and a class change, which this round did not make.

14. EXP-030 criterion 3 is ticked on a compile (`links.annotations.compile.test.ts`). The PDF is
    read as text with every Flate stream inflated, because `qpdf` and `pypdf` are not installed.
    This is a search for action keys and subtypes, not a PDF parser. It checks that URI and GoTo
    actions are found (so the search reads annotations) and that no Launch, JavaScript, GoToR,
    GoToE, SubmitForm, ImportData, Rendition, RichMediaExecute or `/JS` key is present.

15. EXP-028 criterion 2 (`here`) is ticked on a compile (`figures.placement.compile.test.ts`). The
    figure's position comes from the class's layout report, and its caption from `pdftotext`. The
    picture is the converter's placeholder box, since no asset is attached.

16. EXP-033 criterion 6 is left as the round 2 review set it. The width input needs a
    field-width measure that the repository does not have (no font metrics), so it is not built
    here. The severity question (decision 8) is still the owner's. No change in this round.

## Round 11 (lane EXP-027-039)

Status: proposed. Stories touched: EXP-033, EXP-028. Tests only; no converter or class change.

17. EXP-033 criterion 8 (no live PDF form fields) is ticked on a compile of the converter's
    bundle with flattened fields, with a link annotation as the positive control
    (`exp-033-no-live-fields.compile.test.ts`). Reading the PDF objects as text is the same method as
    EXP-030 criterion 3.
18. EXP-028 criterion 5 (figure kept with its caption) was ticked on a compile sweep of 30 figures
    at varying offsets, and the round 11 review unticked it. The class sets `\penalty\@M` between the
    picture and the caption. The review ran the sweep with the penalty removed and got the same
    result, so no figure in the sweep had a page break that would fall between picture and caption.
    The test stays as a sweep, but it does not exercise the criterion. Round 5 fix (E group 2): the
    sweep was replaced. Each trial now starts a page with a spacer whose space after is found by
    search, so the picture fits at the foot of the page and the caption does not. The same document
    is compiled with the penalty removed as a control: there a picture and its caption land on
    different pages, while with the class as shipped the whole figure moves to the next page.
    Criterion 5 is ticked on that test.
19. Not decided here, left as the spec default in the stories: EXP-030 criterion 1 (percent-
    encoding of TeX-special characters in a link target). Encoding `&`, `#` and `%` would change the
    meaning of a query string or fragment, and the `url` emitter already hex-encodes the target, so
    TeX specials never reach TeX. The owner decides whether the criterion means URI encoding or
    TeX-safety. EXP-030 criterion 5 (link title through `pdfString`) is also left open: the title
    goes into `/Contents` as a dictionary value through `pdfannot_dict_put`, so a `\DEstr` there
    is not known to expand to a valid PDF string without a compile.
20. Not built in this round, needs a class or converter decision: EXP-031 criterion 3 (column
    break, see the story's Notes), EXP-036 criteria 2 and 3 (watermark has no converter mapping and
    no class macro), EXP-037 criterion 1 (right-to-left paragraph layout), EXP-039 (the converter
    does not call `splitRow`, no row measure exists), EXP-035 criterion 2 (block `fallbackText`
    through `pdfString` versus the spec's `text` emitter, a converter rule the owner decides).
    EXP-032 criteria 1, 3 and 4 need leader and decimal checks on a compile and the EXP-115
    fixtures, which are not in the repository; not attempted in this round.

## Round 12 (lane EXP-027-039)

Status: proposed. Stories touched: EXP-036, EXP-032, EXP-034. Tests and notes; no class or
converter change. (Decision 20's note that the watermark has no mapping is out of date: criterion 2
is ticked on a compile, see the story.)

21. EXP-036 criterion 3 (watermark outside the tagged reading order) is ticked on a tagged compile
    (`exp-036-watermark.tagging.compile.test.ts`). The check reads the content stream: the watermark
    block sits in `/Artifact` marked content, and the body text in an MCID sequence. The structure
    tree is not read. Spec default followed (`\SuspendTagging` in the class).
22. EXP-032 criterion 1 stays unticked. The decimal stop and the dot and character leaders pass on a
    compile. The underscore and heavy leaders are drawn as one stroked line of the gap's length. The
    test in `exp-032-tabs.compile.test.ts` counts 1 pt bars and fails. The file was being edited by
    another agent during this round, so the test was left as it stands. The owner or the EXP-032
    owner should decide whether the test or the class's leader is the reference.
23. EXP-034 criterion 1 (signature picture) is not built. The picture's height needs the image's
    proportions. `AssetInput` has no pixel size, and the bytes may be absent. Owner decision: pass the
    pixel size with the asset, or the bytes, in the job.
24. EXP-031 criterion 3 and EXP-039 criteria 1 and 2 are unchanged from decisions 2 and 7.
    EXP-030 criterion 1 and 5 are unchanged from decision 19.

Round 14 (lane EXP-027-039, developer agent). Stories touched: EXP-031, EXP-029. Status: proposed.

25. EXP-031 criterion 3 (column break) is ticked. The class macro `\DEbrcol` is now
    `\par\columnbreak\noindent` in place of `\hfil\penalty-10000\relax\vadjust{\columnbreak}`
    (`class/docedit.cls`). The compile test `exp-031-column-break.compile.test.ts` failed on the old
    macro (the word after the break stayed at the left margin) and passes on the new one. Owner
    decisions still open: whether the class version is bumped for this change (ADR 0115, as in
    EXP-032), and the empty line that a paragraph beginning with a column break still shows.
26. `pdftotext -bbox` needs poppler. The xpdf build that Git for Windows puts on the path has no
    `-bbox`. The new test reads the tool from DOCEDIT_PDFTOTEXT and skips without one. This is a
    test-environment decision for the owner (the same applies to EXP-032's tests, which call the
    path tool directly and fail on the Git build).
27. EXP-029 criterion 3 (footnote continuation in layout.json): a test is written
    (`exp-029-footnote-continuation.compile.test.ts`) but has not run. `podmanInfo()` in
    `services/export-worker/src/container.ts` has a 30 s timeout, and `podman info` took 37 to 43 s on
    this host during this round, so `sandboxReady()` reports Podman unavailable and the test skips.
    Not ticked. The owner should decide whether the 30 s timeout is raised for loaded hosts.
28. Not changed, spec default not applied: EXP-030 criterion 1 (percent-encoding). The `url` emitter
    already passes every character outside RFC 3986 through percent-encoding, and the result is
    hex-encoded before TeX sees it. Percent-encoding `&`, `#` and `%` would change the meaning of
    a valid URL, so the owner should decide whether the criterion means RFC 3986 or a stricter rule.
    EXP-030 criterion 5 (link title through `pdfString`): the class writes the title as the
    annotation's `/Contents` PDF hex string, so `pdfString` would need a class change. Left as is.
