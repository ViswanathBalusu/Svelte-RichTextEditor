# ADR 0330: decisions of lane U-UX-076-090 (round 1)

Status: proposed (2026-11-13). Owner decisions stay the owner's; the choices below are the
working defaults of this lane and are listed for review.

## 1. Audit kind for a classification label change (UX-085 criterion 4)

The spec (07 section 14) lists no event for a change of the classification label, and UX-085 says
only that a label change is audited. This lane records it as `classification.changed` with the
data `{ previous, label }` (the label before and after; null when none). The audit query
(`GET /audit`) returns fixed fields and scopes only, so the values are not served there; they are
read from the store.

Also open: whether the event belongs in the same transaction as the update. The lane records it
after the update commits (`services/document-service/src/control-plane/handlers.ts`,
`updateDocument`). A failure between the two leaves a change without its audit entry. The
PostgreSQL store's `update` (services/document-service/src/storage/document-store.ts) would be the
place for an atomic write, as it is for `grants.changed`; that is not done here.

## 2. Test ping and replay of deliveries (UX-079 criterion 2)

`WebhookDispatcher.ping` and `replay` exist, but the protocol names no route for them. 05 section
6.2 lists `/webhooks/{id}` with GET, PATCH and DELETE, and the test ping and the replay as things
the resource offers, without a method or a path. The registry (`spec/dep/dep-1.registry.json`) has
no operation for either. This lane does not add routes: a new path is a protocol decision, and
spec/ is generated. Proposed for the owner or the protocol maintainer: `POST /webhooks/{id}/ping`
(204, or a delivery identifier) and `POST /webhooks/{id}/deliveries/{deliveryId}/replay` (a new
delivery with the same `webhook-id`). Both are service-credential only.

## 3. Limits wording (UX-090 criterion 6)

The "Limits of the embedding" section of `apps/reference-host/docs/integration-guide.md` states
each limit with the state of 2026-11-13. It names the restriction guards and the sample
extension's axe run as not yet built, so the guide does not promise behaviour the editor lacks.

## 4. Policy hook on the export path: fail closed, and the audit kinds (UX-086, round 2)

Status: proposed. The spec leaves the timeout and the outcome when the hook does not answer open (13 section 10; the open questions of the stories). This lane chooses a default so that the export path is defined; the owner decides whether it stands.

- An export is asked of the tenant's hook before it starts (`services/document-service/src/control-plane/export-routes.ts`). The request is signed like a webhook delivery (`policy-hook.ts`, `webhook-signing.ts`).
- Allow: the export goes on. Deny: refused with `forbidden`, with the hook's reason as the problem's detail (at most 500 characters, as `decisionOf` reads it).
- Unanswered (timeout, unreachable, an answer that is not a decision): refused with `unavailable`, and no job is started. This is fail closed. The timeout is the caller's (`PolicyHookClient`, `timeoutMs`); no figure is set here.
- Audit kinds, proposed alongside `classification.changed` (section 1): `policy_hook.refused` (data: action, target, reason) and `policy_hook.unanswered` (data: action, target, cause: `timeout`, `unreachable` or `bad_answer`).
- The send path is not asked: it is not built. Where a tenant registers its hook and its secrets is not decided; the server takes them through `ServiceParts.policyHook`.
- The hook's URL must be http or https and redirects are an error, so the hook is never asked at an address the tenant did not register.

## 5. PostgreSQL quota table (UX-078 criterion 1, durable half, round 2)

Status: proposed. `services/document-service/src/control-plane/quotas-pg.ts` carries the DDL of table `tenant_quotas` (one row per tenant and dimension, CHECK clauses for the seven dimensions and for a finite value of zero or more, and a grant to `docedit_app`). The table is not in `migrations/`: adding a migration changes the schema version every database expects, which is for the main session to sequence. The lane's test applies the DDL to its own database. The store's reads are asynchronous, so it cannot be the synchronous source of the live quota gate without a cache, which is not built.

## 6. Retention policy shape and precedence (UX-080 criteria 1 and 4, round 3)

Status: proposed. 08 section 11 gives two behaviours and no field names or periods, so the shape is a proposal, not the spec.

- The policy has `mode` (`keep_all`, the default, or `thin_payloads`) and `afterDays` (an integer of 1 or more, required with `thin_payloads`, refused with `keep_all`). No period is chosen for the default; `afterDays` has no default value. Owner decision: the period and whether a tenant may choose it.
- The effective policy of a document is its own policy, else the tenant's, else `keep_all`. Whether a document policy may be less strict than the tenant's is not specified and is not checked. Owner decision.
- Routes (service credential only, `If-Match` required on PUT, the version as the ETag): `GET|PUT /retention` and `GET|PUT /documents/{id}/retention`. A document policy cannot be cleared yet (no DELETE is defined).
- A change is audited with kind `retention.changed` and data `{ scope, previous, policy }`, after the change is stored (not atomic, as in section 1).
- Storage: `services/document-service/src/control-plane/retention-pg.ts` carries the DDL of table `tenant_retention` (one row per tenant and document; `doc` is the empty string for the tenant policy; CHECK clauses for the mode and the period). It is not in `migrations/`, for the main session to sequence, as in section 5.
- Holds (UX-080 criteria 2 and 3) are not built: the hold rule is in `@docedit/history`, which `services/document-service` does not depend on. That dependency is a `package.json` change for the main session.
- The operations are in the protocol definition (`packages/protocol/src/definition/resources.ts`, owner `UX`), and `spec/dep` was regenerated with `node scripts/generate.ts` in `packages/protocol`. The prose table of 05 section 6.2 has a row for the document route.
- Open conflict, for the main session: `services/document-service/test/control-plane/matrix.test.ts` requires row 13 of `packages/authority/src/permissions/matrix.ts` to hold every service-only route, but row 13 must match the 13 rows of 07 section 12, which list no retention route. Another agent's classification of the four routes as "no row in 07 section 12" was also present in round 3 and was removed while this lane worked. Row 13 is left as it was. The permissions artifact in `spec/permissions` is stale after these changes and needs `pnpm --filter @docedit/authority generate` once the conflict is decided.
