# ADR 0322: Lane U-EXP-081-096 decisions

Status: proposed (2026-11-13). Not an owner decision.

## Context

Lane U-EXP-081-096 closes the criteria of EXP-081 to EXP-096 that earlier lanes left open for want of PostgreSQL, a container, or a browser. Two choices were needed where the spec and the code did not agree.

## Decisions

1. **The export worker accepts `suggestions: markup`.** `services/export-worker/src/profile.ts` refused `markup` as "comes with EXP-083", although the converter (`packages/export-latex`, `suggestions.ts`) already prints markup. The spec default (09 §10) is that `markup` is a valid decision, so the refusal is removed. The `accept` and `reject` paths are unchanged. Consequence: `services/export-worker/src/profile.test.ts` (an existing test, not written in this lane) asserts the old refusal and now fails on that one line. Its owner should change the expectation to accept `markup`; this lane did not edit it.

2. **The job-count check of EXP-082 criterion 1 runs on PostgreSQL only.** The memory store has no `jobs` table to count. The criterion is ticked on the PostgreSQL run.

3. **EXP-086 criterion 4 covers the service's rules, not the writer.** The `cdm` job is run by a stand-in handler in the service test. No worker runs the canonical JSON writer for `cdm`; that is a gap for the export worker and is not closed here.

## Not decided here

- Which targets the EXP-082 refusal covers (open in 09 §10). The service applies it to every target.
- The non-colour cue of EXP-083 criterion 4, and the PDF colour of criterion 1.
- The licence manifest of EXP-085 criterion 4 and the LuaLaTeX compile of its criterion 5 (not run in this lane).

## Round 3 (2026-11-13)

Status: proposed.

1. Podman readiness timeouts (services/export-worker/src/container.ts, sandbox-ready.ts). On the loaded
   Podman machine podman info took about 43 s and podman image exists about 54 s, longer than the
   30 s limit, so the sandbox read as not ready and the tests skipped. The limits are raised to 120 s.
   Owner or root decision: none; this is a timing change only.
2. Machine route arguments. The machine route passes arguments through ssh, which accepts no spaces.
   The EXP-085 archive test therefore sends its script on standard input, with the archive inside it
   as a base64 here-document. Decision for the owner: none needed.
3. EXP-081 criterion 5 is ticked on the service's half (PostgreSQL). EXP-081 criterion 2 (mt
   revert) stays open: ADR 0032 section 1 shows mt as suggested in both modes, which conflicts with
   the criterion. Owner decision needed.
4. EXP-085 criterion 5 is not ticked: the test is written but has not passed (see the story Notes).

## Round 9 (2026-11-13, lane U-EXP-081-096)

Status: proposed. Not an owner decision.

1. Form-field bindings of checkbox and date controls (EXP-095 criterion 1). `packages/export-docx/src/writer.ts`
   left `w:dataBinding` out for these two kinds, so their controls were not bound to the values part. The
   exclusion is removed. The spec (09 §11, 12 §12) does not say how the values are stored, so this lane
   chose: a checkbox is stored as `true` or `false`, and a date as `YYYY-MM-DDT00:00:00`, the form Word
   reads for a `dateTime` mapping. Test: `packages/export-docx/test/exp-095-bindings.test.ts`. Word itself
   has not opened these files in this lane.
