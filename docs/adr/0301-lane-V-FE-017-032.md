# ADR 0301: decisions taken by lane V-FE-017-032 (round 3)

Status: proposed. Date: 2026-11-13. Owner decisions stay with the owner; each item below uses the
spec's default or the reading the story Notes give, and says so.

## 1. Identifier changes are refused in the core (FE-031 criterion 5)

Decision taken in code: a local transaction that replaces a non-null `id` with another value, or
with null, is filtered out (`changesExistingId` in `packages/engine/src/ids.ts`). Exempt: remote
transactions, the plugin's own fills (`docedit.internal`) and history transactions (undo and redo),
because undo may take back a step that was accepted when it was made. Setting a null `id` is a fill,
not a change. Open for the owner: whether a local change of an identifier should instead be a
rejection the user sees, not a silent filter. Default taken: silent filter, as the other guards do.

## 2. Scope of the selection in a sub-editor (FE-026 criterion 3)

The criterion says `selectionScope()` returns the definitions or a story. The main state's selection
is clamped out of a story, so the case is reached only through a sub-editor's own state. Open
question: which sub-editor is the selection's scope when the panel is open but the body has focus.
Proposed default: the scope of the focused editor, and the body when focus is in the body. The core
does not yet receive focus from the sub-editor views, so the criterion stays open until it does.

## 3. The "one helper" for `de-` events (FE-022 criterion 3)

The criterion asks for a lint rule. The workspace ESLint configuration does not parse Svelte files,
so the decision taken is a Node.js source scan (`packages/ui/test/de-event.test.ts`) that fails any
other `dispatchEvent(` in `packages/ui/src` and `packages/element/src`. Proposed default: keep the
scan, and the main session adds the lint rule to root configuration when it can parse `.svelte`.

## 4. Source scan for the integration guide (FE-017 criterion 5)

The guide's global side effects are checked by names in the element's source (the `pointerdown` and
`visibilitychange` listeners, `docedit-journal`). A new listener is caught only once it is added to
the test's list; a full audit of every `addEventListener` is not automated. Proposed default: keep
the list, and review it when the element adds a listener.
