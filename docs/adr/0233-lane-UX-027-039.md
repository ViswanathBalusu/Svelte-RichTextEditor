# ADR 0233: Open questions decided by the UX-027 to UX-039 lane (proposed)

Status: proposed. Owner decisions are the owner's; the spec default is used until the owner says otherwise.

## Context

The lane UX-027-039 implemented the rules of the comment and review tools as pure functions in `packages/ui/src/shell/comment-rules.ts` and `packages/ui/src/shell/review-rules.ts`. The spec leaves some points open. Each is recorded here and in the story Notes.

## Decisions (proposed)

1. Accept and reject of a suggestion by its own author (UX-036). The spec (07 section 17) does not say whether a suggester may withdraw or act on their own suggestion. The rule offers accept and reject to any user with `edit` in the suggestion's scope, their own suggestions included, and to no one with `suggest` alone. Default until the owner decides.
2. Edit of a comment by its author who no longer holds `comment` (UX-029). Not specified. The rule uses the wording of the story only (author or `manage`), and does not add a `comment` test.
3. Accept all and reject all (UX-036 criterion 2). Not decided here: the bulk plan and the count of suggestions left pending are the FE-047 and the core's, and no rule is written in this lane.
4. The four markup views (UX-035 criterion 1). The spec names `all`, `simple`, `none` and `original` without defining them. `shell/markup-views.ts` uses the definitions in its header: `none` is the accepted text, `original` the rejected text, `all` every run with its change and author, and `simple` the accepted text with a marker before each changed run. Default until the designer confirms; the story Notes say the same.
5. The 5,000-thread limit (UX-028 criterion 5). The spec gives the number but no error code. `shell/thread-target.ts` refuses with the working name `threadLimit`. Only the gate is built; the refusal the core returns and the message the user sees are not.
6. Block target for a comment (UX-028 criterion 2). A selected figure, table or equation targets `{ block: id }` as the story says. Blocks of other kinds are not limited here, since the spec names only these three.
7. Stale mention results (UX-031 criterion 2). Only the results of the newest query are shown. A result for an older query is dropped, not held for later. The spec does not say; this is the simplest rule that meets the criterion.
8. Mention node (UX-031 criterion 3). The node holds the principal identifier only, `user:<sub>` or `group:<id>` (07 section 1). Whether a person outside the document may be mentioned is the host's decision (UX-031 Notes), not this lane's.

9. Evidence for a presentation criterion (UX-027 criterion 4, round 3). A criterion that says how a caret, flag or selection is drawn under forced colours is ticked on a Node.js source check of `shell.css` and `Carets.svelte` (`packages/ui/test/ux-027-presentation.test.ts`), as UX-062 criterion 1 is. The Evidence says that it is a source check and that no rendered run is claimed. Criteria about what a person sees or does (criterion 5) stay open for the browser run. Default until the owner decides the standard of evidence for presentation criteria.

10. Empty excerpt in the review pane (UX-037 criterion 1, round 4). A suggestion with an empty excerpt (a block change, say) is shown with a `null` excerpt, so the view can say that there is no text. The spec does not say how an empty excerpt is shown. Default: `reviewPaneRows` in `packages/ui/src/shell/review-pane-rows.ts`.

11. Announcement of a linked comment (UX-034 criterion 4, round 4). A linked comment announces its author, creation time and state, and no other part of the thread. The spec names these three parts only (UX-034 criterion 4). Default: `linkedCommentAnnouncement` in `packages/ui/src/shell/linked-comment.ts`. The sentence itself is the string tables' and the view's.

## Consequences

Criteria that depend on these points are ticked for the rule only, and say so in the story Evidence.
