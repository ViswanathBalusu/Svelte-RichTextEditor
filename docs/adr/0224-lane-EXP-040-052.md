# 0224. Lane EXP-040-052: open questions and defaults taken

**Status:** proposed (2026-11-13). Written by the developer of lane EXP-040-052 (round 2) in `packages/export-latex`. Not reviewed by the owner.

## Context

The lane worked stories EXP-048 and EXP-049 in this round, and read EXP-040, EXP-045 to EXP-047, EXP-050 and EXP-053 without changing them. Where a criterion rests on a point the spec leaves open, the default taken in code is recorded here, as CLAUDE.md requires. Owner decisions are the owner's.

## Open questions and the default taken

1. **How a font licence permits server-side use (EXP-048 criterion 3).** 09 §5 says "the font licence must permit server-side use; the manifest records it". The manifest records a licence as free text (`licence: 'OFL-1.1'`), and the spec does not say which licences permit server use, who decides, or whether the flag is a field of the manifest. Default in code: none. The converter does not read a policy from the licence string, so criterion 3 stays unticked. Question for the owner: should the manifest carry an explicit boolean for server-side use, set by the font administration (BE-048 or FE), or should the converter keep a list of permitted licence identifiers? Either way the converter would then refuse the face, use the fallback chain and warn with the family name.

2. **A removed tenant font as the converter sees it (EXP-048 criterion 4).** The converter receives only the job's manifest. A removed font and a family that was never uploaded give the same input. Default in code: the converter treats both alike (`font_family_missing` warning, default family, fallback chain written to `styles.tex`), and the test in `packages/export-latex/src/tenant-fonts.removed.test.ts` checks that. Question: none beyond confirming that the job, not the converter, is responsible for leaving a removed family out of the manifest (BE-048).

3. **Currency of the generated math allow-list (EXP-049 criterion 5, part).** The generator is `packages/export-latex/scripts/math-allow-list.ts`, and `allow-list.ts` says it must not be edited by hand. Default in code: the test `packages/export-latex/src/math/allow-list.currency.test.ts` recomputes the list and checks the data, fingerprint, refusals and KaTeX version against the installed KaTeX. It does not compare the prettier-formatted text of the file. No owner decision is needed; the compile part of criterion 5 stays open because it needs the TeX engine.

## Consequences

- EXP-048: criterion 4 ticked on the converter's side, with Notes for criteria 1 to 3.
- EXP-049: criterion 5 stays unticked (compile); a currency test is added, and the Notes say so.
- No container, TeX engine or browser was run in this round.

## Round 3 (2026-11-13)

4. **When the font files are checked against the manifest (EXP-047 criterion 2).** The check is `checkFontFiles` in `services/export-worker/src/font-files.ts`. Default in code: the check is a function with its own tests, and nothing calls it yet. Open question for the owner: should the job run it before every compile (in the local path, where the font directory is known, and in the image build), or should the image be verified once at build time? Until that is answered the job does not fail on a missing hash, so criterion 2 stays unticked.
