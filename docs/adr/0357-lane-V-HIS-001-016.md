# ADR 0357: Lane V-HIS-001-016 choices (proposed)

**Status:** proposed, 2026-11-13. Recorded by lane V-HIS-001-016 for the HIS epic.

## Context

The lane closes the HIS-001 to HIS-016 criteria that were blocked on PostgreSQL, a container or a
browser. Some criteria left a choice the spec does not make. Each choice below uses the spec's
default or the narrowest reading, and is listed so the owner can confirm or change it.

## Choices

1. **Named version: default seq is the head.** HIS-006 criterion 1 says "pointing at the head (or
   at the `seq` given)". `PgVersionStore.create` (`services/document-service/src/storage/versions-store.ts`)
   uses the head when no `seq` is given and the `seq` otherwise. The head is read under
   `for update` on `doc_heads`, so the check and the insert see one head.
2. **The store does not import `@docedit/history`.** The rules of `packages/history` (`createVersion`)
   are called by the service before the store. `services/document-service/package.json` does not
   list `@docedit/history`, and package.json files are not changed by this lane. The seven kinds are
   repeated in the store and checked against the `versions` check constraint of migration 0050.
   Owner or main session: add the dependency and let the store call `createVersion` directly.
3. **Version creation with the same seq and kind returns the stored one.** This applies HIS-007
   criterion 5 to the named kind as well, as `packages/history` already does (ADR 0118).
4. **Stored name and note are text.** No markup handling is done in the store; HIS-006 criterion 5
   (display as text) is the pane's.

## Not decided here

- The `POST /documents/{id}/versions` route, the events and webhooks of HIS-006 criterion 4, and the
  requester's `edit` check on the route: the service's, not built.
- HIS-015 criterion 2 (`GET /documents/{id}/attribution`) needs `@docedit/history` as a dependency of
  the document service (see choice 2).
- HIS-014 criterion 4 (the attribution map written with a checkpoint) needs the room in
  `packages/authority` to keep the map; not started.

## Round 5 choices (HIS-007 criterion 1, export versions)

Status: proposed. The spec (08 §4) says the `export` version points at the `seq` when the export
finishes but does not say what happens when the version cannot be stored.

5. **The export version is written after the export completes, and a failure does not fail the
   export.** `exportHooks` (`services/document-service/src/control-plane/exports.ts`) stores the
   `export` version with the job's creator when a non-preview export completes. A store refusal or
   error is reported through `versionFailed`, which the server logs as `export.version`. The export
   stays completed. The alternative, failing the job until the version is stored, would make a
   storage outage look like a compile failure. Owner: confirm, or choose to retry the version
   write from the job runner.
6. **Only non-preview exports get a version.** Previews are not sent and are not named in 08 §4.

## Round 7 open questions (HIS-010 and HIS-013, 2026-11-13)

Status: proposed. Nothing in this section is decided; the spec default is listed where there is one.

7. **Comment ranges at a checkpoint (HIS-010 criterion 4).** The story says the comment ranges shown
   for an old version are those of the nearest checkpoint at or before the `seq`, and that the view
   says they are approximate between checkpoints. The checkpoint type in `packages/authority/src/room/content.ts`
   holds `seq` and `doc` only, and `packages/history/src/thinning.ts` holds the policy fields only.
   The spec does not say whether comment anchors are stored in the checkpoint document or kept in a
   separate table keyed by `seq`. No function can be written against the current data. Owner or the
   spec (08 §3): choose the storage; until then the criterion stays unticked.
8. **No history pane exists yet (HIS-009, which HIS-010 and HIS-013 depend on).** `packages/ui/src/panes`
   has no history pane; the `history` and `catch-up` entries in `packages/ui/src/shell/panes.ts` have
   no `load` function. The read-only second editor state (HIS-010) and the comparison overlay with
   change navigation (HIS-013) are mounted from that pane. Their browser tests need that pane first.
   Spec default: the pane is loaded on demand (HIS-009 criterion 6), which the existing `load` pattern
   of the pane registry already does for other panes.
9. **Summary by region and gate-filtered version lists (HIS-013 criteria 3 and 6)** have logic in
   `packages/history/src/compare.ts` (`summarise`) and the gate in `CompareContext`. The pane has to
   offer only versions inside the gate; that is a UI check still to be written.

## Round 7 (HIS-009; lane V-HIS-001-016, 2026-11-14)

Status: proposed. The owner's decisions are not made here.

10. **Shape of the history port (HIS-009 criterion 1).** The port is `HistoryPort` in `packages/ui/src/core-api.ts`: `list(query)` returns the groups and named versions of one page with an opaque cursor, `choices()` gives the regions, fields and people the filters offer, and `resolveUsers` is the host's directory. The element adapts the document service's routes to it (not built here). Default: the spec's split, the service filters and groups (HIS-008), the pane only asks and shows.
11. **Command for the pane (HIS-009 criterion 1).** `view.history` is a built-in command with the feature `history`, and it is registered by `App.svelte` only when the port exists. Its capability is the parity row `version-history`, which the parity profile already names (13 §2). The generated `spec/parity/parity-profile.json` is stale until `pnpm --filter @docedit/ui generate` runs in the main session.
12. **Names of erased people (HIS-009 criterion 3, HIS-038).** An identifier the directory does not resolve is shown as "Unknown person". The pane does not tell an erased person from one the host does not list. Default: the same label for both, as the spec's wording asks for an unknown-person label.
13. **Named-versions reader (HIS-009 criterion 4).** The port says whether the reader sees named versions only (`namedOnly` in the result); the pane then shows the reason. The rule that decides it stays in the service (HIS-024).

## Round 5 (HIS-005, HIS-003, HIS-002; lane V-HIS-001-016, 2026-11-14)

Status: proposed. Nothing here is decided by the owner.

14. **A steps commit with no matching replayer is refused (HIS-005 criterion 5).** The replay worker
    holds one replayer (`pm-steps/1`, CDM 1). `ContentReader.rebuild`
    (`services/document-service/src/control-plane/content.ts`) now answers `internal`, naming the
    engine and CDM version, rather than replaying such a commit with the CDM 1 schema. The spec
    default (08 §3) is that the matching package is used; no second package exists yet, so the
    refusal is the narrowest reading. Owner or spec: choose whether an older engine gets a replayer
    (policy HIS-045) or a different answer such as `unavailable`.
15. **Where the per-session user agent family and client version are stored (HIS-003 criterion 3).**
    08 (`docs/spec/08-history.md`, line 39) requires the document service to store them per session,
    but does not name the table, the owning service (data plane or control plane), the retention, or
    the rule that turns a user agent string into a family. No code does it. Default: none until the
    owner chooses. The criterion stays unticked.
16. **The byte layout of the chain hash (HIS-002 criterion 2).** The three-implementation vectors
    (`services/document-service/test/data-plane/his-002-chain-vectors.test.ts`) pass, but the layout
    is written only in ADR 0020 (provisional). The spec default is to write it in 08 §2. That edit is in
    `docs/spec`, outside this lane; the main session makes it.
17. **Parity profile (round 5 review fix).** `spec/parity/parity-profile.json` is stale: the test
    `packages/ui/test/parity.test.ts` fails on the missing `view.history` / `version-history` entry
    (15 tests, 1 failed, 2026-11-14). `spec/` is generated and outside this lane. Main session:
    `pnpm --filter @docedit/ui generate`.
