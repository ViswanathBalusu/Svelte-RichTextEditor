# ADR 0307: Readings taken by lane U-FE-113-128

Status: proposed. Owner decisions are not taken here.

Date: 2026-11-13

## Context

Lane U-FE-113-128 closed blocked browser criteria in stories FE-113 to FE-128. Where a spec left a reading open, the lane took the reading below and recorded it here. The main session or the owner may change any of them.

## Readings

1. FE-126 criterion 1: "reports no new violation" is read as the FE-019 comparison. A named page state passes when axe reports no rule that the editing state does not already report, and no rule with more nodes than the editing state. A state with no baseline violation therefore fails on any violation at all. Source: `packages/element/e2e/fe-126-axe-states.spec.ts`.
2. FE-113 criterion 1: "a supported mobile browser" is read as Chromium and WebKit with the mobile emulation Playwright provides, at 390 by 844 CSS pixels. Touch scrolling and pinch-zoom use Chromium DevTools input gestures and so run in Chromium only. Source: `packages/element/e2e/fe-113-mobile-view.spec.ts`. A real phone is not used.
3. FE-116 criterion 4: "the editor uses `Selection.getComposedRanges()`" is read as the call count of the wrapped native method being above zero in WebKit. Chromium and Firefox are recorded, not asserted. Source: `packages/element/e2e/fe-116-composed-ranges.spec.ts`.

## Consequences

- The three readings are tests, not product behaviour. A change in the owner's reading means changing those specs.
- Criterion 2 of FE-113 (a touch device is served the web view) is not met in the product. The element does not call `selectView`; the `view` attribute has no behaviour yet (PRO-079). No decision is taken on how `view` should behave.

## Round 4 (2026-11-13), status: proposed

- FE-121 criterion 1 asks for the view layer as a separate package. The split is the main session's call (root configuration and package layout), not this lane's.
- FE-121 criterion 4 (the core tests on every change, before browser tests) is CI configuration at the root.
