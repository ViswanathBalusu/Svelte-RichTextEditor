# ADR 0333: Lane V-BE-015-028, unblock round 2 (stories BE-015 to BE-028)

**Status:** proposed, 2026-11-13. Owner: lane V-BE-015-028 (developer, round 2).

## Context

Round 2 asked the lane to close criteria that earlier lanes left open because they needed PostgreSQL,
object storage, a container or a browser. The lane started from the highest story number and worked
down. BE-028 stays blocked (BE-062 and BE-067 are not built). BE-022 criterion 5 stays open (the
in-process plane does not serve the REST content read that a reload needs).

## Decisions taken in this round

1. **BE-016 criterion 3 ("Given CI").** The criterion names CI. CI is root configuration and was not
   run. The test runs against the shared PostgreSQL container in Podman instead, and the Evidence says
   so. Proposed default: the criterion is met by a test on the real database; a CI job that runs it
   is a root-configuration change for the main session.
2. **"Previous release's schema".** Read as the migrations `migrations/releases.json` lists for
   `0.1.0-phase1a` (0001 to 0007), applied with the migrator's `only` option, then every migration.
   No release tag or dump of an older database exists, so this is the closest proxy. The schemas are
   compared by catalogue description (tables, columns, constraints, indexes, policies, functions by
   source hash, triggers, partitions), not by `pg_dump` text.
3. **BE-020 criterion 3, durable state only.** Read as two checks: the worker check (earlier lane) and
   a check that a checkpoint due after stored commit A is written from A alone while commit B is held
   in the log store. The room builds checkpoints from its stored-commit buffer (`#since`), so the test
   confirms that design rather than a new rule. Owner decision not taken: the order of checkpoint and
   snapshot writes (already recorded in the story Notes).

## Consequences

- Ticked: BE-016 criterion 3; BE-020 criterion 3 (both halves).
- Still open, with reasons in the story Notes: BE-016 criteria 1 and 5 (a running older release and
  release notes with rollback text); BE-022 criterion 5 (reload content over REST); BE-024 criterion 6
  and BE-021 criterion 4 (measurements on the reference machine); BE-027 criterion 3 (latency and
  memory of other channels, a measurement); BE-028 (blocked on BE-062 and BE-067).

## Round 3 (2026-11-13)

Round 3 asked the lane to take the highest untouched stories of BE-015 to BE-028. BE-015, BE-017,
BE-018, BE-025 and BE-026 were already fully ticked. BE-024 criterion 6 is a measurement (BE-058).
BE-028 stays blocked (BE-062 and BE-067 are not built).

### Decisions taken in this round

1. **BE-019 criterion 2: the node-identifier index is rebuilt on read, not mapped per commit.** The
   room builds `NodeIndex` (`packages/authority/src/room/node-index.ts`) in its constructor and
   rebuilds it in `Room.nodeIndex` when the durable head has moved. 07 §5.4 says that the permission
   indexes are carried by mapping, but 03 §9 and 06 §2.2 give no maintenance rule for node
   identifiers. Default: rebuild on read, which is correct and simple. Question for the owner: map
   the index through each commit once a reader needs it on every commit.
   Position maps (from the stored steps, back to `maxRebaseSteps`) and the region, definition, field
   and comment indexes were already built on open (`PermissionIndex.build`, the `maps` of
   `Room.record`, `mapThreads`); the new test checks them.

2. **BE-019 criterion 5 stays open: the open path runs on the main thread.** `CheckpointStore.load`
   decodes the envelope in process, `#load` in `room-host.ts` calls `nodeFromJSON` and `check()`, and
   the `Room` constructor replays the log with `applySteps`. Only reads and checkpoint writes use
   workers. Proposed default, not taken: move the decode of the checkpoint envelope to the existing
   `decode` task, and keep the parse and replay on the main thread until the owner decides whether a
   16 MiB open may be built from plain data in a worker.

3. **BE-022 criterion 5: the reload content is read in process with the client's identity.** The
   REST content route calls the same data-plane method (`readContent`, `control-plane/kit.ts`). The
   test calls that method, not HTTP, so the HTTP route itself is not exercised by this criterion.
   The test is `services/document-service/test/data-plane/be-022-rolling-restart.pg.test.ts`, run in
   PostgreSQL in Podman.

4. **BE-023 criterion 2 stays open.** A transient authority's timers and held memory are not
   observable through the public surface. `process.getActiveResourcesInfo()` can count timers, but
   no test handle reaches the transient room to prove that its memory is released. Proposed default:
   leave unticked until the room host exposes a test hook, or the owner accepts a weaker check.

### Consequences

- Ticked: BE-019 criterion 2 (`be-019-v-be-015-028-open-indexes.test.ts`, Node.js, 4 tests passed);
  BE-022 criterion 5 (`be-022-rolling-restart.pg.test.ts`, PostgreSQL in Podman, 1 test passed).
- Still open, with reasons in the story Notes: BE-019 criteria 4 and 5; BE-020 criteria 4 and 5
  (attribution side object and thinning, HIS-014 and HIS-029); BE-023 criterion 2; BE-024 criterion 6
  (BE-058); BE-028 (blocked).
