# ADR 0336: Lane V-BE-057-070 decisions (proposed)

Status: proposed. Owner decisions are not made here.

## Forwarding stream core (BE-062)

The spec (06 §2.1, §4.3) asks for a reliable ordered stream with gap detection between nodes. It
does not name the frames, the repair rules or the numbers. The lane chose the following, as a
proposal, in `services/document-service/src/control-plane/channel-forward.ts`:

- Frames carry a sequence number from 1. The receiver delivers each once, in order.
- A missing number is asked for with a `nack`. The sender resends it from a window of its last
  `retain` frames. A number the sender no longer keeps is answered with `gone`, which closes the
  channel with `unavailable` and a `retryInMs`.
- A number known only from the sender's `head` heartbeat is asked for after `repairMs`, because it
  may still be in flight. A number that a later frame overtook is asked for at once.
- After `maxNacks` requests for one number, the gap is unrepairable and the channel closes with
  `unavailable`.

Owner decisions needed:

1. The window size (`retain`), `repairMs`, `maxNacks` and the `retryInMs` a client is given. The code
   takes them as arguments and sets no default. The spec gives no figure. Each is a target to measure
   on the reference machine, not a number to invent.
2. The heartbeat rate for `head`. The code leaves the rate to the caller.
3. Whether a forwarded channel closes with `unavailable` on owner change (as built) or with a
   reason the client can tell apart. The spec (06 §2.1) says "closed and re-routed"; the re-route is
   the client's reconnect through BE-061, which is not built.

## Owner change (BE-062 criterion 4)

`ForwardedChannels.setOwner` removes and returns every forwarded channel of a document when its
owner differs from the one on record. The lane did not wire it to the connect route. Re-routing
happens when the client reconnects, and no route calls `routeDocument` yet (BE-061).

## Bus transport (BE-062 criterion 1, BE-059 criterion 3)

The stream takes an `out` function and does not name a transport. The bus choice (Redis or Valkey
streams, or NATS) is the open question "Which bus in stage 2" (06 §16, BE-059) and is the owner's. Until it is taken, no criterion
that needs packets between real nodes can be tested.

## Webhook test ping and replay routes (BE-057 criteria 3 and 4, round 4)

`WebhookDispatcher.ping` and `replay` are built and tested in `webhook-dispatcher.test.ts`, but no
route calls them. The spec names no path, method or body for either: `spec/dep/dep-1.gaps.json`
records that there are "no routes or bodies for event filters, secret rotation, the test ping or the
replay of deliveries", and the generated `spec/dep/dep-1.registry.json` lists only the five
`/webhooks` operations. A route here would invent its shape, so none was added. Proposed for the
owner or PRO to choose: two paths under `/webhooks/{id}` (a ping of one subscription, and a replay
of one delivery of it), the service credential only (as `/webhooks`), the status codes, and the
test event's type name (`dep.webhook.test.v1` is a placeholder in `webhook-dispatcher.ts`). Once the
spec names them, the handlers belong in `webhook-routes.ts` and the criteria can be ticked by a route
test over HTTP.

## Replica reads for history (BE-064 criterion 1, round 4)

Lists (`listDocuments`) and pinned content reads already go through the `ReadRouter` (`kit.ts`
`readAs`, used by `field-routes.ts` and `handlers.ts`). The Notes of BE-064 say that history reads
do not, and point to `history-routes.ts`; that module holds only fork and the read marker, so the
reference is stale. The reads the criterion names (`history`, `versions`, `diff`, `attribution`,
`activity`) live in other modules: `activity-route.ts` and `commit-routes.ts` read the primary through
`connectionOn` and `readerView`, and `versions-routes.ts` serves `/versions`. Routing them changes
the read semantics of those routes, so it was not done this round. The owner should confirm which
reads the criterion means (and whether `/versions` counts) before criterion 1 can be ticked.
