# ADR 0205: Decisions raised by lane FE-066-078

- Status: proposed (not accepted; the owner decides)
- Date: 2026-11-13
- Scope: stories FE-066 to FE-078 in `docs/stories/FE-frontend.md`

## Context

Two questions in this lane are open in the spec, and one spec rule is not yet applied in the layout code. This record gives the proposal for each. No code or story is changed on the strength of a proposal here, except where a story note says so.

## 1. Whether layout runs in a worker (FE-075, 02 §15)

02 §9.1 says the layout engine has no DOM dependency "so that it can run in a worker and in Node.js for tests". 02 §15 leaves open whether it runs in a worker from the start or is moved there later. The spec gives no default. Spike S5 (text measurement: canvas against HarfBuzz) has no recorded result in the repository, so where measurement runs cannot be decided from evidence here.

Options:

- A. Main thread first. The engine API (FE-076) stays plain data, so the same engine moves to a worker later without a change to its callers.
- B. Worker from the start. The measurement provider runs in the worker, with the font aliases registered there (FE-063) and `OffscreenCanvas` or HarfBuzz as the measurer.

Proposal: option A until a measured cost per animation frame exists for crossing the layout tree to the main thread (FE-075 criterion 3). Option B adds the font-alias and measurement work to the worker before any number shows it is needed. This is a proposal; the owner decides, and ADR 0005 is updated only when the owner accepts it (FE-075 criterion 4).

## 2. Gap between paragraphs (FE-077 criterion 3, 03 §7)

03 §7 says the gap between two consecutive paragraphs is the larger of the first one's `spaceAfter` and the second one's `spaceBefore`, and zero between paragraphs of one style with `contextualSpacing`. The code in `packages/layout/src/flow.ts` keeps both values, and `packages/layout/src/paginate.ts` adds them (`spaceBefore + spaceAfter`), so the layout uses the sum.

Proposal: in `toFlow`, after the contextual pass, set the first paragraph's `spaceAfter` to the larger value and the second paragraph's `spaceBefore` to zero. The pagination sum then equals the rule without a change to `paginate.ts`.

Why not applied now: the change moves the layout output of every consumer of `toFlow` (layout tests, `export-latex`, the perf package, and `ooxml.ts`, which writes `last.spaceAfter` into DOCX `w:after`). Those are other packages, and their expected values would change. The owner or the package owners should accept the change first.

## Consequences

- FE-075 stays unticked until the owner decides the question in section 1.
- FE-077 criterion 3 stays unticked until the change in section 2 is accepted and applied.
