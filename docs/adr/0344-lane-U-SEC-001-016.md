# 0344. Lane U-SEC-001-016: open questions and the defaults taken

**Status:** proposed (2026-11-13). Written by the developer of lane U-SEC-001-016, round 1. Not reviewed by the owner. Each default below is the spec's own position or the code's current behaviour; no owner decision is made here.

## Context

The lane closed criteria that earlier lanes left open because they needed PostgreSQL, a container or a browser. Round 1 covered SEC-014 (criterion 4, restart), and re-ran the PostgreSQL variants of SEC-013, SEC-015 and SEC-016 that were skipped when PostgreSQL was down.

## Open questions and the default taken

1. **`revoked` in `ch.open` (SEC-014, criterion 2, the `ch.open` clause).** The service answers a refused channel token with `ch.rejected` code `forbidden` (services/document-service/src/data-plane/session.ts, `#openChannel`, the `d.token` branch). The spec lists the codes of `ch.rejected` without `revoked` (docs/spec/05-protocol.md, row `ch.rejected`; packages/protocol/src/generated/types.ts, `ChannelRejected`). The criterion asks for `revoked`. Default taken: the spec's list stands, the service keeps `forbidden`, and the criterion stays unticked. The `it.fails` marker in tests/security/test/revocation.test.ts is unchanged. Question for the owner or the protocol maintainer: add `revoked` to the `ch.rejected` codes (a protocol change, so a DEP version question), or amend the criterion to `forbidden`.

2. **Service-minted tokens do not survive a restart (SEC-014, criterion 4, context).** The signing key of `POST /v1/tokens` is a new Ed25519 key that lives as long as the process (services/document-service/src/control-plane/tokens.ts, `signingKey`). After a restart every token it minted fails as `unauthenticated`. The refusal holds, so the criterion's wording ("still refused") is met, but it does not show the revocation. The lane's restart test therefore uses a host-signed token, whose key is in PostgreSQL. Default taken: none changed in the product. Question: should the signing key be configured and persisted (an operations decision), or should service-minted tokens be documented as session-bound to a process?

3. **Burst of copies on PostgreSQL (SEC-015, criterion 2).** On PostgreSQL the burst of 1000 copies of one commit identifier gets no acknowledgement before the test's check (`expect(acks.length).toBeGreaterThan(0)` fails in the PostgreSQL variant of test/replay-and-key-reuse.test.ts). The memory variant passes. Criterion 2 stays unticked. Default taken: no product change in this lane. The cause (the per-connection limit of SEC-018, or the commit latency of PostgreSQL inside the burst window) is not yet diagnosed.

## Round 2 (2026-11-13): decisions taken while closing SEC-006 and SEC-009

1. **Where the DOCX writer checks a link address (SEC-006 criterion 5).** Default taken: the writer applies the same allow-list as `link.href` (`LINK_HREF_PATTERN`, I9) to every external hyperlink. A refused address is written as plain text with a warning that names I9. The alternative, refusing the whole export, was not taken because the commit gate already refuses such addresses and a refused link should not lose the paragraph text. Question for the owner: is a text-only fallback acceptable for a refused link in a Word export, or should the export fail?

2. **Target and code of the version-collision `de-error` (SEC-009 criterion 3).** The spec says the collision is "reported through `de-error`" but not on which target, with which registry code, or whether it is fatal. Default taken: the page's global event target (`globalThis`, when it has `dispatchEvent`; none in Node.js); code `internal`, because the registry has no code for a version clash; `fatal: false`, because the first version keeps running and the host can register this one under another name. The `console.warn` is kept. Question for the owner: is `internal` acceptable, or should the registry gain a code such as `version_conflict` (a protocol change, so not made here)?

3. **Rendered link attributes (SEC-006 criterion 2).** The engine's link mark already sets `rel="noopener noreferrer"` and drops an `href` for a refused scheme (packages/engine/src/schema.ts). This lane proves it in Chromium, Firefox and WebKit on the rendered anchor. No `target` attribute is set; the criterion's wording is met by `rel`, and a same-tab link does not need `noopener`, so the rule stays in place as a guard. No change to the product code.

## Round 3 (2026-11-13): questions and defaults taken while closing SEC-007 and SEC-011

This section was first appended in round 3 and was lost from the file afterwards. It was written again by the round 3 fixer from the stories' Notes and the current code.

1. **The browser extension policy (SEC-011, criterion 1).** The spec takes a position: extensions that read or change editor content (grammar checkers, translators) run with the user's privileges and cannot be prevented, but their edits arrive as ordinary input and pass the same checks (docs/spec/10-security.md, section 6, first item). Default taken: that position, word for word, is the product's stated policy. What the product guarantees: an extension's edit becomes a transaction like any typed input, the schema keeps only valid content, and the server refuses a change that breaks a permission. It does not guarantee that an extension cannot read the content shown to the user. The default is proposed, not decided, so criterion 1 stays unticked until the owner accepts it. Criterion 2 is proved separately (packages/element/e2e/sec-011-extension.spec.ts). Criterion 3 stays unticked: there is no integration guide in this tree to carry the position. Question for the owner: accept the spec's position as the policy, or state a different one.

2. **The journal clause of SEC-007, criterion 1.** The criterion says "the journal rows hold commits only", and the spec puts the recovery journal in IndexedDB (docs/spec/10-security.md, threat row "Token theft"; 04-sync-engine.md, client state; 13, section 9). No code in packages/element/src writes a journal or any other browser storage yet (a search of that directory, 2026-11-13). The browser test scans localStorage, sessionStorage, IndexedDB, cookies and the visited addresses and finds no token, but an empty IndexedDB says nothing about journal rows. Default taken: criterion 1 stays unticked until the journal exists and the test reads its rows. Its transport is also the in-memory service of the demo page, not a DEP connection over the wire. Question: none for the owner; this waits on the recovery journal being built.

3. **`RTL_IDS` in packages/element/demo/embed-page.ts.** The lane's browser tests load the shared demo page, so the page must start without an error. The node identifiers of its right-to-left document (`RTL_IDS`, FE-111) are now each 16 characters (`pRtlOwn000000001`, `pRtlLtr000000001`, `pRtlInherit00001`), which matches `NODE_ID_PATTERN` (`^[A-Za-z0-9_-]{16}$`, packages/model/src/conventions/ids.ts). This is a change to a demo fixture only, not to product code. The earlier values are not recorded here, because the round 3 append that named them was lost.
