# ADR 0220: Kit publication order and read-restriction naming (lane PRO-127-131)

**Status:** proposed (2026-11-13). Not an owner decision.

## Context

Stories PRO-127 to PRO-131 cover publishing the conformance kit (PRO-127), the decision on a second
server (PRO-128), the freeze of protocol 1.0 (PRO-129), and the read-restriction parts of DEP and the
`perm-read` profile (PRO-130, PRO-131). Three points were left open by the spec and needed a stated
default before the kit's documentation could say what to do.

## Decisions proposed

1. **Order of profiles for an implementer.** 05 §11 says the kit grows with the roadmap and that the
   `core` scenarios come first. It does not order the other profiles. The kit's README
   (`packages/tck/README.md`) states the order `core`, then the mode profiles that need nothing else,
   then the feature profiles in the order of 05 §11, then the phase 2 profiles, then `authority-service`
   and `core-relay`. Spec default used: `core` first; the rest is a proposal.
2. **Feature name for read restrictions.** Left as the kit's proposal `read-restrictions`
   (ADR 0042 item 4) until PRO-130 names one. `perm-read` is documented as skipped until a server
   announces that name. No feature name is added to `packages/protocol` or to discovery in this lane.
   Owner or protocol decision needed.
3. **PRO-128 default.** Not decided here. The spec default is "scheduled when a partner wants to build
   one" (05 §11). The "not scheduled" record belongs to the review at the end of phase 4.

## Consequences

- The README test (`packages/tck/test/readme.test.ts`) checks that every profile of the kit is listed
  with its mode or features, and that the order starts with `core`. It does not prove that a reader
  can follow the document for an empty server.
- PRO-130 criterion 4 (feature announced in discovery) and criterion 5 (prose of 05) stay unticked.
- PRO-131 criteria 1 to 3 stay unticked: they need a server that announces read restrictions.
- PRO-127 criteria 1 and 3 stay unticked: a signed container image and release notes need a release
  process and a Podman build that this lane does not run.
