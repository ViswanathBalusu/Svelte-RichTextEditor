# ADR 0324: lane U-EXP-113-123 (round 3) decisions

Status: proposed. Owner decisions stay with the owner; this lane records what it changed and the spec defaults it used.

## Context

Round 3 of the export stories (EXP-113 to EXP-123) closes criteria that earlier rounds left open with a note that they needed a container, a browser or PostgreSQL. This lane found that sandboxed LuaLaTeX compiles did not run on this Windows host, so every compile test skipped, including those of EXP-111 and EXP-023.

## 1. The sandbox readiness probe (EXP-070, EXP-072)

Correction (round 3 fix, 2026-11-13). The first version of this section was wrong. It said that `sandbox.ts` mounts an empty tmpfs on `/run/secrets`, so the old probe (`if [ -e /run/secrets ]`) refused every sandbox. When the lane changed the probe, that overlay had already been withdrawn (ADR 0346, "Round 3 fix"), and the reviewer showed the old probe passing on the machine route (`secrets=absent`). The lane then weakened the probe to `ls -A /run/secrets` (empty means ok), which would also accept an empty directory from Podman's default mounts. The skips the lane saw were more likely the probe's slowness and flakiness on the loaded machine.

Since then lane V-EXP-033-048 added the overlay again (`--tmpfs=/run/secrets:ro` in `sandbox.ts`, ADR 0319), citing the weakened probe. With that line, the strict `[ -e ]` probe refuses every sandbox.

Change in the fix: the `/run/secrets` check moved to `services/export-worker/src/secrets-probe.ts` and is strict. It refuses a sandbox in which `/run/secrets` exists, with one exception: an empty, read-only tmpfs with root `/` in `/proc/self/mountinfo`, which only the job's own `--tmpfs` argument makes. Podman's default mount is a bind of a copied directory, so its root is that directory's path and it is refused even when empty. A second mount below `/run/secrets`, a writable tmpfs, a plain directory of the image, a separate `/var/run/secrets` and an unreadable answer are refused too. With the overlay absent this is the old strict check.

Evidence (Windows 11, Podman 6 WSL machine `podman-machine-default`, machine route, 2026-11-13; scratch probe through `runInSandbox` and `podmanCommand`):

- The job's own arguments: `/run/secrets` exists, holds nothing, and its mountinfo line is `819 814 0:113 / /run/secrets ro,nosuid,nodev,relatime - tmpfs tmpfs rw`.
- Control, the same arguments without the overlay and without the empty default mounts file: `/run/secrets` holds `rhsm`, and its line is a `tmpfs none` mount whose root is `/containers/storage/overlay-containers/<id>/userdata/run/secrets`.
- Both lines are fixtures of `services/export-worker/src/secrets-probe.test.ts` (8 tests, passed).

Readiness: a probe that does not start is run once more, and the readiness reason now names each route tried and its exit code or the entries found. On a remote client the machine route is tried first. Measured with a scratch script calling `sandboxReady()` on the same host: ok on the machine route in 143 s with no `DOCEDIT_PODMAN_MACHINE` set, and ok in 226 s with it set (the machine was shared with other lanes; one `podman run` took about 104 s). One earlier run of `sandbox.escape.test.ts` in the same hour still reported not ready after 122 s; the reason was not recorded.

Open, not decided here: whether the job keeps the overlay (ADR 0319) or drops it (ADR 0346). The EXP-072 escape case "mounts nothing from the host" in `sandbox.escape.test.ts` asks for no `/run/secrets` at all, and fails with the overlay in place (run 2026-11-13, `secrets=present`). The main session should settle it; this probe accepts either.

Status of the change: proposed. The gate is a security control (EXP-072); the main session should review the edits to `services/export-worker` (`sandbox-ready.ts`, `secrets-probe.ts`, `verapdf.ts`).

## 2. Stored reference PDFs (EXP-114)

Spec default used: a reference is the output of the converter's bundle compiled in the sandbox, with the options written to `packages/export-latex/test/references/manifest.json`. The first two references are the inline sample of EXP-111 and the S4 fixture `s4-01p`, both tagged, as PDF/UA-2 and PDF/A-4f. Which documents form the full mapping set of 09 §3 is not decided here; EXP-114 criterion 1 stays open.

## 3. Lane decisions not made

- Citation import (EXP-122 criterion 2) waits for citation documents in the SPK-028 corpus. No importer change was made.
- The Word and LibreOffice check (EXP-118 criterion 5) waits for a run on a machine with Word and LibreOffice.
- CI wiring for `exp-114-references.compile.test.ts` is root configuration and is left to the main session. The test now needs only Podman and the pinned veraPDF image (not the compile sandbox), and fails instead of skipping when `DOCEDIT_REQUIRE_SANDBOX=1` is set. A CI job would pull the veraPDF image and run `DOCEDIT_REQUIRE_SANDBOX=1 pnpm vitest run packages/export-latex/src/exp-114-references.compile.test.ts`.
- `services/export-worker/src/verapdf.ts` chose `--pids-limit=0` only when `DOCEDIT_PODMAN_MACHINE` was set, which the sandbox readiness check set as a side effect. Without that check, the validator failed on the remote client (`controller pids is not available`). It now retries once without the pids limit after that exact refusal and remembers it; the network, capability and privilege flags are unchanged.
