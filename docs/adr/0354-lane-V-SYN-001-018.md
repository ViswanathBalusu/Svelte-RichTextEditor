# ADR 0354: lane V-SYN-001-018, open questions decided by the spec default

**Status:** proposed (2026-11-13). Written by lane V-SYN-001-018 for the main session to review.

## Context

Lane V closes the criteria of SYN-001 to SYN-018 that earlier lanes left open. Two questions were
left open in the stories and are not owner decisions. This record states what the code now does and
which reading of the spec it follows.

## Decision 1: the code for a wrongly typed value (SYN-012 criterion 3)

Spec 12 section 4.2 P7 says that a wrongly typed value from a user with `fill` and not `edit` is
`field_invalid`, and that anything else is `permission_denied`. Criterion 3 of SYN-012 says that a
wrongly typed value (I15) is `invalid_op` for any other user.

Before this lane the room answered `field_invalid` for any value-only violation, whoever submitted it.

Applied here (spec default): `Room.submit` (`packages/authority/src/room/room.ts`, step 6) answers
`field_invalid` only when the connection holds `fill` and no `edit` in any scope (`fillOnly`), and
`invalid_op` otherwise. The invariant check in `packages/authority/src/invariants.ts` is unchanged.

Tests: `packages/authority/test/syn-012-p7-code.test.ts`.

FRW should confirm this reading.

## Decision 2 (left open, not decided): read_only or permission_denied for an owner in `sent`

Spec 07 P6 says that when a state or workflow limits a connection, step 1 refuses its commit with
`read_only` first. Spec 12 section 6 says that while a workflow is `sent` or `in_progress` the
authority accepts only commits that P7 and P8 allow.

The room gives a connection that holds `fill` (the owner, an editor with fill in the role) through
to the outcome check while the workflow is `sent` or `in_progress`, and that check refuses an
ordinary edit with `permission_denied`. A viewer gets `read_only`. The code is unchanged here.

Tests: `packages/authority/test/syn-007-workflow-lock.test.ts` (viewer case). The owner case is left
out of the tests because the code is not settled.

PRM and FRW to decide.

## Consequences

- `packages/authority/test/syn-012-i15-limits.test.ts` accepts either code for the 4 KiB value, so it
  still passes. Its comment, which says that the room answers `field_invalid`, is now out of date.
  That file belongs to lane U and was not edited.
