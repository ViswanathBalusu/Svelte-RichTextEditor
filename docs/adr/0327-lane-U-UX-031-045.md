# ADR 0327: decisions and measurements, lane U-UX-031-045

Status: proposed (lane U-UX-031-045, round 3, 2026-11-13). The owner has not accepted any part of this record.

## Part A: UX-031 criterion 5, the combobox role on the comment field

The comment box (`packages/ui/src/components/CommentBox.svelte`) is a multi-line `textarea`. It carries `aria-autocomplete`, `aria-controls` and `aria-activedescendant`, but not `role="combobox"`. The ARIA combobox pattern is written for a single-line text input. Putting the role on a multi-line field is not a pattern the ARIA specification defines.

A browser run now proves the keyboard half of the criterion: ArrowDown and ArrowUp move the active result, Enter chooses it, Escape closes the list and keeps the dialog, and the count is announced (`packages/ui/e2e/ux-031-mention-keyboard.spec.ts`, Chromium, Firefox and WebKit).

Open for the owner: whether a comment body may be multi-line. If it may not, the field can become a single-line input with the combobox role, and criterion 5 can be ticked as written. If it may, the picker needs another standard pattern, or the spec needs to name one. Until then criterion 5 stays unticked.

## Part B: UX-043 criterion 2, candidate dictionaries for the first locales

Measured 2026-11-13 with the npm registry (metadata by `npm view`, the package packed into a scratch folder with `npm pack`, the tarball unpacked to read the licence files). Method only; no build was made.

Candidate for en-GB: `dictionary-en-gb`, version 3.0.0, from the `wooorm/dictionaries` project.

- Declared licence in `package.json`: `(MIT AND BSD)`.
- The package's `license` file holds the BSD-style text of the SCOWL word list (a Princeton-based licence with a notice requirement) and the package wrapper is MIT.
- Size of the tarball: 203,045 bytes. Unpacked size: 575,855 bytes across 7 files, of which `index.dic` is 552,106 bytes.
- The licence check against Apache-2.0 is a reading, not a legal opinion. Both licences are permissive and need their notices kept. The owner or counsel should confirm the inclusion before any fallback ships.

The first locales are not set in the spec, so the candidate list is a proposal only. The project's interface strings are en-GB (`packages/ui/src/i18n/en-GB.ts`), which makes en-GB the proposed first locale. The owner decides the locales. No candidate is shipped and no fallback is built.

## Part C: UX-043 criterion 3, the cost of an on-demand fallback

Not estimated here. The estimate needs a built bundle with the fallback split into its own chunk, which does not exist. The compressed size in Part B is a data point, not the cost in the initial budget.

## Part D: UX-040 criterion 1, a refused export command does not open the dialog (round 12, lane U-UX-031-045, 2026-11-13)

Status: proposed. The owner has not accepted this part.

- Decision taken in code: document.export is disabled by the shell query shell.exportAllowed under 
o-export. The registry refuses to run a disabled command (UX-004), so the export dialog does not open for a person under the restriction. Its reason shows on the command.
- The spec does not say whether the dialog should still open to show the reason (UX-040 open question on the PDF preview and export). The spec default is applied here: the command is disabled with the reason and the dialog is not opened.
- Dialog behaviour under the restriction is still tested (packages/ui/e2e/ux-040-export-restrictions.spec.ts), by letting the restriction arrive while the dialog is open.
- Owner question: should a person under 
o-export see the export dialog with its targets disabled, rather than no dialog?
