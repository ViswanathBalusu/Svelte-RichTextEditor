# ADR 0329 (lane V-UX-061-075): decisions taken while closing blocked criteria

Status: proposed. For the owner and the spec owner to confirm. Dated 2026-11-13.

## Context

Lane V-UX-061-075 closes criteria that earlier lanes left open for want of a browser run. Where a
criterion needed a choice the spec does not make, the choice is recorded here, not decided silently.

## Decisions

1. **Target size of a radio or checkbox inside its label (UX-068, criterion 2).** The export dialog's
   radios and checkboxes are 15 by 15 CSS pixel inputs inside a `label.de-check` that is at least 24
   pixels high. The test measures the label, which takes the pointer, and reports the bare input in
   the story Notes. Alternative: enlarge the input itself to 24 by 24. Default taken: measure the
   label. Owner to confirm, because it changes whether criterion 2 can be ticked.

2. **Heap figure for the memory criterion (UX-074).** The method of the earlier lane is kept: the
   JavaScript heap used after two full collections, Chromium only, after warm-up. The longer run
   (120 cycles) is a measurement of growth, not a pass. Owner to confirm the method and the noise rule
   (spread of five back-to-back readings).

3. **Scope of the first-paint theme check (UX-061, criterion 6).** The check reads the shell's theme in
   the same synchronous task that mounts it. The host page's own background before the element script
   runs is not checked. Default taken: the shell's mount is the "first paint" the criterion means.

4. **Command search in the axe run (UX-068, criterion 1).** Included, since `CommandSearch.svelte`
   exists. Its results list is checked after a query.

5. **Typing latency method (UX-072).** The figure is the Event Timing duration of `keydown` entries at
   a 16 ms threshold (the API's minimum), with the page CPU-throttled four times, Chromium only. The API
   rounds to 8 ms and reports nothing under the threshold, so the median and 95th percentile are of the
   reported interactions, and the count of unreported keys is kept. The reference machine is not named
   in the story; the run is a stand-in and does not decide criterion 1. Owner to name the machine and the
   fixture (100 pages, five peers). Default taken: report figures, tick nothing.

6. **Caret placement when mirrored (UX-065, criterion 5).** The caret layer stays `dir="ltr"` and places
   carets from the core's physical coordinates; the test shows they keep their offsets from the text in
   `ar-XB`. Default taken: the core owns the coordinate system; the shell does not mirror it. Owner to
   confirm, since the core's logical-to-physical mapping for right-to-left text is not tested here.

## Round 3 (UX-066, UX-067): the checker pane

7. **The checker pane and its command (UX-066, UX-067; status: proposed).** The checker has a pane,
   `packages/ui/src/panes/CheckerPane.svelte`, loaded on demand through `src/shell/panes.ts` and offered when
   the core gives its document (`getContent`). It is opened by a `view.checker` command in the review
   group, with capability `accessibility-checker` (the profile's id), offered by `src/App.svelte` under the
   same condition. Default taken: the command is in the review group and the pane lists issues by kind.
   Owner to confirm placement and the capability name.
8. **Wording of the explanations and of the fixability marks.** The English sentences in
   `src/i18n/en-GB.ts` (`checker.*`) are the spec default for a short explanation with facts from the
   checker, and "You cannot fix this." is followed by the region's who-can-edit sentence when the access view
   names one. Owner to confirm the wording; translations are not made.
9. **Going to an issue.** The pane asks the core to select the issue's block (`selectBlock`). Whether the
   caret and the scroll follow is the core's, and not tested here. Owner to confirm that this is the way.
10. **Flaky axe policy report (WebKit).** One run of the axe test in WebKit failed once with a
    `style-src-elem` report of `body {}` (axe's own injected style, reported by the harness policy); the same
    test passed on rerun alone. Not investigated further; recorded for the next full run.

## Round 4 (UX-064, UX-070; 2026-11-14)

11. **Visual baselines for the mirrored shell (UX-064, criterion 7).** The baselines are Chromium on
    Windows 11 only (`ux-064-rtl-visual.spec.ts-snapshots`). Default taken: one platform until the
    reference machine is named; Firefox and WebKit need their own baselines. Owner to name the platforms.
12. **Initial-bundle check by a marker (UX-064, criterion 8).** The check looks for characters that only
    the pseudo-locale tables use, and for the base table's message `Bold`, in the scripts the page requests
    at start. It shows the pseudo table is absent; it does not measure bytes against the UX-070 budget
    (FND-008). Default taken: the marker check is the test for "only the base table"; a byte budget is FND-008's.
13. **Themes on demand (UX-070, criterion 4), not done.** The dark and high-contrast rules are in
    `src/styles/shell.css`, loaded at start. Loading them on demand would show an unstyled first paint for
    `auto` with a dark system setting, which the spec does not decide. Owner decision: keep the themes in
    the start CSS (current), or accept the first-paint cost. Nothing changed here.

## Consequences

- Tests added: packages/ui/e2e/ux-068-axe-states.spec.ts, packages/ui/e2e/ux-074-memory-levelling.spec.ts,
  packages/ui/e2e/ux-061-first-paint.spec.ts, packages/ui/e2e/ux-066-067-checker.spec.ts.
- Playwright runs use `--output` outside `packages/ui/test-results`, because concurrent runs in that folder
  delete one another's trace files.

## Round 5 (2026-11-14, lane V-UX-061-075)

Status: proposed. Stories UX-064 and UX-068.

1. **Target size of a radio or checkbox (UX-068, criterion 2), proposed.** The 15 by 15 CSS pixel input is
   measured through its `label.de-check`, which takes the pointer. Spec default taken: the label counts as the
   target. The spec owner decides whether the input alone must meet 24 by 24. Measured in
   `packages/ui/e2e/ux-068-target-size-panes.spec.ts`.
2. **Linux visual baselines (UX-064, criterion 7), done.** Recorded in a Playwright v1.65.0 container under
   Podman (`mcr.microsoft.com/playwright:v1.65.0-noble`, no published ports, the repository copied to a scratch
   folder and installed there). No macOS baseline exists; a macOS run still skips with its reason.
3. **Wiring the Playwright UI suite into CI, not decided.** The CI browser job runs only `vitest --project browser`.
   Adding the Playwright suite is a root `.github` change for the main session.

## Round 5 (UX-068, UX-074; 2026-11-14)

11. **Focus obscuring with no sticky element (UX-068, criterion 3; status: proposed).** The shell has no
    sticky, pinned or fixed header, toolbar or pane, so the criterion's condition ("given a sticky header")
    is not met. `packages/ui/e2e/ux-068-focus-not-obscured.spec.ts` walks every visible control with the full
    toolbar and one pane open and passes in three browsers, as a guard. Default taken: the criterion stays
    unticked, as the earlier round left it, because a condition that does not apply is not evidence. Owner
    to decide whether the criterion is vacuous for this shell (tick) or whether a sticky header is to be built.
12. **Heap figure and object diff (UX-074, criterion 2).** `packages/ui/e2e/ux-074-heap-diff.spec.ts` takes two
    heap snapshots (after warm-up, and after 60 cycles of the five panes) and diffs them by object group. The
    snapshots are written to the folder named by `DOCEDIT_HEAP_DIR`, not to the repository. Default taken: the
    diff is reported and criterion 2 stays unticked; the method of decision 2 is kept. Owner to confirm the
    method and the noise rule.
