# ADR 0307: lane V-FE-113-128, open questions and decisions (round 1)

Status: proposed. Date: 2026-11-13. Lane: V-FE-113-128.

## Context

The lane closes the stories FE-113 to FE-128 that earlier rounds left blocked, where a test can run
in the environment this machine has. Each question below was found while doing that. The spec default
is kept in each case, and the owner's decisions are not made here.

## Decisions and questions

1. **FE-128 criterion 7 ("produces `fmt` suggestions instead of marks").** The core, as built
   (`packages/engine/src/suggestion-edit.ts`, `suggestFormat`), applies the formatting and also adds a
   `fmt` mark that names the user and records the prior marks in `before`. A `bold` mark is therefore
   present on the text next to the `fmt` mark, which the wording "instead of marks" does not allow.
   Default kept: the design as built (03 §5, the rejection path restores `before`). Question for the
   owner or the spec: is the `bold` mark to be left out of the suggested run, or is the present design
   what "instead of marks" meant? The criterion stays unticked until this is answered. Test:
   `packages/engine/test/fe-128-format-suggest.test.ts`.

2. **FE-124 criterion 6 (loading starts once, in any order).** The FE-003 order tests in
   `packages/element/e2e/element.spec.ts` pass in Chromium and fail in Firefox and WebKit in this lane's
   run, and the FE-002 test times out on its outline-toolbar click in all three. The files belong to
   other lanes, so they were not changed here. The criterion stays unticked. The next step is a
   maintainer's look at both failures in the shared element spec.

3. **FE-124 criteria 1 and 3 (four framework hosts; server-side rendering).** No React, Angular, Vue or
   SvelteKit package is installed for the element. Adding them needs `scripts/pnpm-locked.ps1` installs,
   which were not run by this lane (needs the main session). Server-side rendering has no test.

4. **FE-125 criterion 1 (fonts, proofing, assistant port under strict policy).** The strict-policy
   suite (`packages/element/e2e/s2-features.spec.ts`) exercises the web view with typing, paste and the
   outline pane, but not the font registration, the proofing port or the assistant port in the element.
   The element source has no assistant port. Stays open.

5. **FE-128 criterion 3 (`lang` mark used by proofing).** The proofing request builder
   (`packages/ui/src/proofing/request.ts`) takes a block's `lang` mark as the tag it sends. No test
   shows the engine's mark reaching that builder in the element. Stays open.

## Round 3 (2026-11-13): the perf harness

Status: proposed. Stories touched: FE-119 (criterion 2 ticked), FE-120 (criterion 5 ticked).

6. **Trace setting of the reference project (FND-007 harness).** `packages/perf/playwright.config.ts`
   sets `use.trace: 'retain-on-failure'` for every project, and the reference project runs the
   harness on the same config. With a trace recording, Playwright's DOM snapshotter runs inside the
   measured page: in the first profile of `pages-300` it took about 60 per cent of the scrolling
   samples (`captureSnapshot`, `visitNode`). `packages/perf/e2e/fe-120-profile-300.harness.spec.ts`
   turns tracing off with `test.use({ trace: 'off' })`. Question for the FND-007 owner: were the
   recorded figures of `packages/perf/baseline/reference-1.json` (2026-11-06) taken with tracing on?
   If so, `harness.spec.ts` should be re-run with tracing off before any figure is compared. Default
   kept: the config is not changed here (it is not this lane's file).

7. **Backend commit path in the profile.** The in-page mock backend runs its commit path on the page's
   main thread in `deferred` mode. The profile uses `backend=hold` so that the editing path is what is
   sampled; the backend's share is then not in the profile. Question: is the typing budget (00 §9) meant
   to include the in-page backend? Default kept: it is scaffolding (the harness says so), so it is
   excluded.

8. **Chunk listing (FE-119 criterion 2).** The critical-path list matches chunk names by pattern
   (`pane`, `viewer`, `pdf`, `math`, `equation`, `print`, `read-view`, `outline`). The build hashes names,
   and the pattern holds for this build only. Default kept: the pattern is the check; a renamed lazy
   chunk needs the pattern updated, and the spec fails if the editor chunk is not in the list.

9. **Table and node-view attribution (FE-120 criterion 4).** The production build is minified, so the
   profile names ProseMirror's own functions and the element's functions only by minified name. No
   table-heavy document was profiled. Question: should the perf build keep function names, or should a
   source-map step attribute samples to modules? Default kept: no criterion ticked on this point.

## Round 4 (2026-11-14)

10. **FE-128 criterion 7 (suggest-only formatting produces fmt suggestions "instead of marks").** The
    test `packages/engine/test/fe-128-format-suggest.test.ts` passes (2 tests, Node.js with backend-mock,
    run this round). The design writes the `fmt` suggestion and also keeps the `bold` mark on the text,
    as 03 §5 describes. The criterion's wording says "instead of marks", which the design does not do.
    Question for the owner or the spec: is the wording or the design meant? Default kept: criterion 7
    stays unticked.
11. **FE-128 criterion 3 (proofing uses the `lang` mark).** The `lang` mark is applied with a BCP 47
    check (`packages/engine/test/formatting-values.test.ts`). Proofing does not run in the editor (no
    proofing port is wired, `packages/ui/src/proofing/request.ts` says so), so the criterion stays
    unticked.
12. **FE-119 criterion 4 (warm cache).** The reference perf server sends `Cache-Control: no-store`
    (`packages/perf/scripts/serve.ts`), so a warm reload has no HTTP cache hit. Question: what is the
    warm state, and should the reference server be cache-enabled for this figure? Default kept: the
    criterion stays unticked; the report with both loads is written by
    `packages/perf/e2e/fe-119-cache-states.harness.spec.ts`.
13. **FE-120 criterion 2 (navigation and comments panes on the 300-page document).** The perf harness
    page (`packages/perf/pages`) has no outline or comments pane, so the criterion cannot be measured on
    it. Question: which page should carry the panes for the budget report? Default kept: unticked.

## Round 7 (lane V-FE-113-128, 2026-11-14)

Status: proposed. Owner decisions stay with the owner.

11. **FE-122 criterion 3 ticked (two tabs on one real service).** New files: `tests/V-FE-113-128/fe-122-two-tabs.spec.ts`, `tests/V-FE-113-128/playwright.config.ts`, `packages/element/demo/pages/fe-122-two-tabs.html`. The spec starts `services/document-service` on PostgreSQL in its own database, and the element uses its own DEP client through `endpoint` and `getToken`. The service code is unchanged: the test allows the demo origin for its tenant (`addOrigin`) and routes the page's REST and `/dep` WebSocket to the service through Playwright. Chromium, Firefox and WebKit each passed once with no retry. Open question: the criterion says "two tabs with different grants". The test reads this as two grants (two tokens) with the same role, `editor`, for two users. A pair with different roles (for example `editor` and `suggester`) is not run. Default kept: the reading above. The owner should confirm which is meant; if it is the role pair, the criterion needs a second run with a suggester tab and a new expectation for its typing.

12. **FE-113, FE-114, FE-123, FE-125, FE-126, FE-128: no criterion ticked this round.** Each open criterion still needs something this lane cannot provide, as recorded in the stories:
    - FE-113 criterion 3: the scrolling and comments parts. The embed page has no comments entry, so the comments pane cannot be opened there (needs a page with the comments feature, a root or demo change).
    - FE-114: no code reads `window.visualViewport`, and no phone or on-screen keyboard run exists (needs a device, and an implementation).
    - FE-123 criteria 2 and 3: dead keys and the mobile keyboards are manual in every browser, and WebKit has no composition driver. A scripted manual pass recorded per browser and version needs a person.
    - FE-125 criterion 1: the proofing and assistant ports are not wired into a demo page, and fonts are not run under strict policy. Criterion 5 is CI configuration (root).
    - FE-126 criterion 1: needs a CI job that runs the element's Playwright specs (root configuration, `.github/`). Criteria 2 to 4 need screen-reader passes, which a person must run.
    - FE-128 criterion 3: proofing does not read the `lang` mark end to end (UX-041). Criterion 7: the wording question in item 1 above.

13. **Commands run.** `pnpm exec playwright test -c tests/V-FE-113-128/playwright.config.ts --project=chromium` (and `firefox`, `webkit`), with PostgreSQL from `infra/containers` up. The demo server builds to `packages/element/dist/runs/V-FE-113-128` on port 57078. No container was created and no shared container was changed; the test database was created and dropped by the spec.
