# ADR 0257: Lane SEC-040 to SEC-052 decisions (proposed)

Status: proposed (2026-11-13, lane SEC-040-052, round 1)

## Context

The lane ticked criteria in SEC-046 and SEC-050 and added a repository secret scan (SEC-048). Three choices were not in the spec and are recorded here instead of being decided silently.

## Decisions

1. **Engine identifier gate (SEC-050 criterion 4).** The definition and golden fixtures of `pm-steps/1` are hashed together, and the digest is recorded against the identifier in `tests/security/test/engine-identifier.test.ts`. A changed fixture under an existing identifier fails the test; a new identifier takes a new entry. This is the spec's default reading of 04 §4 ("a release that changes any fixture output is a new engine identifier"). The mechanism is a proposal: the owner may prefer the generator to write the digest.

2. **Signed URL lifetime (SEC-046 criterion 6).** The lifetime is the control plane's default of 300 seconds (`DOCEDIT_SIGNED_URL_SECONDS`), as stated in `services/asset-worker/README.md`. The spec leaves the lifetime open (SEC-046 Notes, 2026-11-06). Using the default is the spec default; the owner decides the final value.

3. **Secret scan scope (SEC-048 criterion 1).** The scan covers the working tree text files, with high-confidence token formats only. It is not a CI step. Wiring it into `.github` needs the main session. The patterns are a proposal; a finding is read by a person before an allowlist entry is added.

## Not decided here

- Pinning `packages/tck/Containerfile` by digest (SEC-052 criterion 4) needs the owner of `packages/tck`.
- The tenant filter for a deliberately unfiltered handler (SEC-045 criterion 3) needs the PostgreSQL run.

## Round 4 decisions (proposed, 2026-11-13)

4. **Purge job placement (SEC-044 criterion 5).** The purge job is a new file, `packages/authority/src/workflow/evidence-purge-job.ts`, that takes the store and the audit sink as interfaces and calls `planPurge`. Spec default: the purge job is the workflow service's (retention.ts header). The job is not scheduled and not wired into a service; the owner decides where it runs and the retention period (FRW-084 stays open, the caller passes it).

5. **Signed URLs across tenants (SEC-045 criterion 4).** The test uses the asset origin's verifier (`verifyAssetUrl`) as the verifier for tenant-moved URLs. Spec default: 10 §3.7 requires that a URL works for one object only. No verifier exists in the document service for `MemoryObjectStore.signedUrl`; that gap stays open, and the criterion's "full scenario" stays unticked.
