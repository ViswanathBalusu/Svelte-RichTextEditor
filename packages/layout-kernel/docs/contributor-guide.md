# The layout kernel: contributor guide

The kernel is a small Rust library, compiled to WebAssembly, that does the text work of the page view: it measures text, finds lines, hyphenates words, orders mixed-direction text (UAX #9), and (planned) segments text. This guide is for someone who changes it, or only runs it, and does not know Rust. The decision is [ADR 0016](../../../docs/adr/0016-rust-wasm-compute-kernels.md); the stories are in [docs/stories/WASM-rust-kernels.md](../../../docs/stories/WASM-rust-kernels.md).

## Where things are

| Path | What it is |
|---|---|
| `crates/` | The Rust workspace (own `Cargo.toml`, `Cargo.lock`, `rust-toolchain.toml`, `Containerfile`, `build.sh`). One crate: `crates/layout-kernel`. |
| `crates/layout-kernel/src/` | `lib.rs` (the calls the page can make), `faces.rs` (font files by alias and hash), `shaping.rs` (advances and the cache), `linebreak.rs` (first-fit lines), `hyphenate.rs` (TeX patterns), `bidi.rs` and `bidi_data.rs` (UAX #9; the data is generated by `scripts/bidi-data.ts`), `sha256.rs`. |
| `packages/layout-kernel/src/` | The typed wrapper (`createKernel`, `KernelShaper`, `ParagraphInput`, `ensureHyphenation`). Universal TypeScript: no browser and no Node.js API. |
| `packages/layout-kernel/node/` | The Node.js loader (`@docedit/layout-kernel/node`): starts the build from disk and loads manifest fonts by path and hash. |
| `packages/layout-kernel/dist/` | The build output (git-ignored): the generated ES module, the WebAssembly file, typings, `build.json`. |
| `packages/layout-kernel/patterns/` | Hyphenation pattern files, loaded on demand; not part of the WebAssembly file. |
| `packages/layout-kernel/golden/reference.json` | What Node.js recorded for the cross-browser suite (WASM-010, WASM-011). |
| `packages/element/src/features/layout-worker*.ts` | The worker that hosts the kernel in the browser (WASM-004). |

## Build

The build runs in a Podman image that holds the pinned toolchain (Rust 1.89.0, wasm-bindgen-cli 0.2.130, wasm-opt from binaryen version_133). You need Podman and nothing else: no Rust on your machine.

```
pnpm --filter @docedit/layout-kernel build:wasm       # writes packages/layout-kernel/dist
pnpm --filter @docedit/layout-kernel verify:reproducible   # two builds from scratch, same SHA-256
```

The first run builds the image. `DOCEDIT_CONTAINER_CLI` names another container command (default `podman`; never Docker in this repository). `DOCEDIT_KERNEL_NATIVE=1` runs `crates/build.sh` on a machine that has the pinned tools. Two builds of one commit are byte-identical; if `verify:reproducible` fails, something put a path or a time into the output.

Rules the build enforces: the project's crates forbid unsafe code; the dependency tree has no `-sys` crate (no system library); the direct dependencies are exact versions and every `cargo` call has `--locked`; `crates/Cargo.lock` is pinned by a hash in `licences/cargo-lock-review.json`, so changing a dependency is a reviewed change (run `node scripts/licence-gate.ts`).

## Test

```
pnpm --filter @docedit/layout-kernel test:native      # Rust tests, rustfmt, clippy -D warnings (in the image)
pnpm --filter @docedit/layout-kernel test:wasm        # build, then the package's Node.js tests
pnpm --filter @docedit/layout-kernel test:layout      # every suite that runs the kernel, in Node.js (below)
pnpm exec playwright test -c packages/layout-kernel/playwright.config.ts   # four browsers
```

- **Rust tests** (`cargo test`, in the image) check the rules in integers: the advance unit, the cache, the line breaker, the hyphenation algorithm.
- **Node.js tests** start the real build. `packages/layout-kernel/src/*.test.ts` test the calls; `packages/perf/test/wasm-006-*.test.ts` and `wasm-008-*.test.ts` compare the kernel with HarfBuzz and with the layout engine's own breaker over the shared corpus; `wasm-010-kernel-node.test.ts` locks `golden/reference.json`. Where `dist/` does not exist a test skips, unless `DOCEDIT_KERNEL_REQUIRED=1` is set, which turns the skip into a failure.
- **The browser suite** (`e2e/wasm-011-cross-browser.spec.ts`) serves the build, the wrapper and the fonts to Chromium, Edge, Firefox and WebKit and compares every advance and every line with the golden file. One unit of difference fails it. `DOCEDIT_BROWSERS=msedge` limits the projects.
- **Bidirectional text** is checked against the browsers: `e2e/wasm-015-bidi-browsers.spec.ts` orders 1,500 random strings in each base direction in Chromium, Edge and Firefox and compares with the kernel (WebKit: the two explicit directions, on strings without Arabic-Indic digits and isolate controls, where it differs from UAX #9). Rewrite `crates/layout-kernel/src/bidi_data.rs` with `node scripts/bidi-data.ts` (reads the Unicode data of a TeX Live Perl).
- **Hyphenation** is also checked against TeX: `test/hyphenation-reference.json` is what LuaLaTeX gives for 100 words in six languages. Rewrite it with `node scripts/hyphenation-reference.ts` (needs TeX Live on the path); rewrite `patterns/` with `node scripts/hyphenation-patterns.ts <hyph-utf8/patterns>`.
- **Updating the golden file** is a deliberate act: `DOCEDIT_UPDATE_GOLDEN=1 DOCEDIT_KERNEL_REQUIRED=1 pnpm exec vitest run --project node packages/perf/test/wasm-010-kernel-node.test.ts`, then `pnpm exec prettier --write packages/layout-kernel/golden/reference.json`. Say in the commit why the numbers moved (a font file, a Unicode update, a changed rule).

### Without a Rust toolchain

Everything above except `test:native` and `build:wasm` runs without Rust, from a `dist/` folder. If you have no `dist/` and no Podman, take the build from a package tarball (`pnpm --filter @docedit/layout-kernel pack` makes one on a machine that has built it) and unpack its `dist/` into `packages/layout-kernel/dist/`. `test:layout` then runs the layout engine and the kernel together:

```
pnpm --filter @docedit/layout-kernel test:layout
```

It runs the layout engine's suites (`packages/layout`), the kernel package's tests, the kernel's perf and corpus tests (`packages/perf/test`), and the element's worker and loader tests (`packages/element/test/wasm-*`). The kernel package is not published yet (`"private": true`); until it is, `dist/` comes from a build.

## Profile

What exists, and where:

- **Cost of a call in a page.** The worker records the time of each batch (`BatchStat`, `packages/element/src/features/layout-worker-host.ts`). `packages/element/e2e/wasm-006-kernel-measure.spec.ts` measures the cost of a keystroke (a paragraph posted, shaped and answered) in the four browsers and writes `test-results/evidence/`.
- **Start time.** `packages/perf/e2e/wasm-012-kernel-start.spec.ts` times compile and instantiate on the reference machine.
- **Size.** The library build reports the module under "webassembly" and `scripts/bundle-report.ts` holds it to the budget of WASM-012 (420,000 bytes of gzip). The module is stripped (`--strip-debug`, `--strip-producers`); no build with function names is defined yet, so a browser profiler shows the module's functions by number.
- **Memory and cache.** `kernel.memoryBytes()`, `kernel.faces.bytesHeld()` and `kernel.shaper.cacheStats()` (hits, misses, entries, code units held).

Measure before and after a change, on the same machine, and say how in the story's Evidence. Never write a number into the spec that you did not measure.

## The contract with the layout engine

The layout engine (`packages/layout`, TypeScript, FE's) calls the kernel only through the measurement interface of 02 §9.1; nothing else of the engine knows the kernel exists.

- **Units.** An advance is a whole number of 1/1280 pt (64 to the twentieth of a point): the font's value scaled to the size and rounded half up in integer arithmetic. The same in every runtime. Sizes are whole twentieths of a point.
- **Text.** UTF-16 code units. An inline atom is one unit (U+FFFC) and a bookmark none, so offsets equal the layout tree's (09 §7.1). The advance of a cluster is on its first unit; the other units of the cluster and the second half of a surrogate pair are 0; the units sum to the width of the run.
- **Fonts.** Only the files of the manifest, loaded under the alias `de-font-<sha256>`; the kernel refuses a file whose hash is not the manifest's. The kernel has no system font and reads no file.
- **Lines.** `breakParagraph` takes the text, the runs (face alias, size, language, features), the break opportunities, and the column. It gives, for each line, the start, the end, the x position, the width, the space to add to a justified line, and whether the line ends at a hyphen. The break opportunities (UAX #14) are an input today (WASM-007 would produce them); first fit is the engine's own rule, and the tests prove the two agree.
- **Bidirectional text.** `kernel.bidi.levels(text, dir)` and `kernel.bidi.visualRuns(text, dir, from, to)` (UAX #9). `dir` is `'ltr'`, `'rtl'` (the model's `dir`) or `'auto'` (the first strong character). The text is one paragraph; offsets are UTF-16 units of the block's text. A visual run is a range of logical offsets and a level, left to right; an odd level reads right to left. The line breaker does not use it yet: break first, then order each line. Complex scripts shape through HarfRust like any other text; `packages/perf/test/wasm-015-complex-scripts.test.ts` compares Arabic and Devanagari with HarfBuzz.
- **Hyphenation.** Off unless the paragraph asks (`hyphenate`) and the language's patterns were loaded (`ensureHyphenation`). A language without patterns is not hyphenated and nothing fails.
- **Versions.** `KERNEL_ABI_VERSION` (in `src/index.ts`) and `ABI_VERSION` (in `crates/layout-kernel/src/lib.rs`) change together when a call changes meaning or a call is added; `createKernel` refuses a build with another number, so a stale `dist/` never runs.
- **Errors** are codes (`unknown_face`, `bad_size`, `hash_mismatch`, `no_patterns`, and so on), thrown as `KernelShapeError`, `KernelFaceError` or `KernelHyphenError`. A trap ends the worker, is reported through `de-diagnostic`, and the next use starts a new one; the document lives in the editing core, so nothing is lost.

## Fallback rules

The editor must always edit, save and collaborate (PRODUCT.md, principles). The kernel is needed for the page view only.

1. A session that only uses the web view fetches and compiles no WebAssembly (WASM-002).
2. If loading fails (blocked by the host's policy, a failed fetch, a refused compile), the element raises `de-diagnostic` with `kind: 'load-failed'`, the `code`, and the missing `directive` (`script-src 'wasm-unsafe-eval'`), then `kind: 'degraded'` with the `fallback` it chose (WASM-003).
3. The fallback follows spike S5's record per browser: canvas measurement in Chromium, Edge and WebKit; the web view in Firefox, with a plain message that offers the web view and the read view.
4. Editing never waits for the kernel, and a failure of the kernel never loses an edit.
5. The host that sends a strict policy must allow `'wasm-unsafe-eval'` on the page and, if it sends a policy on the worker script, there as well (integration guide, "Layout kernel").

## What belongs in the kernel, and what does not

In the kernel, because they are pure functions of text and font files and must give the same numbers everywhere:

- shaping and measurement from the font files (HarfRust);
- segmentation: UAX #14 line-break opportunities and UAX #29 grapheme clusters (not built: WASM-007);
- first-fit line breaking in integers;
- hyphenation with TeX patterns;
- bidirectional ordering (UAX #9; WASM-015), built ahead of the plan that 02 §11 asks for, which does not exist yet;
- later: the line-breaking rules of East Asian and South-East Asian scripts (WASM-016).

In TypeScript, owned by the front end, and not to be moved into the kernel:

- pagination, the flow of blocks and floats over pages, footnote placement;
- the layout tree and its sharing with the painter and the PDF reconciliation;
- the painter and everything that touches the DOM, the canvas or a font stack;
- caret and selection geometry on the layout tree;
- the choice of what to measure and when (the font epoch, dirty ranges, incremental layout).

A change that moves a decision from one side to the other needs an ADR. TeX's own paragraph builder (Knuth and Plass) is not rebuilt (09 §7).

## Before you commit

1. `pnpm --filter @docedit/layout-kernel test:native` and `test:wasm` pass, and `verify:reproducible` if you changed the crate or the build.
2. The golden file is unchanged, or changed on purpose and explained.
3. `pnpm exec eslint`, `prettier --check` and `tsc` for the packages you touched.
4. The module is within the budget (`pnpm --filter @docedit/element build`; the report lists it).
5. A new Rust dependency is exact, `--locked`, passes `node scripts/licence-gate.ts`, and has a review in `licences/kernel-data.json` if it carries data. Ask first: a new dependency is the owner's decision.
