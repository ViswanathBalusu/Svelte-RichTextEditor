# Rules fixtures (kit copy)

A copy of the published rules fixtures of `rules/1` (FRW-020; 12 §5; ADR 0030). The source is
`spec/rules/`, generated by `packages/rules/scripts/generate.ts`. These files are copied by the
kit's generate script (`pnpm --filter @docedit/tck generate`, `packages/tck/scripts/rules-copy.ts`),
never edited by hand. The kit's test `packages/tck/test/rules-fixtures.test.ts` checks that they
equal a fresh copy byte for byte and that the manifest hashes match.

## Files

| File | Content |
|---|---|
| `rules-1.fixtures.json` | The cases, with the presets (`presets`) and the limits (`limits`). |
| `rules-1.manifest.json` | The rules version, the status, the profile and feature, the case count and the SHA-256 of each file. |
| `rules-1.schema.json` | The JSON Schema of the rules language. |

## Format of `rules-1.fixtures.json`

- `rules`: the rules version (`rules/1`). A change to the expected result of any case is a new version.
- `status`: `draft` until the owner reviews ADR 0030.
- `presets`: the preset patterns (`email`, `phone`, `postcode`) that a rule may name.
- `limits`: the bounds of the language (rule count, field count, value bytes, depth and so on).
- `cases`: one object per case, in publication order. Every case has:
  - `id`: unique within the file.
  - `category`: one of `operators`, `decimal`, `dates`, `patterns`, `rules`, `invalid`, `values`.
  - `kind`: `expression`, `rules`, `pattern` or `value`. It says which of the fields below apply.
  - `covers`: the operators, operands and effects the case exercises.
  - `tags` (optional): `null` for a null operand, `type` for a wrong-type operand, and others.
  - `given` (optional): `fields` (the field definitions), `values`, `roleDefs`, `roles` and `now`
    (an instant and a time zone).
  - `expect`: the expected result, compared as canonical JSON (RFC 8785). A problem list is compared
    as a set of `{ code, path, construct, keys }`. Messages are for people and are not compared.
  - the input by kind: `expression` (an expression), `rules` (a rule list), `pattern` (a pattern and an
    optional `input`), `value` (one value against the first field of `given`).

## Using the cases from another language

A native backend evaluates each case from its `given` and its input (`expression`, `rules`,
`pattern` or `value`), serialises its result in the shape of `expect`, and compares the two as
canonical JSON, with problem lists compared as sets. The kit does not yet ship a runner for another
language; the TypeScript runner is `runFixtures` in `packages/rules/src/conformance.ts`.

## Rules version

`rules-1.manifest.json` names the version. A new version may change any case. Under the same version
a changed expected result, or a removed case, is a defect: the rules package's generate script
refuses to write it (`changedUnderSameVersion` in `packages/rules/src/artifacts.ts`).
