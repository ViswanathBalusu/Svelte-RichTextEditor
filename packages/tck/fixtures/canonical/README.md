# Canonical-hash fixtures (kit copy)

A copy of the canonical-form fixtures of the CDM (03 §2; CDM-011). The source is
`packages/model/fixtures/canonical/`, generated by the model package's `generate`. The kit's copy
is written by its `generate` script (`pnpm --filter @docedit/tck generate`, through
`packages/tck/scripts/canonical-copy.ts`), byte for byte, and never edited by hand. The kit's test
`packages/tck/test/canonical-copy.test.ts` checks that the copy equals a fresh one and that every
SHA-256 in `index.json` matches the bytes of the file it names.

A backend in any language needs only a JSON parser and a SHA-256 function to run these cases.
`packages/model/conformance/canonical.py` is an independent implementation that does exactly that.

## Files

| File | Content |
|---|---|
| `index.json` | The cases, the canonical-form version and the rules they cover. |
| `inputs/<name>.json` | The input of a case: an envelope, or a node alone when `kind` is `node`. |
| `expected/<name>.jcs` | The exact canonical bytes: UTF-8, RFC 8785 text, no trailing newline. |

## Format of `index.json`

- `canonicalFormVersion`: the version of the canonical form these bytes belong to. A change to the
  bytes of any case is a new version (CDM-003).
- `rules`: the rule names the cases exercise, with a sentence each (default omission, mark order,
  text merging, `ext`, empty members, `requires` order, object-valued attributes, subtrees, bytes).
- `cases`: one object per case, in publication order. Every case has:
  - `name`: unique within the file; also the file stem of `inputs/` and `expected/`.
  - `kind`: `envelope` or `node`. A `node` case canonicalises a subtree alone (07 §11).
  - `rules`: the rule names the case covers.
  - `input`: the path of the input file, relative to this directory.
  - `inputSha256`: the SHA-256 of the input file's bytes.
  - `expected`: the path of the expected bytes, relative to this directory.
  - `sha256`: the SHA-256 of the expected bytes. Hash the bytes, not the text.
